# 既有流程沿用與差異驗證

適用：使用者已在自己的工作區成功發布，要求沿用既有技能；或維護者明確要求把私人行為一般化。不是自動同步機制，也不授權執行舊排程或發布腳本。

## 最短沿用流程

1. 只讀確認技能入口、實際載入的程式與呼叫來源，解析 symlink 但不建立連結。不要只看同名舊副本；不要執行可能寫入的 help、dry-run 或 verify，先查其實作。不要讀取憑證內容。
2. 在使用者指定範圍讀取既有結果，區分平台讀回證據、含 ID 的發布報告、僅請求回應，以及草稿／處理中／排程／已發布／未知。歷史 Agent 的「成功」敘述不是當前平台 GET。真實帳號、內容、ID、網址及紀錄留原私人位置。
3. AI 整理差異：帳號與資源選取、文案、媒體順序、憑證介面、主機、版本、操作格式、確認與重試規則。保持原本有效步驟；去掉固定品牌、時間、最新檔自動挑選、隱藏跨貼與自動排程。由已核准 plan 明確指定檔案及設定，不再讓使用者填一份問卷。
4. 只在現有可信工具能滿足交易契約時沿用。憑證改由作業系統安全儲存的可信介面取用；不能為相容舊工具匯出 token.json 或 .env。不能省略逐步 checkpoint、獨立讀回或預覽確認。舊程式只有「整批直接發布」而無停止位置時，不可外包給它繞過 begin；回報尚未適配，不臨時在正式發布中重寫整套程式。
5. 本機只測一般化差異：虛構目的地／素材、參數是否正確、秘密不進輸出、送出後中斷是否停止、重跑是否造成第二次發布。若要測腳本，必須能注入離線 transport 或確定沒有網路與憑證讀取；不能用真的帳號配上 dry-run 名稱假裝安全。
6. 未變動且有可靠實機證據的原流程可引用，不另造重複測試貼文。新憑證介面、API 版本、登入路徑、媒體格式或瀏覽器橋接屬於未驗證差異；第一次經授權的正常使用可以同時完成差異驗證，不必另發垃圾測試內容。使用者要求最後集中驗收時，現在只列差異，不啟動實機測試。

## 已挑選的可重用行為

以下是來源程式／紀錄支持的操作模式，不是本套件新增 HTTP driver 的宣告。平台端點與權限仍以各平台文件中的官方來源為準。

| 路徑 | 沿用部分 | 不帶入／仍有差異 |
| --- | --- | --- |
| YouTube | 最終影片與核准封面綁定；上傳影片後依序加縮圖、字幕、播放清單；以同一 video ID 查明與接續 | 不帶固定頻道、播放清單、分類、語言、每週排程、片長政策或私人憑證檔；附加步驟也需去重與讀回 |
| Facebook | 圖片先建立未公開素材，依明確 photo ID 與順序組成一篇貼文 | 未公開不等於未上傳；不默認兼作其他平台圖床，不把 photo ID 當 post ID |
| Instagram | 輪播逐張子容器、父容器、處理狀態、一次發布；Reels 分開核對影片與獨立封面 | 私人直傳程式曾運作不等於所有 IG 登入路徑通用；需核對版本、憑證及上傳協定，不默認要求 FB 圖床 |
| Threads | 每個容器與正式貼文 ID 分開保存；串文需逐則處理關係 | 首則帶圖、後續純文字是內容設計，不是平台絕對限制；目前交易未提供串文關係模型，不假裝已一般化完成 |
| Substack | 使用既有登入分頁與同一草稿；核對正文段落、連結、圖片實際保存，真正重新載入後再確認 | 不帶固定刊物、標籤數量、舊選擇器與 OpenCLI 內部模組路徑；影片／Podcast 保留來源證據但不冒充目前 article 交易已支援 |

## 排除的舊做法

- 找不到檔案就選最新檔、從共用目錄拿所有圖片；改為已核准的明確檔案清單與雜湊。
- 一次指令偷偷連發其他平台、額外留言、上傳素材主機、刪舊素材或建立排程；這些都不是單平台發文的隱含授權。
- Instagram 憑證當 Threads 備援、私人 .env／token.json、自動讀其他 Agent 的秘密；不一般化。
- 送出後看到錯誤便再按一次 Send、切換介面重發、只有 ID 就回報完成；保留未知並唯讀查明。
- 已失效素材主機、固定舊 Graph 版本、固定電腦安裝位置、依內部模組或非公開 API 卻稱為官方支援；不搬入套件。

## 驗收用語

分別回報「來源曾實機完成」「來源只有發布報告」「通用文件已整理」「一般化程式已離線驗證」「新環境已實機驗證」。這些不是同一件事。沒有新 driver 就明說，不以文件沿用掩蓋未實作；沒有新實機證據也不抹去來源已有的成功紀錄。
