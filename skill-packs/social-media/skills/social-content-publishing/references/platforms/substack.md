# Substack 文章發布 adapter

查證：2026-09-06，Substack 官方說明。尚未進入真實刊物、建立草稿或寄信。

## 實際執行來源

主要路徑明確選為 Agent 操作已核准的 OpenCLI 受控 Chrome，依本文件進入官方 Dashboard；OpenCLI 固定來源與安裝狀態由 setup 管理，不是 Substack 官方工具。`publish_job.py` 的 begin 必須先完成，`publish_execute.py prepare-browser` 產生綁定預覽與確認的本機 handoff；Agent 核對登入者與刊物後、第一次遠端編輯前執行 `claim-browser`，操作後真正重載，再以 `record-observation` 形成 receipt。瀏覽器登入由使用者處理，平台畫面是真實執行來源。OpenCLI 未安裝、Bridge 未連線、帳號不符或頁面不能可靠讀回時，改 manual，不改用內部 HTTP endpoint。

## 能力與預覽

官方 MCP 有資格條件且為唯讀，不能發布文章、發 Notes 或修改帳號；API Terms 的存在也不證明任何內部端點是公開發布 API。[官方 AI Assistant 說明](https://support.substack.com/hc/en-us/articles/50834026608916-How-to-connect-Substack-to-your-AI-Assistant)

本 MVP 以文章 article 為範圍。先評估正式 API／官方連接器，但未取得當前明確寫入文件就不使用；可靠 CLI 必須驗證實際版本、文章發布／讀回能力與其非官方性質。OpenCLI 作者的 GitHub 不等於 Substack 官方授權；不猜內部 POST，不下載未知套件。

settings 必須明示：刊物名稱與網址、標題／副標、封面與內文圖片順序、完整內文、付費或免費受眾、付費預覽分界、留言對象、標籤、是否寄送 email／App inbox、立即或原生排程（時區）。文章上網與寄信是不同影響，使用者只說發布不能默認同意寄送。若平台預設開啟寄信，要在預覽中清楚提出並取得確認；預覽選 web-only 就取消寄送選項。[官方文章發布與寄送選項](https://support.substack.com/hc/en-us/articles/360037831771-How-do-I-publish-a-new-post-on-Substack)

## 受控瀏覽器執行

1. 共同確認及 begin 後，用使用者授權給 Agent 的瀏覽器核對登入者與 publication；登入／安全驗證交人，不操作其他私人日常瀏覽器。
2. Dashboard → Create → Article，填入最終標題與全文；依序放入圖片，檢查段落、連結、替代文字與封面。編輯器自動保存是遠端寫入，所以不能在同意前先建「無害草稿」。記錄可以安全取得的 draft／post ID，不保存具存取能力的秘密草稿分享連結。
3. Continue 後核對受眾、付費分界、留言、標籤、email／App inbox、時間，與核准預覽逐項比較。若平台預覽與本機不同就先修正在原授權範圍內的格式；改文字、對象、寄送或費用須新確認。
4. 只對當前項目送出一次 Publish 或平台 Schedule。若畫面停住、切頁或逾時，先保留狀態去唯讀查明，不按第二次。原生排程不是由 Agent 建背景服務。

## 沿用既有瀏覽器流程的保存檢查

以下來自既有流程的實作與本機驗證紀錄，不是 Substack 對特定 DOM、OpenCLI 私有模組或內部端點的正式保證。沿用當前可用的受控瀏覽器工具，不複製維護者安裝位置或舊選擇器。

- 同一交易保存分頁與草稿識別；中斷後先讀同一草稿，不重新 Create。檔案雜湊、正文與草稿不符時停，不清空編輯器重貼。
- 貼入 HTML 後核對真正段落層級、完整文字、連結目的地、圖片數量與順序。不能只看貼上事件成功或粗略字數。比較連結前還原 HTML entity，例如 &amp; 與 &；不要用網址前綴相同判定連結相同。
- 圖片必須已保存、可解碼且尺寸非零；只有 blob 預覽不算保存。橋接上傳出現零位元／零尺寸時，先確認遠端狀態，不能直接重送。只有明確未成功且仍在核准範圍，才選當前工具支援的原生選檔替代；不能將某台電腦曾遇到的檔案大小問題當平台限制。
- 標籤透過真正輸入與選項選取，再查標籤成品；修改 input.value 不代表 React 編輯器保存。建立新標籤也須在預覽範圍內，不套用固定標籤數上限。
- 等待 Saved 後執行真正的重新載入。可用新文件載入指標（例如 performance.timeOrigin）輔助確認，再核對同一草稿與保存內容；只 goto 相同網址、重讀舊 DOM 或看到同一個畫面都不夠。查明失敗就停，不依舊腳本自動再按 Send。

## 讀回

真正重新載入 Dashboard 的已發布／排程列表，再打開該篇文章與設定，核對完整內容、媒體、受眾、寄送選項及時間。從可觀察的管理介面取得平台識別、正式 URL 與平台發布／預定時刻；不能把 slug 冒充不曾讀到的內部 ID，亦不能從網址猜出已發布。自訂網域要與預覽刊物一致。

寄送狀態、文章上線、排程成立分開記錄於 evidence；平台顯示已寄出也不代表所有收件匣均收到。無法確認任一必要欄位時 receipt=pending，保留已查證的部分，不重發或重建文章。RSS 可以輔助發現公開文章，不能證明 email 投遞、付費內容、精確排程或所有平台 ID。匯入／匯出是資料移轉，不是單篇發布 API。

找不到可靠操作介面時交付全文、媒體、選項預覽與人工步驟，標 manual_handoff；使用者手動完成後仍依同一標準讀回，不能把交付稿件說成已發。Notes、影片／Podcast 與外部平台自動交叉發布不在本文 MVP；不要因上傳影片就順便啟用其他平台同步。
