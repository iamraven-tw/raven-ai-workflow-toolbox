# 四種製圖路徑與一次設定

## 設定來源與優先順序

讀使用者已指定的私人 social-media/config.json 的 image_production；不掃描其他工作區、不讀憑證。欄位：

| 欄位 | 值與用途 |
|---|---|
| default_method | codex、antigravity、web、html_css；公開空白範本為 not_configured |
| information_dense_method | html_css：大量資訊、比較表、步驟圖、簡報型圖卡自動採 HTML＋CSS；inherit：沿用預設方式 |
| web_provider | 可為 null；只保存使用者指定的服務／模型名稱，不保存登入資料、Cookie、私人生成連結或憑證 |
| icon_source | heroicons：可選免費開源 SVG；none：不使用第三方圖示 |

本次明確指定方式 → 已保存的資訊密集內容偏好（適用時）→ 已保存的預設方式。不能只因有兩行中文字就把一般封面判成資訊密集。當次改用別種方式不修改長期設定；只有使用者要求「以後都這樣」才交 setup 預覽／確認寫入。

初始化時由 social-media-setup 一次整理選擇與資訊密集偏好，併入一般設定預覽。已設定後不再問用哪家模型，也不反覆問是否開始。舊 schema 3／尚未設定時不暗中遷移；若本次已有指定方式就直接採用，不阻擋製圖。否則只問一次「平常要用 Codex、Antigravity、網頁模型，還是 HTML＋CSS 製圖？」並交 setup 保存。本技能不直接寫一般設定。

可用 scripts/image_routing.py --config <config.json> 判斷，資訊密集時加 --information-dense；使用者本次明確指定方式才加 --method。--browser-requested 只能對應當次真正要求代操作的證據，不能因設定或 Agent 自己判斷方便而加上。腳本不執行任何工具，也不證明授權／模型可用。

四條路徑同時讀取 schema 5 的 brand_visual；優先序與素材權限依 [規格與檢查](production-and-review.md)。image_routing.py 輸出 visual.values、sources 與 missing，讓 Agent 把同一份色票與字型帶入生圖提示詞或 CSS。本次覆寫只影響簡報，不回寫設定；沒有品牌就保留缺口，不套用維護者配色。

## Codex／Antigravity：收到需求就製作

依設定選定客戶端的實際生圖工具及其適用技能。需求明確、工具可用且在既有授權範圍，就直接開始生圖，不再交一份提示詞請人貼上，不增加「可以開始嗎」關卡，也不先要求核准同一份構圖。繁體中文及精確版面可直接交模型處理。

Codex 路徑使用當前 Codex 環境提供的生圖工具；Antigravity 路徑使用當前 Antigravity 環境提供的生圖工具。這是執行環境分流，不宣稱兩個客戶端共用 API 或模型。找不到指定工具時清楚回報並保留需求；不能在 Codex 假裝已呼叫 Antigravity、偷偷換模型、另開 API 付費或自動操作外部網站。模型名稱與支援規格以執行時實際工具為準，不由偏好保證。

生成前可用一句進度告知所用方式與張數，不需等待回覆。已涵蓋的正常用量不用每張重問；新增購買、超出既定預算、額外私人素材上傳、登入／條款仍是必要關卡。成品預覽與最終確認保留。

## 網頁模型：預設給提示詞，人類貼上

輸出 prompt-package.md：完整可直接貼上的提示詞、平台用途、尺寸／比例、精確圖上文字、逐頁順序、視覺一致性、必要參考圖與最小操作提醒。每張各給一份完整提示詞；共同規則也要包含，避免貼單張時遺漏。用「請把生成的圖片傳回來，我會接著檢查」結束。不要只丟幾個抽象關鍵詞或要求使用者自己改寫。

保存狀態 awaiting_user_images，不能建立假 assets 或 approved manifest；提示詞交付不是圖片完成。使用者回傳圖片後核對張數、實際內容與來源，接回主流程檢查／成品確認，不重啟初始化、不重問製圖偏好。

使用者當次明確說「幫我操作瀏覽器」時，才使用其環境允許的受控瀏覽器；沿用已登入的正確帳號，填入同一提示詞與已授權素材、執行原範圍生成，讀回結果並保存。遵守使用者瀏覽器分工，不從公開包預設私人瀏覽器設定。登入、安全驗證、條款或新增費用才交人處理。不得購買點數、公開分享、發布到社群或大量追加生成。結果不明時停止，不重按生成。

此要求只適用當次任務，不將 browser_requested 保存成長期免確認權限；下次網頁路徑仍預設提示詞交付。

## HTML＋CSS：正式資訊圖卡路徑

按 [HTML＋CSS 與 SVG 圖示流程](html-css.md) 建立可編輯原稿並輸出 PNG。這是主動選擇的第四路徑，不只是沒有 AI 權限時的退路。使用者指定或設定判為資訊密集時直接開始排版，不再問模型。既有 Pillow 純文字 PNG helper 保留為另選的簡單備援，不代替 HTML＋CSS 的版面能力。
