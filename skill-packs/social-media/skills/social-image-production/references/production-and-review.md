# 製作規格與人工檢查

## 製作簡報

先讀私人 social-media/config.json 的 brand_visual（schema 5；舊版缺少不自動遷移）。本次明確設計指示優先於已確認品牌設定，剩餘缺口才使用暫時提案；記錄使用／覆寫的主色、輔色、背景色、文字色、字型、風格與素材參考。未確認推測不當成品牌規範。Codex、Antigravity、網頁提示詞與 HTML＋CSS 都用同一份視覺簡報，HTML 以 CSS 變數固定色票。圖示也要一致，但可讀性問題應提出調整，不暗改保存值。品牌素材只讀指定檔案，拒絕跳出已授權資料夾的 symlink；使用者沒有授權上傳時不能交給遠端模型。

每個成品包只對應一個平台用途與一組版本。不同裁切比例另存成品包，不以同一成圖自動代替全部平台。簡報由 Agent 整理：目的／受眾、入口及核准證據、平台／用途、畫布像素與比例、每頁精確文字、視覺方向、來源與權利、替代文字、工具與輸出位置。來源只定向讀取；不能為找參考遍讀私人工作區。

輪播每頁一個主要訊息，封面交代主題，中間依論點排序，最後呈現已核准 CTA（若有）。張數依內容和使用者需求，不固定十張；使用同一色彩、字級層次與留白，避免每頁無關風格。外部作品僅作參考，不將他人完整版面、標誌或內容換字冒充原創；不因 AI 生成就宣稱權利毫無風險。

## 尺寸與平台限制分開

1080 × 1080 方形圖卡、1080 × 1350 直式圖卡可作「編輯起點」，不是五平台官方通用上限。Facebook／Instagram／Threads／Substack 要依這次實際用途與發布介面查官方文件；未查證欄位寫 unknown，不把 PNG 可開啟當 API 一定接受。圖片製作不建立五個發布 adapter。

2026-09-05 查閱 [YouTube 縮圖官方說明](https://support.google.com/youtube/answer/72431?hl=en)：長影片建議 3840 × 2160、16:9；Shorts 建議 2160 × 3840、9:16。官方也區分桌面及行動上傳容量。這是該頁的 UI 路徑資訊，不能推定 Data API 使用相同容量或支援所有縮圖功能。實際任務需再確認，模型不能輸出該尺寸時記錄實際值與差異，另確認輸出處理，不承諾模型原生像素。

簡報的 width／height 是這份交付預期像素，不是官方保證；checker 只比對簡報與檔案。MVP helper 只檢查單張靜態 RGB／RGBA／L PNG 或 JPEG，其他格式先保留並另行處理，不能改副檔名冒充轉檔。

## AI 生圖與改圖

- 依已保存的 Codex／Antigravity 偏好使用對應工具，並讀其技能指示；不得偷偷切換另一家服務。網頁模型依 generation-methods.md 預設交提示詞，不自動操作。工具規格、模型名或價格以實際可用環境為準。記錄工具、可取得的模型版本、執行時間、提示詞、使用者已授權素材、輸出及修改關係；付費不明且需要新授權時先停。
- 提示詞包含 exact_text 的原文、逐頁目的、版面與風格；不要讓模型自行補統計、引用、網址或產品承諾。新文字或語意改動回交文案確認，不以製圖潤飾之名繞過。
- 改圖先實際查看目標與參考，依工具要求傳入正確圖片；只改指定範圍。工具已回傳成品就先檢查，不為取得更漂亮版本無限追加費用。
- 生成過程與輸出的 metadata 可能含私人路徑／提示詞；全部留私人工作區。交發布前檢查是否含不宜公開的資訊；清除 metadata 也要記錄新檔與雜湊，不改已核准版本。

## 視覺驗收與交接

先看原尺寸，再看手機大小預覽；每張逐字對照原文，留意異體字、簡體字、同形字、標點、數字與日期。中文字型缺字常仍會輸出方框，程式成功不能取代看圖。檢查高對比、邊界、人物特徵、來源標註、圖表誤導，以及輪播頁序與 CTA。替代文字描述實際畫面，不只複製提示詞、不塞搜尋關鍵字。

在 manifest 的 visual_review 記錄 checked=true、本次 review_ref 與時間；不確定就寫 unresolved，不能交接。Agent 的視覺檢查不等於使用者確認。使用者看過目前整組圖後記錄 approval；雜湊只防內容變更，不證明本人同意。交接包括所有圖片、順序、alt_text、來源／權利、實際格式／尺寸／bytes／SHA-256、檢查與確認證據。發布授權永遠另取。
