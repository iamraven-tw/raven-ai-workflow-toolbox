# 監控與事件處理

## 健康檢查

`manage_operations.py check` 對設定的公開頁面執行 GET，檢查狀態碼、必要文字、最終網址、回應時間與 TLS 憑證剩餘天數。它不登入、不送出表單、不建立預約，也不開啟付款交易。未加 `--record --confirm-write` 時只讀取，不留下紀錄。

建議預設檢查首頁、`robots.txt` 與 `sitemap-index.xml`。若網站刻意沒有 sitemap，應修改候選設定，而不是忽略持續失敗。正式監控只接受 HTTPS；`localhost` 與 `127.0.0.1` 的 HTTP 僅供隔離測試。

使用者明確要求定期監控後，先預覽頻率、檢查網址、寫入的本機歷史位置與通知條件，再用目前用戶端的排程／heartbeat 功能建立。排程授權可涵蓋後續每次健康 GET 與本機紀錄，但不涵蓋部署、DNS 變更或第三方服務寫入。狀態不變時保持安靜，只在失敗、恢復、TLS 即將到期或需要人處理時通知。

## 事件分級與停止條件

- 單一路徑失敗：再讀一次 DNS／HTTPS 與該路徑，排除短暫網路錯誤；結果不明時不得連續重送。
- 全站失敗：讀取最近一次成功紀錄與最後部署資訊，先判斷是來源、部署、網域或 TLS 問題。
- 內容錯誤但 HTTP 正常：比較本機建置與公開讀回，未授權前不重新部署。
- 表單、電子報、預約或付款異常：只檢查公開入口與服務狀態；端到端寫入另交 `website-service-integration` 取得授權。
- 若要讓舊版恢復上線，先預覽 Cloudflare 版本／部署與影響範圍，再取得獨立回復授權。`wrangler rollback` 會立即改變所有路由上的有效版本，不能從「請幫我看看」推定。

修復後必須重新執行健康檢查並從正式網址讀回；命令成功或後台顯示部署完成都不是公開網站已恢復的充分證據。
