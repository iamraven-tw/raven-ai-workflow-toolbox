# 官網文案

完整建站先讀 [技能接續契約](../website-setup/references/workflow-handoff.md)。Agent 先寫，使用者確認商業事實、承諾與方向；不逐句要求人類代寫。單獨修改只處理指定內容，完整建站自動接續設計與建置。

## 輸入與事實邊界

讀取正式或候選 `website/config.json`、既有 `copy.json` 與使用者指定素材。依 [寫作規則](references/writing-rules.md) 撰寫，欄位結構見 [文案契約](references/copy-contract.md)。不讀憑證、Cookie 或環境秘密。
只有設定或使用者提供的事實可寫成數字、客戶、經歷、價格與承諾；缺項集中補問或使用不作承諾的中性文字。不把模型推論標成 `user_fact`。

## 執行流程

單獨啟動時先用 Mermaid 呈現步驟與批次確認；完整建站沿用既有流程圖。

1. 用 `content_writer.py draft --config <候選或正式設定> --out <候選文案>` 建立骨架。只為已選頁面填文案；`guide` 是 Agent 自查欄位用途的工具，不是給人填的問卷。
2. Agent 完成所需文字。原始事實標 `user_fact`，Agent 組織的句子標 `ai_suggestion`；保留來源標記不代表永遠未定稿。
3. 部落格未選就略過文章。需要文章時依 [文章格式](references/user-posts.md) 沿用素材，或在使用者要求的範圍內產稿。不得加入虛構客戶案例，無文章不阻擋網站完成。
4. 先以 `status=final` 驗證候選，處理 blocking，再執行 `preview`。與頁面／設計推薦一起批次呈現完整文案、事實來源及需確認的商業承諾；使用者可直接採用，不要求親自改寫。
5. 同一批次確認涵蓋文案寫入時，使用原候選及 `--expected-preview-sha256`、`--confirm-write` 執行 apply；不再追加一次相同確認。修改了實質內容才重做預覽。
6. 尚未建站就自動交給 `website-build` 套用；已建站則 `sync` 後自動建置、檢查、截圖與記錄。這些已核准的本機動作不逐項詢問；部署仍需對應授權。

## 寫入與停止邊界

只寫使用者工作區的 `website/copy.json`、需求內的 `website/posts/` 與網站專案的 `site.copy.mjs`／文章。商業設定變動由 Agent 接續 website-setup 處理，不要求人類換技能。
未驗證的事實、來源漂移、錯誤雜湊、未知目標或工具驗證失敗時停止並保留資料。命令旗標不是對話核准；未核准候選不得覆寫正式內容。不得寫入技能來源或外部服務。

## 執行錯誤最小回填

實際執行出錯，或可觀察行為與本技能規則衝突時，原任務優先：

1. 先保存使用者已確認的文案。
2. 若 `references/troubleshooting.md` 已存在，只讀與目前症狀相關的段落；不存在時不要先建立空檔。
3. 只有能證明錯誤來自本技能、修正限於同一個由使用者管理的技能來源、不新增依賴或外部授權，且重跑原失敗步驟通過時，才立即回填：流程更新本 `SKILL.md`，欄位指南更新 `assets/field-guide.json`，寫作規則更新 `references/writing-rules.md`，特定環境才建立或更新 `references/troubleshooting.md`。
4. 只做一次小修正、一次針對性重測，再執行本技能最快的既有格式／契約驗證，隨即回到原任務。
5. 一次修正仍失敗、需要改範本的文案欄位、需要跨技能改造時，停止回填並簡短回報缺口。

不得修改已安裝快取、內建技能、外掛或第三方來源。使用者的真實文案、品牌語氣與素材不得進入公開技能。回填不授權 commit、push、發布或部署。


## 輸出與驗證

回報已選頁面、完整文案預覽、來源標記、寫入雜湊與本機檢查結果，接續本次目標的下一技能。工具測試驗證來源、定稿必填、數字與佔位拒絕、預覽雜湊、文章格式及同步；不能代替人類對商業事實的確認，也不代表已公開部署。
