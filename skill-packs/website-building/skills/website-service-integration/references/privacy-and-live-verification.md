# 隱私揭露與端到端驗證

## 發布前揭露

每個已啟用服務都必須讓訪客在操作前看見：服務商名稱、會發生的動作、官方隱私政策連結。聯絡表單還要在送出按鈕前顯示同意勾選，說明姓名、Email 與訊息會交由該服務處理。

設定檔只能保存會出現在公開 HTML 的資料。不得保存訪客內容、名單、後台截圖、Cookie、Token、API key、webhook secret、銀行或付款資料。公開 URL 若帶有看似秘密的 query key，也要停止並請服務商改用正式的 public endpoint／hosted link。

本版不植入分析或廣告追蹤。若未來加入會設定非必要 Cookie 或跨站追蹤的 script，必須先另外定義同意管理、撤回方式、資料保留與所在地法律需求，不能只加一行隱私文字。

## 驗證分層

| 層級 | 證據 | 可以宣稱 |
|---|---|---|
| 設定 | 候選設定通過契約並套用 | 網站已設定公開 endpoint／URL |
| 本機建置 | `npm run build` 與 `verify` 通過 | 靜態 HTML 含正確表單、連結與揭露 |
| 公開讀回 | 正式網址的 `verify --url` 通過，並以瀏覽器開啟 hosted URL | 已部署的網站會導向預期服務頁 |
| 端到端 | 經授權執行動作，並從服務端讀回 | 該次測試資料確實送達或建立 |

不能用下一層推測上一層之外的事實。公開連結可開啟，不代表表單會收件；表單顯示成功頁，也不代表服務端真的保存；付款頁可開啟，不代表付款、退款或入帳正常。

## 安全測試規則

- 聯絡表單：先預覽會送出的虛構姓名、測試 Email 與訊息；取得授權後只送一次。從服務後台或通知信讀回，隨後依使用者指示保留或刪除。
- 電子報：使用使用者指定的測試信箱；訂閱與可能的 double opt-in 都是外部寫入。讀回後說明是否退訂，不自行留在正式名單。
- 預約：先預覽時區、時間、名稱與通知對象；建立後讀回，再經使用者同意取消，避免占用時段。
- 付款：只開啟 hosted checkout 並核對商家、商品、幣別與金額；不填卡號、不按付款、不建立零元訂單來假裝驗收。

若服務後台只允許人類登入，Agent 準備好要核對的欄位，讓使用者完成登入或驗證後再接手讀回；不要請使用者複製整頁資料或任何秘密到對話。
