# 串接模式與供應商選擇

本版只處理靜態網站能安全承載、且公開設定本來就會出現在 HTML 的整合。不依記憶固定推薦供應商；需要選擇時查詢候選服務的官方功能、價格、資料地區、匯出與刪除方式，再把查證日期與連結列在當次預覽中。

## 共通選擇順序

1. 沿用使用者已經付費或已經累積資料的服務。
2. 優先 hosted page 或標準 HTML POST，不加入第三方 JavaScript、iframe、Cookie 或網站端 secret。
3. 比較免費方案是否真的支援所需功能；任何試用期、交易費、寄送額度與品牌浮水印都要清楚標示。
4. 服務必須提供公開 HTTPS 目標與官方隱私政策頁；缺一不可。
5. 使用者必須能從後台讀回表單、訂閱或預約結果。只有前端連結可開啟，不代表資料已送達。

## 聯絡表單

- 模式：`html_post`。
- 網站公開內容：POST endpoint、服務商名稱、隱私政策網址。
- 固定欄位：`name`、`email`、`message`、`privacy_consent`。
- 不支援：需要自訂 JavaScript SDK、前端 API key、自訂 header、檔案上傳、CAPTCHA secret、webhook 或 server-side handler 的表單。
- 完成標準：本機與公開 HTML 正確；使用者另行授權測試送出後，服務端能讀到虛構測試資料。

## 電子報

- 模式：`hosted_link`。
- 網站公開內容：供應商託管的訂閱頁與隱私政策網址。
- 預設不用嵌入碼，避免額外 script、Cookie 與樣式衝突。
- 完成標準：公開連結能開到正確名單的訂閱頁；若要宣稱訂閱成功，需經授權以測試信箱完成訂閱並從名單或確認信讀回。

## 預約

- 模式：`hosted_link`。
- 網站公開內容：供應商託管的預約頁與隱私政策網址。
- 預設不用 iframe，避免第三方追蹤、Cookie 同意與手機版高度問題。
- 完成標準：公開連結能開到正確的預約類型、時區與可用時段。建立測試預約會占用時段，必須另行授權並在讀回後取消。

## 付款

- 模式：`hosted_link`，`verification_scope` 固定為 `link_only_no_transaction`。
- 網站公開內容：服務商託管的結帳頁與隱私政策網址；網站本身不接觸卡號。
- Agent 不輸入身分、稅務、銀行、收款或卡片資料，不建立真實或測試扣款。
- 完成標準只到：公開連結能開到正確商家、商品、幣別與金額。付款成功、退款、發票與入帳都不在本版自動驗證範圍。

## 何時停止改走後續實作

出現下列任一項時，不把它硬塞進通用 hosted 模式：會員登入、購物車、多品項動態價格、優惠碼同步、檔案上傳、webhook、自動寄信、CRM 回寫、API secret、Cloudflare Worker function、資料庫、第三方追蹤 script、iframe 或 Cookie consent。先回報所需架構、資料與權限，再由使用者決定是否擴充。
