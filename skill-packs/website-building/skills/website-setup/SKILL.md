# 官網打造設定

這是官網打造工作流的第一個技能。目標是先完成候選文案與設計推薦，再讓人類批次確認商業事實與視覺方向；已知答案不重問。完整建站時依 [技能接續契約](references/workflow-handoff.md) 自動接續，不因技能邊界停下。

## 責任

- 唯讀盤點工作區既有設定：`website/config.json`、知識庫的一人公司設定檔、社群媒體設定。能抓到的欄位直接當預設值。
- 一次訪談：只問設定檔還缺、而且會改變網站內容或路線的問題；已有答案的欄位只請使用者確認，不重問。
- 產生完整預設方案：頁面清單、視覺調性推薦、託管方案、網域路線、主要行動呼籲。
- 批次確認：一次列出整份方案，使用者只回答要改哪裡；使用者說「全部用預設」時直接進入寫入預覽。
- 依 `references/configuration-contract.md` 驗證候選設定，先預覽，取得明確確認後才寫入。
- 分層回報已確定、尚未確定與必須由人完成的項目，並交接給下一個技能。

設定 helper 只管理設定。完整建站目標由同一 Agent 讀取對應技能，先產生候選文案與風格，不要求使用者重新下指令；不存在的技能或工具須回報，不虛構執行結果。

## 輸入

優先從對話與使用者指定工作區取得：

- 明確任務，例如「幫我做官網」、「我想換網域」、「檢查目前設定」。
- `website/config.json`；若不存在，以 `assets/default-config.json` 作為中性起點。
- 存在時才讀 `sources/strategy/solopreneur-profile.md`（知識庫的一人公司設定檔）與 `social-media/config.json`（社群媒體設定）。兩者都是可選來源，缺少時不要求使用者先安裝其他套件。
- 使用者提到的既有網域、既有 Cloudflare 帳號、既有網站或素材。

不得主動搜尋憑證檔、列印環境變數值、讀取瀏覽器 Cookie，或要求使用者把 Token、密碼與 API key 貼進對話。

## 啟動流程

這是多階段技能。開始執行前，用 Mermaid 向使用者呈現本次實際採用的分支、確認關卡與停止位置；流程圖不代表外部操作已獲授權。

1. 唯讀檢查工作區設定與可選來源，標示 `missing`、`not_configured`、`partial` 或 `configured`。
2. 判斷使用者是否已有明確任務。
   - 有明確任務且只涉及設定的一部分（例如只改網域路線）：只處理該部分，不重跑整份訪談。
   - 沒有明確任務且設定不足：進入一次訪談。
   - 沒有明確任務且設定足夠：摘要目前狀態，詢問這次要修改哪一部分。
3. 一次訪談：依 `references/intake-questions.md`，把仍缺的問題一次列出，並在每一題旁標示 Agent 從既有來源推得的預設答案。使用者只需要回答或修正。
4. 產生預設方案：依 `references/page-inventory.md` 決定頁面清單，依 `references/tonalities.md` 推薦一個調性，依 `references/hosting-options.md` 決定託管與網域路線。走到風格這一項時**主動展示**：若 `website-design-preview` 已安裝，直接用它產生本機風格畫廊並截圖給使用者看，建議的一套標示「建議」，讓使用者在同一次批次確認裡選編號；未安裝時只推薦調性並說明風格會在該技能挑選。
5. 先讀取 `website-content-writing` 完成候選文案，再批次確認：一次列出整份方案，包含每個預設值的來源（使用者提供、既有設定推得、Agent 建議）。使用者說「全部用預設」時視為確認。
6. 形成候選設定後，依 `references/configuration-contract.md` 驗證並預覽。
7. 使用者確認預覽後才寫入；重新讀回檔案並比對雜湊。
8. 依 `references/verification-levels.md` 記錄實際狀態；完整建站自動進入已確認的文案／設計套用與建置，不在設定完成就結束。

## 一次訪談原則

- 核心只有五題：服務誰、提供什麼、為什麼可信、希望訪客做什麼、怎麼聯絡。其餘問題只在會改變網站內容或路線時才問。
- 每題都附預設答案。從一人公司設定檔或社群設定推得的答案標示來源；推不出來的才留空。
- 不把訪談拆成多輪一問一答，除非使用者主動要求慢慢來。
- 訪談答案是事實，Agent 不得自行美化或補上使用者沒說過的成就、數字或客戶名稱。信任依據若使用者沒提供，留空並在文案階段用中性寫法。

## 預設方案原則

- 頁面：依實際需求選擇，預設首頁與技術用 404；關於、服務、聯絡可合併首頁，部落格選配。原六頁與六種風格保留為範例，不強制全選。
- 風格：依受眾與定位推薦一個調性，說明理由，並在可能時直接展示 `website-design-preview` 的畫廊讓使用者看圖選號；不要只用文字描述風格。
- 託管：固定 Cloudflare Workers 靜態資產、免費方案、Agent 本機 `wrangler deploy`。Git 連動只在使用者主動要求時改選。
- 網域：先問「現在有沒有網域」。沒有就預設先用 `workers.dev` 上線，`wanted` 記為 `undecided` 或使用者的答案。要買的話優先 Cloudflare Registrar；使用者想要的頂級網域不在 Registrar 清單時，改走外部註冊商。既有網域則記錄 DNS 是否已在 Cloudflare。
- 行動呼籲：預設 `mailto` 或使用者提供的外部連結；要由 `website-service-integration` 後續建立表單時記為 `form_later`。
- 字型：預設 `google`，各主題會載入自己的中文字型，網站會向 Google 發請求；批次確認時用一句話說明，使用者在意隱私就改 `system`。

## 寫入流程

1. 將候選設定寫入暫存檔，不直接覆蓋正式設定。
2. 執行 `scripts/manage_workspace.py preview`。向使用者顯示新增、修改、保留、設定目標與預覽雜湊；不要只顯示摘要後省略實際欄位。
3. 只有在使用者明確確認這份預覽後，才以相同候選檔與雜湊執行 `apply --confirm-write`。
4. 既有設定在預覽後變動、候選含秘密欄位、路徑跳出工作區、schema 不符或雜湊不同時停止。
5. 寫入後重新讀取 `website/config.json` 與 `.local/website/setup-state.json`；驗證內容雜湊一致，並回報 `contains_credentials: false`。

命令旗標不是對話核准。不可因為能執行 `--confirm-write` 就跳過使用者確認。批次確認方案與確認寫入預覽可以合併成同一次確認，前提是預覽內容與方案完全一致。

## 執行錯誤最小回填

實際執行出錯，或可觀察行為與本技能規則衝突時，原任務優先：

1. 先保存目前進度與已知狀態。
2. 若 `references/troubleshooting.md` 已存在，只讀與目前症狀相關的段落；不存在時不要先建立空檔。
3. 只有能證明錯誤來自本技能、修正限於同一個由使用者管理的技能來源、不新增依賴或外部授權，且重跑原失敗步驟通過時，才立即回填：主要流程更新本 `SKILL.md`，已驗證的特定環境或例外才建立或更新 `references/troubleshooting.md`。
4. 只做一次小修正、一次針對性重測，再執行本技能最快的既有格式／契約驗證，隨即回到原任務。
5. 一次修正仍失敗、需要跨技能或共用架構改造、需要長時間研究、找不到可寫原始來源，或修正本身需要新的外部動作時，停止回填並簡短回報技能缺口；不把未驗證推測寫進技能。

不得修改已安裝快取、內建技能、外掛或第三方來源。真實網域、帳號、Worker 名稱、品牌內容與一次性使用者選擇不得進入公開技能。回填不授權 commit、push、發布、部署或原任務以外的遠端變更。

## 輸出與交接

每次輸出至少包含：

- 本次任務與採用的分支。
- 訪談結果摘要與每個欄位的來源。
- 預設方案：頁面、調性、託管、網域路線、行動呼籲。
- 設定預覽或寫入後的工作區相對路徑與雜湊。
- 各層狀態：本機設定、本機建置、自動化頁面檢查、Wrangler 登入、`workers.dev` 部署、自訂網域、公開收錄。本技能完成時只有第一層可以是完成。
- 剩下的人類接觸點清單，以及下一個唯一建議動作（通常是 `website-content-writing` 或 `website-design-preview`）。
- 後續技能交接需要的已核准輸入；不得把未核准推測包裝成設定。

## 寫入範圍

本技能只可在使用者明確指定的工作區寫入：

- `website/config.json`：商業資訊、頁面、設計、託管與驗證狀態。
- `.local/website/setup-state.json`：設定雜湊、套用時間及不含憑證聲明。

不得寫入技能目錄、公開 Toolbox、一人公司設定檔、社群設定、網站專案目錄或任何外部服務。若使用者要求更新一人公司設定檔，交給知識庫套件的對應技能，並保留其預覽與確認關卡。

## 停止條件

- 工作區無法唯一判定。
- 使用者要求的動作屬於後續技能（建置、部署、購買網域），且該技能尚未安裝。
- 候選設定含秘密、私人識別碼或憑證路徑。
- 預覽未確認、預覽後來源變動、同名路徑類型衝突或讀回驗證失敗。
- 網域現況無法判定是否已在 Cloudflare，且使用者無法回答。

停止時保留現有資料，不自動猜測答案，也不把未確認的預設值寫入正式設定。

## 驗證

公開候選版以虛構工作區驗證：缺少設定、既有來源當預設值、一次訪談、全部用預設、預設方案的頁面與網域路線、秘密欄位拒絕、預覽前不寫入、錯誤雜湊拒絕、確認後原子寫入、既有變動停止、讀回雜湊、驗證狀態不得跳層，以及技能錯誤的一次小修正與停止邊界。虛構測試不證明任何 Cloudflare、Node 或用戶端流程已實測。
