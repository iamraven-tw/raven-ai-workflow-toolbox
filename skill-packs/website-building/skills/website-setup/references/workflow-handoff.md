# 單一目標的技能接續契約

使用者要求「完成官網」時，七個技能是 Agent 內部分工，不是七次使用者指令。開始只畫一次本次流程；單獨查詢或局部修改不啟動整條流程。

1. 讀取使用者指定的工作區與既有事實。Agent 先形成候選頁面、文案、風格推薦與本機目標；缺少真實性所需資料才集中補問。候選檔可存在私人暫存目錄，不冒充已核准設定。
2. 讀取文案與設計技能，先完成文案並展示風格畫廊。設定與文案工具可用候選檔；畫廊需要工作區時用獨立候選工作區，不覆寫正式檔案。
3. 一次呈現商業事實、文案、視覺方向、已選頁面、本機專案位置、必要依賴與外部資料流。人類批次修正／確認；不要求逐欄自己寫、不拆成三次審查。
4. 核准後，Agent 依原有 preview／plan、雜湊及 confirm 旗標，自動套用設定與文案、選主題、建置、測試、截圖、修正及記錄狀態。這些已核准範圍內的本機操作不再問「是否繼續」。旗標不是新增授權；候選或目標漂移仍停止。
5. 需要登入、本人驗證、敏感資料、首次公開部署、購買或付費時才交回人類。部署預覽可一次涵蓋已選網域、收錄設定及同批必要重建／讀回，不把每個技術子步驟拆成新授權。新目的地、費用、服務端寫入或刪除仍需相符授權，不由建站目標推定。
6. 服務串接只在目標需要時自動接續；目前串接器需要聯絡頁，先列入同一份頁面提案。沒有需求就略過，不因為有七技能而強制跑齊。
7. Agent 依實際結果更新既有 verification 與本機狀態；技術狀態記錄不請人核准。維運、備份、更新在已要求範圍內自動處理；排程、異地上傳、線上回復與刪除不預設啟用。

每次交接由同一 Agent 完整讀取下一技能及必要 reference，沿用本次目標、已確認資料與授權，不要求使用者重新呼叫。只缺執行工具時回報具體缺口；不把補技術檔、修程式、截圖或安裝狀態記錄推給人類。不要建立額外的工作流引擎或第二份商業資料庫。

本契約優先於個別技能殘留的「每技能再確認」文字。個別操作的雜湊、來源、秘密與不明結果停止保護仍有效。私人事實只保存在使用者工作區，不回填公開技能。
