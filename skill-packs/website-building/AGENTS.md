# 官網打造技能包維護規則

本目錄是公開、去識別化的技能包來源。所有範例必須使用虛構品牌、虛構網域與虛構文案，不得寫入真實帳號、網址、Cloudflare 帳號識別碼、Worker 名稱、API Token、部署 Hook、私人檔案路徑或任何維護者的品牌內容。

## 核心承諾

- 本技能包交給 AI Agent 全程執行；人類只提供事實、做取捨決定、完成外部帳號的登入與同意、授權付費或公開發布。完整清單見 `docs/human-touchpoints.md`。
- 商業資訊只在 `website-setup` 問一次。之後的技能從 `website/config.json` 讀取，不得重複詢問。
- 每個技能先產生完整的預設方案，一次列給使用者批次確認；使用者說「全部用預設」時只剩授權關卡。
- 每個外部動作都先預覽、取得明確授權、執行後從平台讀回；指令沒有報錯不等於完成。

## 修改邊界

- `install.manifest.toml` 是已實作技能、規劃中技能、依賴候選與安裝狀態的唯一機器可讀來源。
- 尚未完成的技能只可列於 `[[planned_skills]]`，不得建立只有名稱或待辦事項的 `SKILL.md`。
- 第三方依賴在第一個技能階段只列於 `[[planned_dependencies]]`，不下載、不安裝；進入安裝路徑前必須固定版本或 commit、記錄授權與完整性驗證方式。
- 風格來源必須符合 `[style_sources]` 的納入門檻；以真實品牌命名的風格只以視覺調性呈現，不得把品牌名當預設值。
- Cloudflare 帳號建立、`wrangler login`、部署、綁定網域、購買網域、移除 `noindex` 都是獨立外部關卡；本機測試不得假裝這些關卡已通過。
- 套件不保存任何 Cloudflare API Token；本機部署一律使用 Wrangler 自己的 OAuth 登入狀態。
- 公開套件與任何私人網站專案都是獨立快照，不建立自動同步、symlink 或隱含複製流程。
- 真實執行若證明目前技能規則錯誤，依技能內的「執行錯誤最小回填」處理；一次只做同一技能的小修正與針對性重測。
- 只有實際驗證過的特定環境解法才建立或更新 `references/troubleshooting.md`，不得預先建立空殼或寫入私人案例。

## 驗證規則

任何完成宣告都要分開回報：靜態結構、本機技能發現、範本建置、自動化頁面檢查、Wrangler 登入、`workers.dev` 部署、自訂網域、另一臺電腦驗收與正式公開支援。只有實際執行並取得證據的層級才能標示通過。修改套件後執行 `tests/validate_package.py` 與 `python3 -m unittest`。
