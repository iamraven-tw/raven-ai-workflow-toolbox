# 知識來源檢索

這個技能負責決定去哪裡找、如何整合、如何維護索引。它使用目前工作區已設定的 Provider；預設為 Graphify 與 Notebook，但不得將兩者視為不可替換的永久介面。

只有實際使用預設 Provider 時，才讀取 [Provider adapter](references/provider-adapters.md)；使用其他後端時依相同能力契約完成工作。

## 最小 Provider 能力契約

- **知識結構 Provider**：能檢查狀態、建立或更新本地知識結構、查詢節點與來源、保留抽取或推論信心，並提供視覺化或明確宣告不支援。
- **有根據的外部檢索 Provider**：能建立及列出集合、新增與同步來源、針對指定集合查詢、回傳可追溯引用，並回報同步與錯誤狀態。
- Provider 不得把登入秘密或大型全文寫入本機索引；替換 Provider 也不得要求改寫讀書筆記、次級資料、Wiki 與引用 schema。
- Provider 能力不足時要明確回報差異，不得假裝已完成等價操作。

## 知識優先度

1. 使用者直接說出、親自閱讀、思考或與 AI 討論後保存的本地知識。
2. 可追溯至原始來源的本地次級資料。
3. 尚未由使用者充分閱讀的外部探索性資料。
4. Wiki、知識圖譜與 AI 的綜合判斷或推論。

這是預設的個人知識優先度，不代表本地舊筆記必然比新的第一方資料更正確。可驗證事實仍須比較來源品質、版本與時間。

## 四種模式

1. **知識檢索**：回答問題、找資料、比較既有觀點。
2. **登錄外部集合**：記錄已存在且可驗證的知識集合。
3. **加入來源**：將網址、使用者指定的本機檔案或本流程建立的暫存附件加入明確集合。
4. **同步索引**：刷新指定集合的標題、來源清單與狀態。

## 模式一：知識檢索

### 步驟 1：先查本機路由索引

依序讀取：

1. `sources/wiki/index.md`
2. `sources/references/notebooks/index.md`
3. `sources/graphify-out/SOURCES_OVERVIEW.md`（若存在）

先依標題、主題、用途、標籤與來源摘要判斷資料可能在哪裡，不要一開始列出或查詢所有遠端集合。

創業方向、產品定位、目標客群或一人公司決策相關問題，若 `sources/strategy/solopreneur-profile.md` 存在，先讀取該設定檔；不存在時只有在目前沒有更明確任務時，才交給 `/solopreneur-profile` 引導建立。

社群經營策略、平台角色、內容規劃、互動原則或成效判斷相關問題，若 `sources/strategy/social-media-strategy-and-insights.md` 存在，同時讀取該檔案。`status: not_configured` 不得阻擋已提出的明確任務。逐篇數據與定期報告只是證據來源，不能在沒有使用者討論、補充與確認時被描述為已確認洞察。

### 步驟 2：查本地核心知識

- 定向搜尋 `sources/book-notes/`、`sources/wiki/` 與已知相關檔案。
- 知識結構存在時，可透過目前 Provider 查詢跨文件關係。
- 找不到答案時，再定向搜尋已知相關的 `sources/references/` 資料。
- 不為一般問題無差別掃描整個 `sources/references/`。
- 保留知識結構 Provider 的抽取、推論、不確定性與來源標記。

### 步驟 3：選擇相關外部集合

從本機外部檢索索引選出最少數量的候選，通常一至三組。不相關的集合不連線、不重查。

只有下列情況才刷新候選集合：

- 本機紀錄是 `unverified`、`stale` 或 `error`。
- `last_verified` 超過設定的檢查週期。
- 使用者剛在遠端增刪來源或重新命名。
- 查詢回傳的來源識別資料與本機紀錄不一致。
- 精確引用需要最新來源清單。

一般一本書、文章或單一文件預設不建立外部集合；只有資料集龐大、跨大量文件，或反覆載入明顯浪費 Token 時才使用。

### 步驟 4：查詢候選集合

- 每次明確指定集合；若 Provider 不支援跨集合查詢，就逐一查詢後再整合。
- 優先使用結構化輸出，保留集合、來源與引用識別資料。
- 登入或 Provider 失效時，停止遠端查詢並說明限制；仍可用本地來源完成目前能回答的部分。
- 不因全域「目前選擇」狀態而把查詢或寫入送到不明集合。

### 步驟 5：整合與引用

答案必須區分：

- **使用者心得**：本地檔案與段落。
- **本地外部資料**：原始檔案、來源網址或知識結構位置。
- **外部集合資料**：集合名稱、來源標題、來源 ID 與引用編號。
- **綜合判斷**：明確標示為綜合分析，不冒充來源原話。

來源互相矛盾時並列差異，不自動覆蓋任何一方。

### 步驟 6：交付知識結構視覺化

- 一般檢索先直接回答，不為每個單一事實附上整張圖。
- 涉及三個以上重要節點、跨文件關係、跨主題群、概念路徑、意外連結、核心節點或群聚結構時，主動提供視覺化。
- 使用者要求查看整體架構、關係圖或知識地圖時，將視覺化視為主要交付之一。
- 提供視覺化時，同時列出最值得查看的二至五個節點、主題群或關係。
- 回答本身必須完整，不能以「請自己看圖」取代結論與引用。
- 索引或視覺化可能過期時清楚標示；不得只為交付視覺化而盲目重建。
- manifest、環境或變更數量異常時，停止更新並回報。

## 模式二：登錄外部集合

1. 從使用者提供的網址或 ID 解析完整識別資料；解析不可靠時請使用者提供可開啟網址。
2. 驗證登入、存取權與遠端狀態。
3. 取得集合標題、來源識別資料、類型、URL、狀態與數量。
4. 依來源與使用者說明整理主題、用途、適合查詢與不適用範圍。
5. 建立或更新 `sources/references/notebooks/entries/<安全檔名>.md`。
6. 更新 `sources/references/notebooks/index.md` 的路由表與 `last_verified`。

無法登入或無權存取時可建立 `unverified` 紀錄，但不得猜測來源清單。

## 模式三：加入來源

### 選擇目的地

- 本機索引能唯一判斷目的集合時直接使用。
- 有兩個以上同樣合理的目的地，或需要建立新集合時，先向使用者確認。
- 只有使用者明確要求加入、上傳或保存來源時，才執行遠端寫入。

### 來源處理與驗證

- 網址優先直接交給 Provider，不先下載永久副本。
- 使用者現有本機檔案從原位置上傳；未經明確要求不複製到 `sources/references/`，也不刪除。
- 本流程建立的傳輸暫存檔，只有遠端來源確認完成後才可清除。
- 上傳失敗、處理中或狀態不明時保留暫存檔，不先更新成成功。
- 遠端確認後更新本機 entry 與總索引；本機只保存中繼資料，不保存大型來源全文。

## 模式四：同步索引

- 預設只同步題目相關或使用者指定的集合，不做全帳號巡檢。
- 成功取得遠端清單後，標示新增、已移除、處理中、錯誤與改名。
- 不永久刪除本機歷史；遠端已移除來源改標 `removed_remote` 並記錄同步日期。
- 更新 `last_verified`、`source_count` 與 `sync_status`。
- 只有知識結構更新確實成功後，才能將其狀態標成最新。

## 本機索引最小欄位

每個集合的 entry 至少包含：

- 集合標題、完整 ID、網址與存取狀態。
- 主題、用途、適合查詢、不適合查詢。
- `sync_status`、`last_verified`、`review_after` 與來源數量。
- 來源 ID、標題、類型、URL、遠端狀態、加入時間與最後看到時間。
- 已知限制、人工備註與變更紀錄。

Provider 特有欄位可作為 extension，但不得改寫上述共用欄位的意義。

## 安全與破壞性操作

- 不得保存 Cookie、Token、登入狀態內容、私人憑證或大型來源全文。
- 刪除集合、刪除來源、清空、移除分享與登出，必須取得使用者對明確目標的確認。
- 外部工具失敗時保留索引與原始資料，不宣稱同步成功。
- 只清理由本流程建立、且已確認完成用途的暫存副本；不刪除使用者原始檔案。
