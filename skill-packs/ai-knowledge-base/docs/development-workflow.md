# 實際案例與公開核心的開發流程

## 目的

`My Real Second Brain` 以真實使用案例驗證工作流程，再把具有通用價值的修正回饋到公開核心。公開 repository 不保存任何實際案例的私人內容。

## 兩邊的責任

| 層級 | 公開核心 | 實際案例 |
|---|---|---|
| 目錄契約 | `template/sources/` | 工作區的 `sources/` |
| 通用技能 | `skills/` | 可以保留案例專用整合的技能版本 |
| 一人公司設定 | 只有 `not_configured` 空白範本 | 實際方向、限制、優先事項與決策脈絡 |
| 安裝契約 | manifest、安裝文件與 setup 技能 | 實際環境驗證與相容性回報 |
| 內容資料 | 只放空白模板與虛構範例 | 專案規則、筆記、索引、研究及衍生輸出 |

「結構一致」指共用核心目錄、schema 與技能契約相容，不代表兩個專案可以整包覆蓋。實際案例可以加入內容產線或其他專用目錄，公開 repository 則包含發行、授權與安裝文件。

## 回饋分類

1. **通用規則或能力**：去識別化、參數化後同步到公開核心。
2. **案例專用整合**：只留在實際案例，必要時記錄為 extension。
3. **私人內容與資料**：永不進入公開 repository。
4. **Provider 相容性修正**：更新公開契約與固定版本，再回到實際案例驗證。

## 每次同步的檢查

1. 比對 `template/sources/` 與實際案例 `sources/` 的核心目錄集合。
2. 確認公開檔案不含姓名、帳號、Notebook ID、私人網址、絕對路徑或實際來源內容。
3. 確認所有可安裝技能不含維護者專用的同步詢問或本機位置。
4. 驗證 manifest、技能 frontmatter、Markdown fence 與所有必要來源路徑。
5. 在乾淨的暫存工作區測試 template 初始化；不得用真實案例資料測試公開安裝。

同步本機檔案不代表 commit、push、建立遠端 repository 或發布；對外動作仍須獨立核准。
