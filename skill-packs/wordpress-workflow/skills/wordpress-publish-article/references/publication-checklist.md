# WordPress 文章發布清單

只在準備或執行文章發布時讀取本清單。它定義發布套件，不授權改寫正文或執行文章之外的網站變更。

## 必要輸入

- 完整文章正文、可讀取的來源檔案或網址，或既有 WordPress 文章 ID／網址。
- 可辨識的目標 WordPress 網站。
- 新增或更新的意圖；若未明說，依是否有既有文章 ID、網址或重複項目判斷。

若缺少完整正文，不要代寫；轉交寫作技能。

## 受眾與標題

- 優先讀取既有網站受眾設定或專案資料。
- 若沒有設定，從網站名稱、標語、關於頁、主要分類、既有標籤和代表文章建立一段受眾假設。
- 標題提案必須對應受眾需求，而不是只使用誇張措辭。
- 提供三個不同角度的標題，標出推薦選項；已收到正式發布指令時，若使用者沒有異議便使用推薦選項。

## WordPress 欄位

- 公開標題
- 完整正文
- 文章網址代稱（slug）
- 一個主要分類
- 3–6 個一致且可重用的標籤
- WordPress 摘要（excerpt）
- 作者或署名
- 目標狀態（`draft`、`publish` 或排程）、時間與時區
- 留言設定，沿用網站預設值，除非使用者另有指示

## SEO、社群與結構化資料

- SEO title：包含主要搜尋意圖且不與公開標題機械式重複。
- Meta description：準確概括價值與內容，不使用正文未支持的承諾。
- Canonical URL：指向預定的正式文章網址。
- Open Graph：標題、描述和分享圖片。
- X／Twitter Card：只有網站工具或外掛支援時設定。
- Schema：依內容選擇 `Article`、`BlogPosting`、`NewsArticle`、`HowTo` 或 `FAQPage` 等實際支援類型。
- Schema 常用屬性：headline、description、author、datePublished、dateModified、image、publisher、mainEntityOfPage。

先檢查佈景主題、Jetpack 或 SEO 外掛是否已輸出這些資料。不得同時建立內容重複或互相矛盾的 JSON-LD。只有即時 MCP 結構支援的欄位才可宣稱已寫入。

## 圖片

- 指定精選圖片與每張內文圖片的角色。
- 來源為免費圖庫時，保留原始圖片頁連結、作者和可確認的授權依據。
- 每張圖片都要有用途明確的 alt text；純裝飾圖片可使用空白替代文字。
- 需要時加入圖說及署名。
- 驗證圖片尺寸、裁切、壓縮、長寬比和小螢幕呈現。
- 確認佈景主題是否自動顯示精選圖片，避免頁首與正文重複。

## 正文格式

- 版型負責 H1，正文從 H2 開始。
- 標題層級依序排列。
- 保留段落的文字、主張、語氣和順序，除非只有為了區塊相容性而移動元素。
- 允許修正區塊、清單、引用、表格、程式碼區塊、連結格式與圖片位置。
- 發現疑似錯誤、缺少來源或需要重寫時，只標示問題或轉交其他技能。

## 發布前風險檢查

- 已核對 live site identity，不只依賴舊紀錄或重新導向網域。
- 已檢查重複標題、slug、canonical URL 及既有文章。
- 已區分新增文章與更新文章。
- 已辨識網站是 public、private 或其他限制狀態。
- 已辨識可能觸發的訂閱郵件、RSS、Jetpack Social 或其他整合。
- 沒有未替換的佔位文字、測試網址或不明授權圖片。
- 已依使用者明確指令判斷目標狀態；只有明確發布指令才使用 `publish`。
- 正式發布前已提醒使用者：「這次會直接以正式發布狀態寫入 WordPress，不會先建立草稿。」
- 網站若為 private 或受限狀態，已同時說明文章雖為 `publish`，未登入訪客仍無法存取。
- 上述文字是提醒，不是第二次確認關卡；使用者已明確要求發布時，提醒後立即執行。

## 發布後驗收

- 重新讀取文章 ID、網址、狀態和發布時間。
- 比對標題、slug、摘要、分類、標籤、精選圖片與已支援的 SEO 欄位。
- 檢查 `_content_warnings` 與 WordPress 實際保存內容。
- 在實際 WordPress 頁面檢查電腦版與行動版排版。
- 檢查 canonical、meta description、社群分享圖片和 JSON-LD。
- 分別回報文章實際狀態與網站是否能讓未登入訪客存取。
- 一定提供可點擊的文章正式網址，請使用者直接開啟並檢查實際排版；不得只提供文章 ID 或後台紀錄。
- 網站若為 private 或受限狀態，仍提供文章正式網址，並註明可能需要登入才能檢視。
- 明列未能驗證、未被工具支援或可能由外掛另外處理的項目。
