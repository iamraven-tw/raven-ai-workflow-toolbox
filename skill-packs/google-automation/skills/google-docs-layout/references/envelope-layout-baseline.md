# 信封排版定稿案例

這份案例記錄已完成實際 Apps Script 執行與 Google Docs 目視驗收的信封排版方法。它是可重用的設計經驗，不是所有文件都必須照抄的通用尺寸。

## 共用基線

- 每位收件人使用一個主要無框線表格，一人一頁。
- 每頁之間加入明確分頁。
- 頁面邊界：上、下 36 point，左、右 42 point。
- 郵遞區號先從地址拆出，六碼顯示為 `3+3`，中間使用不可斷行連字號。
- 不合併儲存格；郵遞區號放入既有寬欄，避免合併後索引與位置改變。
- 重寫文件時明確取消粗體與斜體。
- 直式與橫式使用分離的排版函式、欄寬、列高及測試。
- 每一方向經使用者目視確認後即定稿；其他方向不得改動其基線。

## 直式定稿

版面關係：

- 「貼郵票處」位於上方左側資料區。
- 收件郵遞區號位於上方靠右。
- 收件地址位於右側直排。
- 收件單位與人名位於頁面中央直排並置中。
- 寄件名稱與地址位於左下直排。
- 寄件郵遞區號位於下方靠左。

字體：

- 收件人與收件地址：28。
- 寄件人與寄件地址：24。
- 「貼郵票處」：24。
- 郵遞區號：20。
- 全部取消粗體與斜體。

實作：

- Google Docs 沒有原生中文直書，以窄欄自然折行。
- 先移除直排資料中的既有空白與換行，不插入逐字換行。
- 六欄版面欄寬基線：`[30, 30, 172, 39, 197, 32]`。
- 三列版面列高基線：`[48, 590, 45]`。
- 單頁安全高度：`700`。
- 收件郵遞區號儲存格右內距設為 `0`，寄件郵遞區號儲存格左內距設為 `0`，使兩者分別靠外側。

## 橫式定稿

版面關係：

- 寄件資料位於左上。
- 「貼郵票處」位於右上。
- 收件資料位於中央偏右。
- 收件郵遞區號在地址上方第一行。
- 收件單位、人名與「啟」位於地址下方。

字體：

- 寄件資料：24。
- 「貼郵票處」：24。
- 收件地址、單位與人名：28。
- 全部取消粗體與斜體。
- 不得為了塞進版面縮小已確認字體。

實作：

- 每位收件人使用一個 3×3 無框線表格。
- 欄寬基線：`[270, 360, 120]`。
- 列高基線：`[120, 290, 70]`。
- 單頁安全高度：`500`。
- 寄件資料放在 `(0, 0)`，貼郵票處放在 `(0, 2)`，收件資料放在 `(1, 1)`。
- 地址優先分成「縣市＋行政區」及「其餘道路門牌」兩行。
- 寄件區行距使用 `1`，收件區行距使用 `1.05`。
- 收件儲存格左內距使用 `12`，保留中央偏右的位置。

## 多行字體問題的定稿修正

橫式寄件與收件資料都包含多行文字。只對第一個子段落執行 `setFontSize()` 時，第一段可能正確，其他行仍顯示 Google Docs 預設的 9 號字。

定稿方式：

1. 使用 `cell.editAsText()` 對整個儲存格設定字體、粗體與斜體。
2. 走訪 `cell.getNumChildren()`。
3. 對每一個 `PARAGRAPH` 分別設定水平對齊、段前、段後與行距。
4. 產生文件後重新開啟第一頁表格。
5. 以 `getFontSize(offset)` 逐字確認寄件資料為 24、收件資料為 28。
6. 使用者最後打開文件，目視確認實際大小、位置與分頁。

## 回歸測試

- 直式欄寬與列高常數保持定稿值。
- 橫式欄寬與列高常數保持定稿值。
- 直式資料沒有手動逐字換行。
- 郵遞區號使用不可斷行連字號。
- 每位收件人只建立一個主要表格。
- 每個方向的列高總和不超過其安全高度。
- 橫式測試完成後恢復使用者原本的方向設定。
- 遠端讀回橫式第一頁，逐字驗證寄件資料 24、收件資料 28。
- 使用五筆較長的臺灣機關名稱與地址目視確認，每位收件人一頁且郵遞區號未落到下一頁。
