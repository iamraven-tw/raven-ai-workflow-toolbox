# 第一版：免費基礎應用分流

## 目的

使用者只提到 Google Apps Script、但沒有指定今天要做什麼時，先決定要做專案或進入教學。做專案時再選建立或接管；進入教學時先選課程案例。目標確定後，才執行共用開發環境關卡，完成電腦層唯讀健檢及該專案的目錄、Git、忽略規則與專案內 `clasp`。

第一版只提供個人 Google 帳號可以完成的基礎能力。使用者不需要信用卡、付費 Google Workspace、Workspace 管理員身分、標準 Google Cloud 專案或公開 Marketplace 審查。

使用者若已有付費 Workspace，仍可使用本技能，但技能不得讓第一版流程依賴付費方案才有的能力或較高配額。

## 免費資格判斷

一項能力必須同時符合以下條件，才能列入第一版：

1. 個人 Google 帳號可使用。
2. 不需訂閱付費 Workspace。
3. 不需 Workspace 管理員權限。
4. 不需綁定信用卡或啟用 Cloud Billing。
5. 不需標準 Google Cloud 專案、自訂 OAuth Client 或公開 OAuth 驗證。
6. 可使用 Apps Script 內建服務完成；唯一例外是已確認的教學案例「指定資料夾檔案上傳紀錄器」可使用唯讀的 Google Drive Activity v2。
7. 能在個人帳號配額內合理測試與使用。

Apps Script 配額可能改變。每次建立可能接近配額的郵件、排程、檔案或 Web App 專案前，重新查閱 [Apps Script 配額](https://developers.google.com/apps-script/guides/services/quotas)，以 Consumer accounts 欄位作為第一版設計基線。

如果免費資格不明，Agent 必須先查證。無法確認時不要假設免費，將需求標記為「下一版候選」。

## 未指定目的時的第一個問題

完整顯示以下選項：

> 今天想要：
>
> 1. 做 Apps Script 專案
> 2. 學習 Apps Script

使用者已明確說要做專案、接管專案、學習或除錯時，直接進入對應流程，不重複顯示這一題。不要在同一題加入進階服務、付費方案或技術架構選項，也不要在使用者選定前執行環境安裝、建立專案或建立 Google 檔案。

## 選擇做專案

接著詢問：

> 這次的專案要：
>
> 1. 建立新的 Apps Script 專案
> 2. 接管既有 Apps Script 專案

選定後才進入下方對應分支。

## 分支一：建立免費基礎專案

接著詢問：

> 你最想完成哪一種結果？
>
> 1. 自動處理試算表或文件
> 2. 建立表單與後續處理流程
> 3. 自動處理 Gmail、Calendar 或 Drive
> 4. 定時或事件發生時自動執行
> 5. 建立簡單 Web App
> 6. 接收簡單 Webhook
> 7. 串接多個免費 Google 服務
> 8. 我不確定，請 Agent 根據需求判斷

使用者可選一個主要結果，再補充其他需要的服務。不要要求初學者先決定獨立式、綁定型或部署架構；Agent 根據需求提出建議。

### 允許的服務

| 類型 | 第一版可使用 |
|---|---|
| 試算表 | `SpreadsheetApp` |
| 文件 | `DocumentApp` |
| 表單 | `FormApp` |
| 簡報 | `SlidesApp` |
| 雲端檔案 | `DriveApp` |
| 雲端活動 | `DriveActivity`，只限「指定資料夾檔案上傳紀錄器」辨識外部上傳 |
| 郵件 | `GmailApp`、`MailApp` |
| 日曆 | `CalendarApp` |
| 執行與觸發 | `ScriptApp`、簡單觸發器、安裝型觸發器 |
| 基礎儲存與控制 | `PropertiesService`、`CacheService`、`LockService` |
| 工具 | `Utilities` |
| 網頁輸出 | `HtmlService`、`ContentService` |

同一個專案可以使用多個內建服務。

### Agent 必須整理的需求

- 使用者想解決的問題。
- 輸入資料從哪裡來。
- 預期產生什麼結果。
- 需要哪些免費內建服務。
- 手動、選單、事件、排程或 HTTP 啟動。
- 只供自己使用，還是與指定測試者共享。
- 使用哪一份新建測試資料。
- 可肉眼確認的成功標準。

## 分支二：接管既有基礎專案

Agent 先做唯讀盤點：

- 使用已驗證的 `clasp` OAuth 執行 `list-scripts`，列出目前 Google 帳號可存取的 Apps Script 專案。
- 讓使用者依專案名稱選擇接管目標；清單有同名專案或找不到目標時，才請使用者提供專案網址協助核對。Script ID 只在本機使用，不逐字顯示在回覆中。
- 專案類型、來源檔與 `appsscript.json`。
- 是否使用 `enabledAdvancedServices`。
- 是否連接標準 Google Cloud 專案。
- 是否使用外部 API、付費服務、管理員權限、Add-on、Chat App 或 API executable。
- 是否已有觸發器、Web App 或 deployment。
- 本機與遠端目標是否能確認。

若專案完全落在第一版範圍內，才繼續接管流程。

接管後續必須使用 [建立／接管流程](project-mode-workflows.md) 中的「接管既有 Apps Script」，先將選定的遠端專案安全複製到作業系統「文件」資料夾下的 `GoogleAppsScript/<專案名稱>`，再建立唯讀盤點、可回復基線與既有行為測試。

若發現進階或付費依賴：

1. 不刪除、不降級，也不擅自改成基礎版本。
2. 說明超出第一版的項目。
3. 將它標記為下一版候選。
4. 若能安全分離出純基礎部分，先提出範圍供使用者決定。

## 分支三：教學模式

使用者還沒指定階段時，只先列出兩個階段：

> 第一階段：生活應用入門
>
> 五個彼此獨立的生活應用，可自由選擇任一案例。
>
> 第二階段：整合專案
>
> 用依序累積的八課完成同一個「活動報名與通知系統」。
>
> 兩個階段沒有先修限制。請回覆 `1` 或 `2`。

未選定前不要自行預設階段，也不要建立練習檔案或撰寫程式。選定後由教學技能自動建立或讀取統一課程進度。第一階段的五個案例各自完整、不互相依賴，列出五個案例讓學員自由選擇，不得強制從最小編號開始。第二階段的八課共用同一專案與前課成果，固定依序完成第 1 至第 8 課；課間不再詢問階段或下一課，中斷後從最早未完成處恢復。使用者已在原始要求中指定階段或案例時直接沿用，不重複顯示清單。

第二階段的「活動報名與通知系統」使用固定路線：

1. Sheets 基礎讀寫。
2. Script Properties 與設定檢查。
3. Forms 收集資料與資料驗證。
4. Sheets 批次處理資料。
5. Docs／Drive 產生文件。
6. Gmail 寄送報名通知。
7. 表單或時間觸發器。
8. 簡單 Web App／Webhook。

不開設多條進階選修，也不在中途加入外部 API、付費服務或管理員功能。

使用者選定教學案例後，轉由 `google-apps-script-teaching` 執行教學案例、中文紀錄檔(Log)、測試與 Agent-first 上傳循環；專案環境與遠端操作仍由本技能處理。

## 第一版允許的架構

- 獨立 Apps Script 專案。
- 綁定 Google Sheets、Docs、Slides 或 Forms 的專案。
- 手動函式或自訂選單。
- 簡單觸發器與安裝型觸發器。
- 時間型排程。
- 簡單 Web App。
- 不處理敏感資料的基礎 Webhook 接收器。

## 第一版延後項目

以下功能不代表一定收費，但因為需要進階權限、Cloud 設定、發布流程或更複雜維護，統一留到下一版。唯一已確認的窄例外是「指定資料夾檔案上傳紀錄器」使用唯讀的 Google Drive Activity v2；Apps Script 預設 Cloud 專案會在加入服務時自動啟用對應 API，不要求標準 Cloud 專案或付費設定。這個例外不得延伸到其他進階服務：

- 進階 Google 服務。
- 外部 API 與第三方 OAuth。
- Google Chat App。
- Google Workspace Add-on 與 Marketplace。
- Workspace Admin SDK 與網域管理。
- API executable。
- 標準 Google Cloud 專案與自訂 OAuth Client。
- Vertex AI、BigQuery、Cloud SQL。
- 大型既有專案與高流量後端。

需要信用卡、付費訂閱、Workspace Business／Enterprise、管理員權限或付費 SaaS 的功能也一律延後。

## 安全預設

- 使用新建的練習檔案、測試表單與測試資料夾。
- Gmail 教學只使用學員本人能親自收信的地址。第二階段「活動報名與
  通知系統」的固定教材資料自動使用目前執行者帳號，正式收件人直接
  來自被處理報名資料的 Email，不建立 `TEST_EMAIL`；其他獨立案例則
  依案例安全設計取得學員控制的測試地址。真實寄送前都要再次取得確認，
  並以狀態檢查避免重複寄送。
- Calendar 使用清楚標記的測試行程。
- 觸發器建立前顯示函式、事件、帳號與頻率，並取得使用者確認。
- Web App 部署前說明執行身分、存取者與資料範圍，並取得使用者確認。
- 公開 Webhook 教學只能使用專用測試 Token 與假資料；完成驗證後預設封存公開測試 deployment。
- Webhook 第一版不得接收密碼、付款資料、OAuth 權杖或其他敏感個資。
- 未經確認，不修改使用者既有的真實文件、郵件、日曆或 Drive 結構。

## Web App／Webhook 限制

第一版只處理低流量、短時間執行、可明確驗證的用途：

- 簡單 HTML 頁面。
- 表單或查詢結果。
- JSON／文字回應。
- 不含敏感資料的 `GET`／`POST`。

若需求包含高流量、長時間工作、背景佇列、複雜驗證、付款、敏感資料或正式 SLA，說明 Apps Script 不適合作為第一版後端並停止該分支。

## 分流完成標準

Agent 必須回報：

- 選擇建立、接管或教學模式。
- 需求是否完整落在免費第一版範圍。
- 使用的內建服務。
- 專案入口與預期使用者。
- 是否需要觸發器或 Web App；這些操作目前是否仍待確認。
- 明確寫出沒有使用付費方案、管理員功能或外部付費 API；若是指定資料夾檔案上傳紀錄器，另列出唯讀 Drive Activity v2 例外，其他情境則寫明沒有使用進階服務。

通過後才能進入專案架構與實作。
