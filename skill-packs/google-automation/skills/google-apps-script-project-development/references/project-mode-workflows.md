# 建立／接管流程

兩種模式共用環境、Git、Script Properties、測試、繁體中文紀錄檔(Log)、UI 與遠端確認規則，但起點、風險與完成條件不同，不得只更換模式名稱後使用同一套初始化。

## 共用階段

每種模式都依序完成：

1. 執行共用首次使用環境關卡。
2. 確認專案目標、輸入、輸出、執行入口、使用者與可見驗收標準。
3. 確認第一版免費範圍、Google 服務、OAuth 權限、觸發器與部署需求。
4. 建立或保護 Git 基線，不混入使用者既有變更。
5. 依 [專案品質標準](project-quality-standard.md) 整理 Script Properties、測試矩陣、繁體中文紀錄檔(Log)與重複執行策略。
6. Agent 完成本機實作與驗證，建立本機 commit。
7. 需要 `clasp pull`、`clasp push`、觸發器或部署時，顯示目標與影響並取得當次確認。
8. 使用者親自完成 Apps Script UI 操作、遠端測試及成果判斷。
9. 通過全部驗收後，回報本機版本、遠端狀態、測試證據、已知限制與回復方式。

## 建立實際專案

### 建立前

1. 用一般語言確認要解決的真實問題，不要求初學者先選技術架構。
2. 列出輸入資料、預期輸出、執行方式、使用頻率及成功標準。
3. 用下方的簡短說明介紹獨立式與綁定型，再由 Agent 根據需求提出建議、理由及對使用者操作的影響。
4. 使用新建測試資源，不直接用正式資料開始開發。
5. 建立專案目錄、Git、忽略規則、專案內固定版本的 `clasp` 與安全的 Apps Script 結構。

向使用者說明時，優先使用以下白話：

- **獨立式 Apps Script**：像一個獨立的小工具，不固定綁在某一份 Google 檔案上；適合排程、跨多個 Google 服務或 Web App。
- **綁定型 Apps Script**：附著在某一份 Google Sheets、Docs、Forms 或 Slides 裡；適合直接處理該檔案，或從檔案中的選單與按鈕執行。

說明後由 Agent 依需求判斷並提出建議。使用者只需要確認建議是否符合實際使用方式，不需要自己研究技術架構後再做選擇。

### 遠端建立分工

- 獨立式 Apps Script 專案：預設由 Agent 準備 `clasp` 建立命令，顯示專案名稱、類型、父層資料夾與影響；取得使用者確認後才建立。
- 綁定 Google Sheets、Docs、Forms 或 Slides 的一般實際專案：預設由使用者親自建立目標 Google 檔案，再依 Agent 的繁體中文指引開啟其 Apps Script 專案。使用者提供私人對話所需的 URL 或 Script ID 後，Agent 只在本機使用，不在回覆、紀錄檔(Log)或 Git 重複顯示。
- 教學模式的新練習檔案：建立與命名屬於 Agent 的課前準備。取得遠端建立確認後，由 Agent 使用最終教材名稱直接建立，不要求學生先建立空白檔案再改名。第一次建立並驗證綁定的 Apps Script 專案後，Agent 立即在目前的私人教學對話提供可點擊的 Apps Script 編輯器網址，讓學生直接開啟；不得另外顯示原始 Script ID。Agent 建立的一般 Google 資源若需要填入指令碼屬性，重新核對後直接提供可點擊網址、ID 所在的網址區段與完整資源 ID，不要求學生自己找網址或貼回來。上述網址與 ID 不得寫入教材、紀錄檔(Log)、課程進度或 Git。工程測試由 Agent 執行；學生仍親自授權、輸入指令碼屬性、操作真正的教學 UI、查看代表性紀錄檔(Log)與驗證成果。
- 使用者明確要求 Agent 以命令建立綁定型檔案時，仍須先說明會建立的 Google 檔案與 Apps Script 專案，取得當次確認後才能執行。
- 遠端專案建立完成後，必須重新核對 `.clasp.json`、`rootDir`、專案名稱與綁定目標；命令沒有報錯不等於目標正確。

### 實作

1. 先完成最小可見成果，再逐項加入功能。
2. 依功能分檔，避免全部程式塞在同一檔案，也避免一個小函式一個檔案。
3. 建立設定清單、集中式設定檢查、中文紀錄檔(Log)與測試函式。
4. 涉及寫入、寄信、文件或事件處理時，先設計唯一識別碼、狀態或 Lock，保證重複執行安全。
5. 需要觸發器時，建立可防止重複的設定與檢查函式。

### 完成

只有本機檢查、強制測試矩陣、遠端可見成果、繁體中文「執行記錄」與使用者驗收全部通過，才能宣布建立完成。

## 接管既有 Apps Script

### 從 Google 帳號選擇專案

1. 先用 `show-authorized-user` 唯讀確認 `clasp` 目前授權的 Google 帳號；帳號不符或有歧義時，交由使用者選擇及完成 OAuth。
2. 使用目前版本支援的 `list-scripts` 唯讀列出該帳號可存取的 Apps Script 專案。
3. 顯示專案名稱與足以辨識目標的非敏感資訊，讓使用者選擇；清單有同名專案或找不到目標時，才請使用者提供專案網址協助核對。Script ID 只保留在本機命令，不逐字貼進回覆、紀錄檔(Log)或 Git。
4. 使用者已提供 Apps Script 專案網址時，仍要核對它屬於目前授權帳號可存取的清單，不直接信任未驗證的 Script ID。

### 建立本機接管目錄

1. 未指定位置時，使用作業系統解析出的「文件」資料夾，在 `GoogleAppsScript/<專案名稱>` 建立安全的專案目錄；專案名稱需先轉成合法且不衝突的資料夾名稱。
2. 顯示完整本機路徑，唯讀檢查目錄是否存在及是否已有檔案。
3. 新目錄或空目錄先建立忽略規則、Git 與專案內固定版本的 `clasp`，再使用 `clone-script` 將選定的遠端專案複製到 `src/`。
4. 目錄已有檔案時不得直接 clone 或 pull 覆蓋。若它已連結同一個專案，先保護 Git 變更；若未連結或目標不同，停止並讓使用者決定改用新目錄或保留哪一份。
5. clone 完成後重新核對 `.clasp.json`、`rootDir`、`src/appsscript.json`、專案名稱與綁定目標；`.clasp.json` 必須保持在 Git 忽略清單中。

第一次抓取使用 `clone-script`；`pull` 只用於已經有正確 `.clasp.json` 的本機專案，而且執行前必須保護本機變更並取得使用者確認。

### 唯讀盤點

完成安全複製後，在任何功能修改或 `clasp push` 前確認：

1. 遠端 Apps Script 專案、本機目錄、綁定的 Google 檔案及 `.clasp.json` 是否指向同一目標；回覆中不顯示完整 Script ID。
2. Git repository、分支、既有 staged／unstaged／untracked 變更及最近版本。
3. 原始碼、`appsscript.json`、OAuth scopes、建置流程、測試與檔案結構。
4. 程式使用的 Script Properties 名稱及「已設定／未設定」，不讀出實際值。
5. 已有觸發器、部署、Web App、外部 API、進階服務及執行帳號。
6. 目前可重現的正常結果、已知錯誤與不可中斷的正式流程。

若接管目錄原本已有內容，而且本機與遠端不同，先顯示差異風險並確認哪一邊是基準，不得用強制推送或直接 pull 覆蓋其中一邊。

### 建立安全基線

1. 不改功能，先補齊 `.gitignore`、敏感資料檢查，並將剛抓取的遠端原始狀態建立為可回復的 Git 基線。
2. 為現有主要行為建立最小特徵測試或可重現驗收步驟。
3. 補上不改變業務結果的設定檢查與繁體中文紀錄檔(Log)；若這會改變 OAuth 或執行行為，先提出影響。
4. 將既有缺陷、未知行為及缺少測試的部分列為接管風險，不假裝已理解。

### 修改與完成

一次只改一個可驗收行為。每次修改都重跑原有正常案例、錯誤案例、重複執行案例與本次修正案例。只有既有功能沒有非預期退化、遠端結果已由使用者驗證，才能宣布該次接管修改完成。
