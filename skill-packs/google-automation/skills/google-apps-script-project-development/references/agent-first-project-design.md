# Agent First 專案設計

本文件只負責實作前的設計決策。測試、重複執行、紀錄檔(Log)、資料保護與觸發器細節沿用[專案品質標準](project-quality-standard.md)；操作引導沿用[UI 操作原則](ui-operation-policy.md)；權限、Git 與遠端確認沿用[安全與 GitHub](security-and-github.md)，不在此重複。

## 核心分工

Agent 負責把需求整理成可直接使用的產品流程、選擇技術架構、撰寫程式、完成工程測試與準備操作入口。使用者只需說明目標、輸入因權限或安全必須本人設定的值、確認具外部影響的動作、使用正式入口，並判斷實際成果。

## Agent First 設計摘要

寫程式前，Agent 先用白話提出一份簡短摘要，至少包含：

- 使用者平常從哪裡開始，以及完成後會看到什麼。
- 哪些準備由 Agent 完成，哪些設定或授權必須由使用者處理。
- 初始化、日常操作、工程測試與管理／清理各自使用什麼入口。
- 常用設定、資源 ID 與敏感設定分別存放在哪裡。
- 哪些動作會寫入、寄送、建立排程、部署、發布或刪除，以及各自的確認點。
- 重複執行、部分失敗或結果不確定時，如何顯示狀態並安全恢復。

使用者只需確認這套操作方式是否符合需求，不必自行決定綁定型、獨立式、觸發器或其他技術架構。

## 設計原則

1. **Agent 完成可自動化的準備**：能由程式或工具安全建立的工作表、欄位、初始格式、操作入口與測試資料，不轉成使用者的手動作業；建立遠端資源前仍依規則取得確認。
2. **提供正式日常入口**：綁定型 Google App 優先使用原生入口。Google Sheets 能用自訂選單滿足需求時，沿用專案品質標準的選單規則；不得把 Apps Script 編輯器或工程測試函式當成一般使用方式。按鈕、側邊欄、表單或 Web App 只有在更符合需求時才採用。
3. **分開不同生命週期**：初始化、日常操作、工程測試與管理／清理不得互相冒充。測試不能搶先建立正式資源，初始化不能依賴只在文件 UI 中存在的操作環境，清理功能不能混入一般入口。
4. **依使用情境放置設定**：使用者可理解且需要經常調整的非敏感設定，優先放在設定工作表、側邊欄或對話框；資源 ID 與低頻技術設定使用 Script Properties；秘密依安全規則處理。不得為了看起來專業，把所有設定都藏進 Script Properties。
5. **把安全狀態設計進流程**：所有入口預設可安全重跑並保留使用者維護的資料與版面。寄送、建立檔案或其他不可逆動作要有確認、鎖定或狀態保護；結果不確定時保留待查狀態，不得自動重試。持續運作的自動化還要提供可見的狀態、停止入口與必要的到期保護。
6. **以真實產品結果驗收**：Agent 先完成正常、錯誤與重複執行等工程測試；使用者只走一次代表性的真實流程，並在對應 Google App 判斷結果。設計前先核對 Apps Script 的服務、事件、權限與配額；不支援時說明限制並提出安全替代方案，不承諾不存在的自動化能力。

需要使用者操作網頁時，仍須依 UI 操作原則提供已核對的直接連結、正確介面名稱與預期結果。
