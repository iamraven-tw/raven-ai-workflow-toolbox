# 第一個 Sheets 自動化練習

## 完成後會看到什麼

執行 `setupLessonSheet` 後，目前的 Google 試算表會出現一個
「活動報名資料」工作表，其中包含兩筆使用目前 Google 帳號 Email 的
教學報名資料。這讓後續寄信課程可以真的寄給學員自己，不需要手動複製
地址。

這個練習刻意不使用外部 API、不建立觸發器，也不部署成公開服務。

## 開始條件

- 共用開發環境關卡已完成。
- 尚無遠端教學專案時，Agent 先顯示建立「活動報名與通知系統」Sheets 綁定專案的摘要；取得使用者確認後才建立。
- 已有教學專案時，Agent 沿用既有專案，不重建、不重問已驗證的 Google 帳號。

## Agent 與使用者操作

1. Agent 在本機準備累積程式、`00_Menu.gs` 與測試，完成語法及敏感資料檢查，並建立本機 Git commit。
2. Agent 顯示目標專案、待上傳檔案、權限與影響；使用者確認後才由 Agent 執行 `clasp push`。
3. 使用者只在第一次執行時閱讀 Google 顯示的權限內容，並完成授權。若出現「這個應用程式未經 Google 驗證」，先確認專案名稱與本課教材相符，再選擇「進階」及「前往『<教材名稱>』（不安全）」繼續；名稱或權限不符時停止。
4. 使用者重新整理試算表，從「活動報名工具」選擇「初始化活動報名資料」，再查看「活動報名資料」；需要診斷時到 Apps Script 左側「執行項目」查看相符時間。
5. `checkLesson01Settings`、`testLesson01Normal`、`testLesson01Error` 與 `testLesson01Repeat` 由 Agent 執行並保存證據，不列為學生操作。

`SpreadsheetApp.getActiveSpreadsheet()` 會取得這個綁定型專案所屬的試算表；後續建立工作表與寫入儲存格會要求修改該試算表的權限。實際授權畫面的文字可能依帳號與 Google 介面版本不同。「不安全」在這個情境表示自建教材尚未送 Google 公開驗證，不代表可以略過不明程式的警告。

## 成功標準

「活動報名資料」工作表應顯示：

| 姓名 | Email | 活動場次 | 處理狀態 |
|---|---|---|---|
| 小明 | 目前的 Google 帳號（自動帶入） | 上午場 | 待處理 |
| 小美 | 目前的 Google 帳號（自動帶入） | 下午場 | 待處理 |

實際 Email 只寫入學員自己的試算表，不會進入紀錄檔(Log)、模板或 Git。
Agent 的 `testLesson01Error` 應拒絕空白工作表名稱，而且不修改資料；
`testLesson01Repeat` 應確認結果維持相同，不會新增另一個同名工作表，
也不會在底部重複追加資料。學生不需要為此再按兩次測試函式。

## 本節要理解的三件事

- `SpreadsheetApp` 是 Apps Script 操作 Google Sheets 的內建服務入口。
- `Sheet` 代表試算表裡的一個工作表分頁。
- `Range` 代表工作表裡的一個儲存格範圍；`setValues()` 接收二維陣列。

## 檢查點

最後問學生：「哪一個紀錄檔(Log)標記代表程式已成功完成？1. `[開始]` 2. `[成功]` 3. `[失敗]`」。學生回答後公布正確答案是 2，並說明 `[成功]` 代表本次動作已完成；不論答對或答錯都可繼續下一課，不要求重答。使用者不需要親自修改程式。

## 常見錯誤

### 找不到 `setupLessonSheet`

先確認程式已推送，而且函式名稱沒有被改動。重新整理 Google Sheets 後，再查看「活動報名工具」選單；學生不需要從 Apps Script 函式選單尋找它。

### 顯示沒有權限

確認正在使用預期的 Google 帳號，並查看錯誤訊息指出的是哪個服務。不要把 OAuth 權杖或完整 Script ID 貼到教學紀錄。

### 工作表沒有變化

到 Apps Script 左側「執行項目」找到相符時間，確認 `[失敗]` 後面的中文原因，並確認目前 `.clasp.json` 對應正確的 Script 專案。
