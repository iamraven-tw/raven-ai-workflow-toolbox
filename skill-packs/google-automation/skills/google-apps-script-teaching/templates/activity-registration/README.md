# 活動報名與通知系統累積模板

第二階段使用同一個專案逐課增加功能。每一課只有完成以下條件後，才能把完整累積程式收錄為 `lesson-XX` 模板：

1. 本機語法、格式、敏感資料與回歸測試通過。
2. 已建立本機 Git commit。
3. 使用者已分別確認遠端建立及當課 `clasp push`。
4. Agent 的設定、正常、錯誤、重複與課程特有測試通過。
5. 使用者完成真正的 Google UI 操作、可見成果與繁體中文紀錄檔(Log)驗收。
6. 使用者完成當課收尾小問題。

快照必須包含當課結束時完整的 `.claspignore` 與 `src/`，不是只有該課新增的單一檔案。一般學習流程一律從第 1 課快照開始；第 2 至第 8 課由 Agent 使用 `scripts/materialize_template.py --upgrade-from`，從相鄰前課依序升級，不直接跳到後面課次。

受控升級在任何寫入前，會確認學生專案的 `.claspignore` 與 `src/` 完整符合前課已驗收快照。若前課檔案被修改、缺少、出現快照外檔案、下一課尚未驗收或課次不相鄰，工具立即停止，不會覆寫、刪除、猜測合併或重新生成程式；完整升級後重跑相同命令則安全略過。這讓技能包提供的累積程式可以直接給學生使用，同時保護學生自行加入的內容。

第二階段從第 1 課起，所有累積快照都包含 `00_Menu.gs`。共用
`onOpen(e)` 只建立 Sheets 的「活動報名工具」選單，不讀寫業務資料；
選單依目前快照中實際存在的函式顯示日常或管理入口，不顯示工程測試、
底線結尾的內部函式、安裝型觸發器回呼或 Webhook 內部處理函式。

尚未符合以上條件的課次，在 `catalog.json` 保持 `pending`，不得放入草稿程式或標記為可使用。

第 1 課的兩筆固定教學資料會自動使用目前執行者自己的 Google
帳號 Email，讓第 6 課能真的依報名資料寄送通知。實際地址只存在學員
自己的試算表，不得進入模板、紀錄檔(Log)、課程進度或 Git。第 3 課
之後新增的表單測試資料若會進入寄送流程，也必須填寫學員能親自收信的
Email；無效格式測試不得送出。第 6 課不使用 `TEST_EMAIL`，正式收件人
固定來自該筆報名資料的 Email 欄位。

課程進度不放在本累積模板內。選擇第二階段時，由 Agent 在獨立的 `GoogleAppsScript/learn-gas-course` 工作區建立或讀取統一進度，並以 `scripts/update_course_progress.py --phase 2` 更新。第二階段固定依序完成第 1 至第 8 課；中斷後從最早未完成處恢復，完成第 8 課前不得切換階段。
