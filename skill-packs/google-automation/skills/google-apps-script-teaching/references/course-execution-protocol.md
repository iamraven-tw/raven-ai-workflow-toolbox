# 活動報名與通知系統：教學執行協定

## 用途

本文件把八課學習路線轉成 AI Agent 可以逐步執行的狀態機。選擇教學模式後，Agent 先讀本文件，再只讀取目前課次的教案；不要一次把八課內容全部丟給初學者。

共用開發環境關卡由 `google-apps-script-project-development` 處理，不列入課程進度。本文件適用於第二階段第 1 至第 8 課。

## 固定專案

- 專案名稱：`活動報名與通知系統`
- 預設本機目錄：作業系統「文件」資料夾下的 `GoogleAppsScript/activity-registration`
- 統一課程進度：作業系統「文件」資料夾下的 `GoogleAppsScript/learn-gas-course/docs/course-progress.md`
- 專案類型：綁定 Google Sheets 的 Apps Script 專案
- 教學資料：假姓名、假場次，以及由學員本人可收信的 Email；第 1 課
  固定教材資料由程式自動使用目前執行者的 Google 帳號 Email
- 第一版限制：不使用付費 Workspace、進階服務、標準 Google Cloud 專案或外部付費 API

所有課程都沿用同一個本機 Git repository、同一個遠端 Apps Script 專案、同一份練習試算表與同一套報名資料。不得為每一課重新建立互不相關的專案。

第一次準備這份練習試算表時，取得遠端建立確認後，由 Agent 直接以最終教材名稱建立。不要把「建立空白試算表」與「重新命名」拆成學生步驟。Agent 建立並驗證綁定的 Apps Script 專案後，立即在目前的私人教學對話提供可點擊的 Apps Script 編輯器網址，讓學生直接開啟；不得另外顯示原始 Script ID，也不得把網址寫入教材、紀錄檔(Log)、課程進度或 Git。使用者從開啟已命名的練習試算表、完成必要設定與真實 UI 操作開始學習。

## 必要 UI 操作

已驗收模板的取用、程式維護與工程測試由 Agent 執行；使用者不需要手寫、貼上、重新生成程式或逐項執行測試函式。教學只涵蓋活動報名與通知系統實際會用到的 UI，並由使用者親自完成必要設定、授權、真實操作與成果驗證：

| UI 區域 | 使用者要學會的操作 | 主要課次 |
|---|---|---|
| Sheets `活動報名工具` | 重新整理試算表後執行目前課次真正的日常或管理功能 | 第 1 至第 8 課 |
| 上方函式選單、`執行` | 只有首次授權、除錯或沒有產品 UI 可用時才直接執行必要函式；不逐項執行工程測試 | 必要時 |
| 編輯器下方的 `執行記錄` | 閱讀從編輯器直接執行之函式的繁體中文紀錄檔(Log) | 必要時 |
| 左側 `執行項目` | 發生異常時追查 Sheets 選單、觸發器、表單、網頁應用程式與 Webhook | 除錯時 |
| `專案設定`、`指令碼屬性` | 使用 `編輯指令碼屬性`、`新增指令碼屬性`與`儲存指令碼屬性`安全輸入設定 | 第 2 課起 |
| `觸發條件` | 發生異常或需要管理時查看表單與時間觸發器 | 第 7 課選用 |
| `部署`、`新增部署作業`、`管理部署作業` | 理解 `執行身分`與`誰可以存取`，取得實際網址並封存測試 deployment | 第 8 課 |

Agent 每次只教目前步驟真的會操作的 UI；未使用的專案總覽、檔案管理、執行項目、觸發條件或部署介面不提前要求學習。Agent 預設不操作使用者的電腦或瀏覽器 UI，只有使用者明確要求時才可協助，而且不能代替使用者完成授權、具外部影響的確認或 Google 服務中的最終成果判讀。

所有 UI 引導都假設使用者沒有程式語言基礎。使用短句，一次只要求一個動作；先說要找哪個畫面，再說要按哪裡，最後只補一個成功判斷方式。

只要要求使用者開啟、切換或操作任何網頁，Agent 必須在同一則指示提供已核對且可點擊的目標連結。每次從 Apps Script 切換到 Sheets、Forms、Docs、Drive、Gmail、Web App 或其他網站驗收時，都要再次附上目的地連結；尚未取得或無法核對連結時先處理連結，不得要求使用者自行尋找頁面。

## 專案演進

Agent 依課程需要逐步增加檔案，不要求初學者理解所有檔案：

```text
activity-registration/
├── README.md
├── .gitignore
├── .claspignore
├── package.json
├── package-lock.json
├── src/
│   ├── appsscript.json
│   ├── 00_Log.gs
│   ├── 00_Menu.gs
│   ├── 01_Sheets.gs
│   ├── 02_Config.gs
│   ├── 03_Forms.gs
│   ├── 04_Batch.gs
│   ├── 05_Documents.gs
│   ├── 06_Gmail.gs
│   ├── 07_Triggers.gs
│   └── 08_WebApp.gs
└── tests/
    └── README.md
```

這條初學路線使用 Apps Script 原生 `.gs` 檔，避免先加入 TypeScript 編譯負擔；程式仍需拆分、加入繁體中文註解並保留可測試的純函式。實際專案需要工程化時再改用 TypeScript。

拆檔以功能為單位，不把全部程式放進單一檔案，也不為每個小函式或測試案例建立新檔案。共用紀錄檔(Log)放在 `00_Log.gs`，共用 `onOpen(e)` 與累積選單放在 `00_Menu.gs`，各課功能與其測試輔助函式集中在對應的 `01_` 至 `08_` 檔案。需要多個測試案例時，優先提供一個給 Agent 使用的測試總入口；內部測試函式以底線結尾，標示為 private，不把測試入口當成學生操作。

## 課程進度狀態

Agent 在獨立課程工作區的 `docs/course-progress.md` 只記錄不含私人 ID 或個資的狀態：

學員選擇第二階段時，Agent 執行 `scripts/update_course_progress.py --select-phase 2`；工具會在第一次自動建立涵蓋兩階段的統一進度，已有檔案就完整保留。若另有統一進度推出前的舊版第一階段紀錄，Agent 只在核對明確完成證據後使用 `--import-legacy-progress` 受控匯入；不得把 `validated` 模板狀態當作學員完成證據，也不得手動改表格。第二階段開始後固定依序完成第 1 至第 8 課，完成第 8 課前不得切換階段或跳過未完成課次。之後每次有證據的狀態轉換都以 `--phase 2` 更新。學生不需要手動建立或編輯本檔；單純下載技能包不會自行執行程式。

| 狀態 | 意義 |
|---|---|
| `not_started` | 尚未開始 |
| `local_ready` | 本機程式與測試通過，已有本機 Git commit |
| `awaiting_push_confirmation` | 已顯示推送摘要，等待使用者確認 |
| `ui_validation` | 已推送且 Agent 工程測試通過，正在進行學生真實 UI 驗收 |
| `blocked` | 發現錯誤，留在本課依全域除錯流程處理 |
| `completed` | 可見結果、Agent 測試與檢查點都有證據；失敗時另有紀錄檔(Log) |

不得只因檔案已建立、`clasp push` 沒有報錯或編輯器已出現程式，就把課程標記為 `completed`。

每次開始教學時，Agent 依序檢查：

1. 統一課程工作區 `docs/course-progress.md` 的第二階段記錄。
2. Git 最新 commit 與工作目錄是否乾淨。
3. 本機目前存在的課程檔案。
4. `clasp status` 顯示的待推送檔案。
5. 上一課是否已有遠端可見結果與測試證據。

如果記錄與實際狀態不一致，以可驗證的本機與遠端證據為準，修正記錄後才繼續。

## 每課固定對話循環

### A. 課程簡介關卡

每一課都先用一小段白話簡介，並在任何遠端建立摘要、Script Properties 填寫、`clasp push` 確認、授權或學生 UI 操作之前完成。Agent 必須告訴使用者：

1. 目前是第幾課，以及這課要解決什麼問題。
2. 完成後會看到什麼真實成果。
3. 本課如何沿用前課的資料或資源，以及在完整活動報名流程中負責哪一段。
4. Agent 會寫與測什麼，使用者稍後會在哪個 Google UI 親自使用並驗收。
5. 本課需要哪些 Google 服務、遠端資源、設定與權限，執行時會造成什麼影響。
6. 要用哪些畫面結果與繁體中文紀錄檔(Log)判斷成功。

需要資源 ID 或其他設定時，Agent 還要先逐項說明資源是由誰建立或從哪一課沿用、程式為什麼需要它，以及為什麼放進 Script Properties。Google 資源 ID 要用「門牌號碼」比喻，說明它所在的網址區段；完成原因說明後，才可提供屬性名稱、完整 ID 或 UI 填寫步驟。

這是不得跳過的教學關卡。即使遠端資源已建立、程式已推送，或學生已回覆「設定完成」，只要本課沒有已提供簡介的證據，就要先補上簡介，再從未完成的檢查點接續。若已有證據則不重複整段。簡介不是額外確認點，不要停下詢問是否理解；說明後直接進入原本應有的實作或確認流程。

每次推送到Apps Script(clasp push)成功後，第一次交付學生操作仍要在同一則訊息先提供「精簡課程回顧」。即使完整簡介已有證據，也要重述本課功能、可見成果、目前設定或操作為什麼必要，以及這一步尚不會執行或造成的外部影響，之後才列 UI 步驟。不得只剩操作步驟，也不得以這段精簡回顧取代本節要求的完整課程簡介。

不要一開始貼出整課程式、八課列表或大量背景知識。

### B. 本機實作

Agent：

1. 檢查 Git 狀態與上一課成果。
2. 查 `templates/catalog.json`。第 1 課已有 `validated` 累積快照時，使用 `scripts/materialize_template.py` 一般複製；第 2 至第 8 課使用同一工具的 `--upgrade-from`，只從相鄰前課快照受控升級。工具必須在任何寫入前證明目前專案完整符合前課快照；檔案遭修改、缺少、出現快照外 `src/` 檔案、目標未驗收或課次不相鄰時立即停止。不得覆寫學員內容、手動合併、跳課或依教案重新生成。
3. 目前課次仍為 `pending` 時，只有使用者明確要求維護 Toolbox 的 Google 自動化技能包，才只修改本課需要的程式、測試與文件；一般學習流程必須停止並回報模板尚未發布。
4. 確認統一課程進度已由選階段流程建立；已有進度時不得用空白範本覆寫。
5. 加入必要的繁體中文註解。
6. 執行語法、格式、本機可執行測試與 `clasp status`。
7. 搜尋憑證、Token、私人 ID、真實 Email 及其他個資。
8. 通過後只提交本課變更，建立本機 Git commit。
9. 使用 `scripts/update_course_progress.py --phase 2` 記錄 `local_ready` 或下一個實際狀態；不得手動填入私人 ID、網址、Email、秘密或私人絕對路徑。

如果測試失敗，使用 `google-apps-script-debugging`，不得先要求使用者推送試試看。

### C. Script Properties 檢查

每課都要有 Script Properties 檢查點，但不得為了形式建立沒有用途的屬性：

- 本課需要新屬性：列出名稱、用途、敏感性與設定位置。
- 本課沿用既有屬性：驗證「已設定／未設定」，不輸出值。
- 本課不需要屬性：明確記錄「本課沒有必要的 Script Properties」，並確認程式沒有硬寫私人 ID 或秘密。

第一次要求使用者設定 Form ID、Spreadsheet ID、Document ID、Folder ID 或其他 Google 資源 ID 前，Agent 必須先說明原因：ID 是讓程式找到同一份 Google 資源的「門牌號碼」；放在指令碼屬性可讓可變設定與程式碼分開、換資源時不必改程式，並避免私人 ID 進入原始碼、紀錄檔(Log)或 Git。說明完成後才進入 UI 填寫，不得只丟出屬性名稱與值。

實際值只由使用者在 Apps Script 輸入：左側點擊「專案設定」，找到「指令碼屬性」，依序使用「編輯指令碼屬性」、「新增指令碼屬性」及「儲存指令碼屬性」。若一般 Google 資源由 Agent 建立，Agent 必須從已核對網址擷取並直接提供完整 ID，不得要求學生自己拆網址；只有使用者原有或親自建立的資源，才由使用者主動貼 URL 給 Agent 協助擷取與整理。Agent 都要說明 ID 位於 URL 的哪一段。API Key、Token、密碼及其他敏感值不得要求使用者貼進對話，只提供屬性名稱讓使用者自行輸入。唯一教學例外是第 8 課：Agent 使用本機安全亂數產生一組只供當次課程使用的 `WEBHOOK_TOKEN` 臨時教學密語，在私人教學對話顯示一次並說明它不適合正式使用；學生親自填入且不得回傳。紀錄檔(Log)、Git、測試與課程進度一律不得保存實際值。

### D. 推送到Apps Script(clasp push) 確認

每一課的程式都必須先完成本機驗證與 commit，才可提出推送確認。Agent 先在內部核對：

- 本機專案絕對路徑。
- 遠端專案名稱與綁定類型；除了首次建立教學專案時已交付的可點擊編輯器網址，Script ID 只在本機核對，不逐字顯示。
- 本課 Git commit。
- `clasp status` 的待推送檔案摘要。
- 新增或改變的 Google 服務與 OAuth 權限。
- 明確寫出「只更新程式，不會部署、不會建立觸發器、不會寄信」，或列出真正會發生的其他影響。

對初學者不要先展示上述工程清單。第一次出現 `clasp push` 時，以目前教材名稱代入以下說法：

> 教學範例程式已經寫好了。接下來由 Agent 使用 `clasp` 套件，把本機已完成並通過測試的程式與資訊清單同步到「教材名稱」的 Google Apps Script 專案。這一步只更新遠端程式，不等於執行函式、寄信、建立觸發器或部署；你不需要操作終端機。這個動作稱為「推送到Apps Script(clasp push)」。你同意我現在推送到Apps Script嗎？

後續再次推送時可以省略完整定義，但所有面向學生的確認、進度與結果仍使用「推送到Apps Script(clasp push)」，並用短句說明目標教材與本次影響；不得只顯示英文命令。只有使用者追問技術細節時，才顯示 commit、路徑、檔案與權限摘要。

沒有使用者明確同意，不得執行 `clasp push`。確認只適用於當次摘要；後續課程需再次確認。

### E. 使用者 UI 驗收

推送並完成 Agent 工程測試後，Agent 引導使用者本人完成下列 UI 操作：

1. Agent 在同一則回覆先提供精簡課程回顧，再提供已核對的試算表連結，並一次說完：開啟或回到試算表 → 重新整理 → 選擇「活動報名工具」→ 選擇當課項目。只有當下步驟必須直接操作 Apps Script 時，才改為重新整理 Apps Script 編輯器並提供完整 UI 路徑；不得停在重新整理後要求使用者先回覆「已重整」。
2. 第一次執行前，用一句話說明函式(function)是 AI 代理(Agent)寫好的一個「有名字的動作」。
3. 若下一步是必要函式，Agent 先說明檔案、函式、用途與預期結果；若已有自訂選單、按鈕或表單，直接使用日常入口。
4. 下一步是必要函式時，合併操作使用固定句型：「請先重新整理 Apps Script 編輯器，等左側「檔案」重新載入後，選擇 `<檔案名稱>`，再到上方函式選單選擇 `<函式名稱>`，最後按「執行」。」不得只說「選擇函式」而省略重新整理與檔案位置。
5. 使用者依序完成上述操作；Sheets 選單是正常產品入口，Apps Script 函式選單只供必要設定、授權或除錯。
6. 第一次需要授權前，Agent 先說明預期權限類型、用途與可以同意的理由，並預告自建教學範例可能出現「這個應用程式未經 Google 驗證」。若畫面上的專案名稱與目前教材相符，使用者選擇「進階」，再選擇「前往『<教材名稱>』（不安全）」繼續授權；若只想離開則可選「返回安全的位置」。專案名稱不符、權限不符或沒有預期的繼續選項時立即停止並回報。
7. 完成一個代表真實使用方式的 UI 流程。
8. 回到對應的 Sheets、Forms、Drive、Docs、Gmail 或 Web App 查看可見結果。
9. 只有結果錯誤或沒有出現時，才到本次入口對應的「執行記錄」或「執行項目」取得診斷文字。

Agent 預設只用文字指出操作位置，不操作使用者的 UI。只有使用者明確要求時才可協助開啟頁面；不得代替使用者完成授權、具外部影響的確認或最終成果判讀。OAuth、CAPTCHA、兩步驟驗證及權限同意也必須由使用者完成。

案例已有 Sheets 自訂選單、按鈕或其他日常入口時，學生的正常使用驗收必須走該入口，不能用 Apps Script 測試函式取代。測試函式只供 Agent 驗證或除錯，也不得在日常入口第一次建立成果前搶先建立永久表單、文件或其他資源。教師隨機測驗案例的固定順序是：`checkQuizBank` 通過 → Sheets 的 `測驗工具`建立第一份測驗 → 設定並檢查 `QUIZ_FORM_ID` → 學生預覽與作答；`testQuizNormal` 由 Agent 執行。

第二階段從第 1 課開始就使用共用 `onOpen(e)` 建立 Sheets 的「活動報名工具」選單，之後每課累積真正的操作入口。固定學生順序改為：開啟 Agent 提供的試算表連結 → 重新整理試算表 → 選擇「活動報名工具」→ 選擇當課項目 → 檢查 Sheets／Forms／Docs／Gmail／Web App 可見結果；需要診斷時再到 Apps Script 左側「執行項目」找相符時間的執行。只有指令碼屬性、首次授權、部署、安裝型觸發器管理或除錯沒有產品 UI 可用時，才引導學生進 Apps Script 編輯器。

每個學生步驟都要能回答「這對真實使用有什麼幫助」。為了蒐集工程證據而反覆檢查觸發器數量、技術狀態、執行項目或紀錄檔(Log)，一律由 Agent 負責；正常成功時不得列成學生的額外回報關卡。狀態入口保留給日後管理與除錯，不作為每次啟用後的必做驗收。

`onOpen(e)` 只建立選單，不執行業務寫入。Agent 在第一次導入時必須把簡單觸發器與選單項目列入設計摘要並取得確認；確認後不需要在 Google UI 安裝觸發器。第 7 課的安裝型表單／時間觸發器仍須分別確認建立、真實執行與刪除，不能用這次 `onOpen(e)` 的確認代替。

執行正常時只要求使用者回覆簡短結果。執行失敗時，請使用者從本次入口對應的「執行記錄」或「執行項目」複製文字訊息，不要求截圖或先自行解釋；只有無法用文字呈現的介面問題才改用截圖。

### F.紀錄檔(Log)判讀

每個主要入口至少有：

- `[開始]`：正在處理什麼。
- `[設定]`：必要屬性是否齊全。
- `[成功]`：實際完成數量或結果。
- `[失敗]`：失敗步驟、中文原因及下一個檢查動作。

依需要加入 `[進度]`、`[略過]` 與 `[警告]`。紀錄檔(Log)不得出現 Script Properties 實際值、完整 Webhook 內容、完整郵件本文或不必要的個資。

### G. 驗收與檢查點

每課至少完成：

1. Agent 完成正常測試。
2. Agent 完成錯誤測試，並證明錯誤發生後沒有繼續寫入。
3. Agent 完成重複執行測試，並證明沒有重複業務結果。
4. Script Properties 檢查。
5. 可見結果。
6. Agent 已確認繁體中文紀錄檔(Log)可供診斷；只有學生操作失敗時才要求貼回。
7. 使用者親自完成本課指定的真實 UI 操作。
8. 一題與本課核心概念有關的收尾小問題；優先讓使用者只回覆選項數字。

第 4 課由 Agent 另測零筆、一筆與多筆。第 7 課由 Agent 完成模擬測試，學生驗收一次真實觸發。第 8 課由 Agent 完成本機測試；取得實際請求確認後，由 Agent 使用 `scripts/run_lesson08_webhook_tests.py` 的隱藏輸入安全取得公開網址與臨時教學密語，直接對部署網址測試正常、錯誤及重送請求，學生查看 GET、試算表與「執行項目」結果。網頁應用程式(Web App)部署不是可執行 API 部署，不得預設使用 `clasp run`、另建可執行 API 部署或把測試函式交給學生執行。

真實寄信、觸發器或部署需要學生帳號授權時，學生只執行一次真正的使用流程；這次結果補足遠端整合證據，正常／錯誤／重複等測試矩陣仍由 Agent 負責。

教學若暫時使用每分鐘等高頻觸發器，不能只用文字提醒學生稍後關閉。教材必須同時具備：

- 由學生親自在真正的 Sheets 選單或 Apps Script UI 啟用。
- 啟用後立刻在同一則教學指示引導學生產生測試事件、等待並查看結果；「已啟用」不是需要停下回報的檢查點。
- 顯示目前是否啟用與安全期限。
- 提供清楚的停止入口，並在驗收後立即引導學生關閉。
- 設定短暫的程式自動到期保護，學生忘記操作時也不會無期限耗用配額。
- 若對學生承諾整次啟用只建立一份文件或寄一封信，必須在外部動作前
  留下單次嘗試記號，完成、結果不確定或錯誤後立即停止相應時間觸發器；
  不得把每次執行的批次上限誤當成整段啟用期間的總上限。
- 說明高頻設定只為縮短教學等待；正式使用需依需求改用較長間隔。
- 驗收與清理後核對[Google Apps Script 官方配額](https://developers.google.com/apps-script/guides/services/quotas)，說明觸發器每日總執行時間按建立者帳號跨專案加總，不是每個專案各有一份額度。
- 列出正式使用可選的時間間隔與每日執行次數，用該函式的實際平均執行時間及同帳號其他自動化共同估算；不得把理論上限直接當成安全值。

學生回答收尾小問題後，Agent 必須公布正確答案並用白話說明它和本課操作的關係。這不是考試，不論答對或答錯都算完成檢查點；不得要求重答或因答錯阻擋進度。完成本課的進度、模板與本機提交後，Agent 直接開始下一課，不詢問是否繼續，也不提供切換階段選項。

完成後，Agent 使用 `scripts/update_course_progress.py --phase 2` 將本課更新為 `completed`，通過檢查後建立只記錄本課驗收狀態的學生專案本機 commit。

若目前是使用者明確授權的 Toolbox Google 技能包維護流程，還要把當課結束時完整累積的 `.claspignore` 與 `src/` 收錄到 `templates/activity-registration/lesson-XX`，在 `templates/catalog.json` 記錄來源 commit、檔案清單並將狀態改成 `validated`，通過 `scripts/validate_skills.py` 後再建立 Toolbox 本機 commit。一般學生專案不得反向修改技能包。

## Script Properties 演進

| 屬性 | 首次使用 | 用途 | 是否敏感 |
|---|---|---|---|
| `SPREADSHEET_ID` | 第 2 課 | 指定練習試算表 | 否，但不公開 |
| `FORM_ID` | 第 3 課 | 指定活動報名表單 | 否，但不公開 |
| `DOC_TEMPLATE_ID` | 第 5 課 | 指定文件範本 | 否，但不公開 |
| `OUTPUT_FOLDER_ID` | 第 5 課 | 指定測試輸出資料夾 | 否，但不公開 |
| `WEBHOOK_TOKEN` | 第 8 課 | 驗證測試 Webhook | 是 |
| `WEB_APP_URL` | 第 8 課 | 指定實際部署的 `/exec` 測試網址 | 否，但不寫入程式、紀錄檔(Log)或 Git |

屬性名稱可以進入 Git；實際值不得進入原始碼、測試、紀錄檔(Log)或 Git。一般 Google 資源 URL／ID 等非敏感設定，若資源由 Agent 建立，Agent 必須在重新核對後直接於目前的私人教學對話提供可點擊網址、ID 所在的網址區段、可複製的完整 ID，以及逐欄填寫「指令碼屬性」的步驟；不得要求學生自己找網址或貼回來。若是使用者原有的資源，才由使用者主動提供 URL 給 Agent 協助擷取與整理。除了第 8 課由 Agent 顯示一次且明確標示不適合正式使用的 `WEBHOOK_TOKEN` 臨時教學密語，API Key、Token、密碼及其他敏感值不得貼進對話；Google 帳號密碼、OAuth access token 與 refresh token 永遠不得存入 Script Properties。第 8 課還要教學生日後可改用密碼管理器、本機安全產生器或 `openssl rand -hex 32` 自行建立正式值，且不得重用既有密碼或其他服務秘密。

第 7 課每次只處理一筆是程式內建的安全限制，不是學員設定；不得要求
學員新增固定值用的 `PROCESSING_BATCH_SIZE`。
