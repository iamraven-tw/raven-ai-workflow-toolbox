# Google Apps Script 教學工作流程

## 教學目標

已驗收程式模板的取用、程式維護與工程測試由 AI Agent 負責，學習者不需要手寫、貼上、重新生成程式或逐項執行測試函式。教學目標是讓使用者在活動報名與通知系統的實作流程中，學會當下必要的設定、授權與真實 UI 操作，能判斷 Google 服務中的實際成果是否正確，並知道遇到錯誤時應該先查看哪一個介面。沒有實際用到的介面不列入教學。

所有教學文字都假設使用者完全不懂程式語言。優先使用生活化比喻、短句與畫面位置；一次只說明目前要做的動作，避免連續講解多個名詞或提供長篇背景知識。

所有面向學生的技術術語都依[初學者術語規則](../../learner-facing-terminology.md)，先說明目前用途，再使用「中文名稱(English)」。固定稱為「紀錄檔(Log)」，不得只顯示英文術語或縮寫；程式碼、命令、檔名與 Google 介面正式文字維持原文並另作中文說明。

## 開始前判斷

整組技能第一次使用且使用者尚未指定目的時，先由 `google-apps-script-project-development` 詢問要做專案或學習。使用者選擇學習後，只先列出「第一階段：五個生活應用」與「第二階段：活動報名與通知系統」兩個選項。兩者沒有先修限制，讓學員在開始前自由選擇；未選定前不預設階段。使用者已明確指定階段時直接沿用，不重複提問。進入第二階段後不再顯示階段選單。

階段選定後，Agent 先在作業系統「文件」資料夾下的 `GoogleAppsScript/learn-gas-course` 執行 `scripts/update_course_progress.py --select-phase`，自動建立或讀取統一進度，再由 `google-apps-script-project-development` 完成共用開發環境關卡。共用環境關卡不是教學課程，也不列入第一或第二階段。

選擇教學模式後，再判斷使用者屬於哪一種情境：

1. **完全初學**：仍由學員自由選階段。選第一階段時從生活應用開始；選第二階段時由 Agent 多補充當課必要的白話說明，不強迫先完成第一階段。
2. **會寫程式但沒用過 Apps Script**：快速介紹執行環境、Google 服務、授權、配額與觸發器。
3. **已有免費基礎自動化需求**：把真實需求拆成小節，以實際專案教學；先確認輸入、輸出、內建服務與執行入口。
4. **已有基礎專案要維護**：先讀取現有程式、資訊清單與同步設定，再用現有架構解說。

如果使用者未提供程度，先視為初學者，但不替他選擇階段。階段確定後由 Agent 唯讀檢查既有開發環境；完整就直接沿用，缺少時才補齊，再進入所選階段最早未完成的項目。

教學案例、Script Properties、中文紀錄檔(Log)與測試的詳細規格統一使用 [教學案例與共同規格](teaching-examples.md)。

## 第一版兩層教學路線

第一階段是生活應用入門課程。每個案例以一個主要 Google App 為核心；必要時允許另一個 App 擔任資料來源。函式、執行記錄及 Script Properties 都在案例第一次需要時才教，不獨立成沒有情境的課程。

第二階段才進入以下整合專案課程：

1. Sheets 基礎讀寫。
2. Script Properties 與設定檢查。
3. Forms 收集資料與資料驗證。
4. Sheets 批次處理資料。
5. Docs／Drive 產生文件。
6. Gmail 寄送報名通知。
7. 表單或時間觸發器。
8. 簡單 Web App／Webhook。

不提供進階選修。使用者若提出進階服務、付費方案、Workspace 管理員、Google Chat App、Add-on、外部 API 或標準 Google Cloud 專案需求，將其記為下一版候選，不中斷目前基礎教學。

八課使用同一個「活動報名與通知系統」逐步擴充：

- 報名資料收集：Forms、Sheets、資料驗證與表單觸發器。
- 文件與通知產生：Sheets、Docs、Drive、Gmail 測試郵件與批次處理。
- 外部資料入口：Web App、Webhook、Sheets 與錯誤回應。

實際帶課時完整遵循 [活動報名與通知系統：教學執行協定](course-execution-protocol.md)。Agent 先判斷目前課次，再只讀取該課教案；不得一次把八課程式與操作全部交給初學者。

## 每一節的固定結構

每節都使用以下順序：

每課狀態使用 `not_started`、`local_ready`、`awaiting_push_confirmation`、`ui_validation`、`blocked` 或 `completed`。只有 Agent 工程測試、必要的 Script Properties、學生一次真實 UI 操作、可見結果與使用者檢查點都有證據時，才能標記完成。繁體中文紀錄檔(Log)必須可供 Agent 診斷，但正常成功時不要求學生另外貼回。

學員第一次選擇任一階段時，`scripts/update_course_progress.py --select-phase` 會在獨立課程工作區自動建立涵蓋兩階段的 `docs/course-progress.md`；已有檔案時完整保留。若學員在統一進度推出前已有分散的舊版 Markdown 進度，Agent 先核對舊檔中的明確 `completed` 狀態或「五個案例均已完成」總結，再使用 `--import-legacy-progress` 受控匯入第一階段；工具只更新 `not_started`，遇到進行中的統一進度或無法辨識的舊檔就會在寫入前停止。不得因模板是 `validated`、對話記憶或模糊文字自行推定完成，也不得手動改進度表。選擇第二階段後，進度工具會鎖定第 1 至第 8 課的順序，完成第 8 課前拒絕切換階段或跳過未完成課次。Agent 在每次有證據的狀態轉換後使用同一工具更新，重跑相同內容時安全略過。學生不需要建立或編輯進度檔；單純下載技能包不會自行執行程式。

### 0. 課程簡介關卡

Agent 在每個第一階段案例與第二階段課次開始時，必須先提供一段精簡、可獨立理解的課程簡介。這段簡介要出現在任何遠端建立摘要、Script Properties 填寫、`clasp push` 確認、授權或學生 UI 操作之前，至少包含：

1. 本課要解決的生活或工作問題，以及完成後看得到的成果。
2. 這項功能在真實使用時的用途；第二階段另說明它如何沿用前課成果。
3. Agent 會準備與測試什麼，學生稍後會在哪個 Google UI 操作與驗收。
4. 本課會用到的 Google 服務、遠端資源、設定與可能的外部影響。
5. 學生要用哪些可見結果判斷成功；只有失敗時才說明到哪裡取得繁體中文紀錄檔(Log)。

若本課需要資源 ID 或其他設定，簡介還要在列出屬性名稱、值或填寫步驟之前，逐項說明資源由誰建立或從哪一課沿用、程式為什麼需要它，以及為什麼放在 Script Properties。Google 資源 ID 要再用「門牌號碼」比喻並說明網址區段。資源已經建立、程式已經推送或學生已經完成設定，都不能成為跳過原因；若中斷恢復時查不到本課簡介已提供的證據，就先補上簡介再繼續。

課程簡介本身不是新的授權或停等點。說明完成後，Agent 仍依既有規則，在遠端建立、每次 `clasp push`、觸發器、真實寄信與部署等操作前分別取得確認。

第一階段與第二階段在每次推送到Apps Script(clasp push)成功後，第一次交付學生操作時都要在同一則訊息先提供「精簡課程回顧」。即使完整簡介已在較早訊息出現，也要重述本課功能、可見成果、目前設定或操作為什麼必要，以及這一步尚不會執行或造成的外部影響，之後才列 UI 操作。這讓推送後的指示可以獨立理解；不得只剩設定、重新整理、選單、授權或部署步驟，也不得把精簡回顧當成課程開始時完整簡介的替代品。

### 1. 本節成果

用一句話描述完成後看得到的結果，例如：「執行函式後，試算表會新增『活動報名資料』工作表並寫入兩筆假資料。」

### 2. 核心概念

只解釋完成本節必須知道的介面操作與 1 至 3 個 Apps Script 概念。第一次實際用到 Apps Script 專有名詞或 UI 區域時，用白話補充用途；不為了完整介紹介面而增加無關操作。

第一次出現 `clasp` 時，固定用以下概念說明：

> `clasp` 套件是 Agent 用來把電腦裡寫好的程式送到 Google Apps Script 的小工具。你不需要操作它。

第一次出現 `clasp push` 時，接著固定說明：

> 接下來，Agent 會把電腦裡已完成並通過測試的程式與資訊清單，同步到指定的 Google Apps Script 專案。這只會更新遠端程式，不等於執行函式、寄信、建立觸發器或部署；你不需要操作終端機。這個動作稱為「推送到Apps Script(clasp push)」。

後續面向學生的確認、進度與結果一律使用「推送到Apps Script(clasp push)」，不得只顯示英文命令。終端命令、程式碼區塊與 Agent 內部工程檢查仍可使用原始 `clasp push`。

第一次出現「函式(function)」時，固定用以下概念說明：

> 函式可以先想成一個「有名字的動作」。Agent 已經把動作內容寫好，你只要選擇它的名稱，再按「執行」。

### 3. Agent 與使用者操作

- 程式、終端機命令與本機檔案預設由 Agent 處理。
- 案例或課次已有 `validated` 模板時，Agent 先從 `templates/catalog.json` 核對來源，再使用 `scripts/materialize_template.py` 取用已驗收程式；不得根據教案重新寫一份相似程式。第一階段案例與第二階段第 1 課使用一般複製；第二階段第 2 至第 8 課必須加上 `--upgrade-from`，從相鄰前課快照受控升級。
- 第二階段受控升級會先完整比對前課受控檔案，全部相符才一次更新至下一課；若檔案被修改、缺少、`src/` 有快照外檔案、目標未驗收或企圖跳課，Agent 立即停止，不得覆寫、刪除、手動合併或重新生成。已完整升級的相同命令可安全重跑並略過。
- 模板狀態是 `pending` 時，不得把草稿交給一般學習者。只有正在維護 Toolbox 的 Google 自動化技能包、且使用者已明確要求完成該課時，Agent 才實作一次；完整驗收後把當時累積程式收錄為模板。
- 統一課程進度與各案例／整合專案分開存放。Agent 使用受控工具記錄所選階段及已驗證狀態；不得覆寫既有進度，也不得記錄私人 ID、網址、Email、秘密或私人絕對路徑。
- Git 預設由 Agent 管理；每個通過驗證的課程修改主動建立本機 commit，除非使用者明確指示不用 Git。
- Agent 在本機完成程式、測試及待上傳檢查；使用者確認目標後，才由 Agent 執行「推送到Apps Script(clasp push)」。
- Agent 在學生操作前完成正常、錯誤、重複執行及課程特有的工程測試；測試函式可以保留供 Agent 驗證與除錯，但不是學生的例行操作。
- 使用者親自完成必要的初始化／設定函式、授權與案例真正的日常 UI 操作，並到對應的 Google 服務檢查成果。
- Agent 預設只用文字逐步指出 UI 位置與成功判斷方式，不操作使用者的電腦或瀏覽器；只有使用者明確要求時才協助操作，而且不能代替使用者完成教學驗證。
- 教學專用的全新 Google 練習檔案由 Agent 在取得遠端建立確認後，以最終教材名稱直接建立。建立空白檔案與重新命名是課前準備，不拆成學生操作；學生從開啟已命名檔案、進入 Apps Script 及後續真實操作開始學習。
- 第一次建立並驗證綁定的教學 Apps Script 專案後，Agent 立即在目前的私人教學對話提供可點擊的 Apps Script 編輯器網址，讓學生直接開啟。不得另外顯示原始 Script ID，也不得把網址寫入教材、紀錄檔(Log)、課程進度或 Git。
- 只要下一步要求學生開啟、切換或操作網頁，Agent 在同一則指示提供已核對且可點擊的目標連結。從 Apps Script 回到 Sheets、Forms、Docs、Drive、Gmail 或其他服務驗收時，也必須重新附上目的地連結；尚未取得或無法核對時先處理連結，不要求學生自行尋找。
- Agent 依功能拆分程式，但控制檔案數量；共用功能使用共用檔，每課主要功能集中在一個對應檔案，測試輔助函式優先留在同一功能檔。
- 只有首次授權、指令碼屬性設定、除錯或沒有實際產品 UI 可用時，才請使用者直接執行必要函式；此時先用短句列出「檔案、函式、用途、預期結果」，再使用固定操作句型：「在 Apps Script 左側『檔案』選擇 `<檔案名稱>`，再到上方函式選單選擇 `<函式名稱>`，最後按『執行』。」不得只說「選擇函式」而省略檔案位置。
- 第二階段是綁定 Google Sheets 的實際累積專案，從第 1 課開始就以共用 `onOpen(e)` 建立「活動報名工具」選單；每課把真正的日常或管理入口累積加入同一選單。學生重新整理試算表後從選單操作，不以 Apps Script 函式選單作為日常產品介面。工程測試、底線結尾內部函式、安裝型觸發器入口與 Webhook 內部處理函式不得出現在選單。
- `onOpen(e)` 只負責建立選單，不讀寫業務資料。它是簡單觸發器，不等同第 7 課另外建立的安裝型表單／時間觸發器；安裝、刪除與真實背景執行仍必須各自取得確認。除非按鈕本身是明確需求、教學目標，或自訂選單無法滿足需求，不得要求學生插入圖片、繪圖或指派指令碼。
- 案例已有 Sheets 自訂選單、按鈕或其他日常入口時，學生的正常使用與驗收必須使用該入口；Apps Script 的 `Tests` 只供 Agent 驗證或除錯，不列為學生步驟，也不得在日常入口第一次建立成果之前搶先產生永久資源。教師隨機測驗案例在 `checkQuizBank` 通過後，由學生使用 Sheets 的 `測驗工具`建立第一份表單，設定並檢查 `QUIZ_FORM_ID`，之後直接預覽、作答與更新成績報表。
- Script Properties 的實際值由使用者在 Apps Script「專案設定」的「指令碼屬性」中輸入。Agent 引導時使用畫面上的「編輯指令碼屬性」、「新增指令碼屬性」及「儲存指令碼屬性」。若非敏感 Google 資源由 Agent 建立，Agent 必須從已核對的網址擷取並直接提供完整 ID，不得把擷取工作交給學生；只有使用者原有或親自建立的資源，才由使用者主動提供 URL，讓 Agent 協助擷取、整理並解釋來源位置。敏感值只提供屬性名稱與用途，不要求使用者貼進對話；只有第二階段第 8 課的 `WEBHOOK_TOKEN` 依下方教學例外提供一次臨時值。
- 一次只提供目前階段的操作。
- Agent 預設不操作目標介面；只有使用者明確指定時才協助操作。無論是否協助 UI，程式都由 Agent 在本機維護，不要求使用者複製、貼上或修改程式。
- 程式碼加入必要的繁體中文註解。

### 4. 權限說明

若本節會出現 OAuth 授權畫面，執行前先說明：

- 哪一個即將執行的動作會觸發授權。
- 程式需要讀取或修改的資料。
- 本節不需要哪些更廣的權限。
- 授權畫面文字可能因帳號與 Google 介面版本不同而異。

教材已經知道預期權限時，直接告訴學生：若畫面顯示的專案、帳號與權限類型符合上述說明，就依畫面選擇自己的帳號並按「允許」或「同意」。不要先要求學生打字轉述授權畫面。只有出現未說明的權限、警告、管理員阻擋或沒有可繼續的按鈕時，才請學生用一句短話或截圖回報。

第一次執行每一個自建教學範例時，都要在學生按「執行」前預告以下固定流程：

1. Google 可能顯示「這個應用程式未經 Google 驗證」，以及「進階」和「返回安全的位置」。
2. 先核對畫面上的專案名稱與目前教材完全相符；這代表正在授權自己剛建立的教學程式。
3. 名稱相符時選擇「進階」，再選擇「前往『<教材名稱>』（不安全）」繼續，之後依預期權限按「允許」或「同意」。
4. 「不安全」在這個情境表示自建教材尚未送 Google 公開驗證，不代表任何未確認的程式都可以略過警告。專案名稱不符、帳號不符或權限超出教材說明時，立即停止並回報。

不得要求使用者貼出權杖、OAuth 憑證、Script ID 或完整含個資的錯誤畫面。

### 5. Script Properties

若本節需要 Spreadsheet ID、Form ID、文件範本 ID、Folder ID、測試信箱、API Key 或第三方 Token：

- Agent 先說明屬性名稱、用途及是否敏感。
- 第一次設定 Google 資源 ID 前，Agent 先用白話說明：ID 像該資源的「門牌號碼」，程式靠它找到並持續更新同一份表單、試算表、文件或資料夾；放進指令碼屬性可讓設定與程式碼分開，日後換資源只改設定，也避免私人 ID 進入原始碼、紀錄檔(Log)或 Git。這段原因必須在 UI 填寫步驟之前說明，不得只提供屬性名稱與值。
- 實際值不得寫進程式碼、測試、紀錄檔(Log)或 Git。
- Agent 不得要求使用者把敏感值貼進對話。第二階段第 8 課是唯一教學例外：Agent 使用本機安全亂數產生一組只供當次課程使用的「臨時教學密語」，在私人教學對話中顯示一次，明確提醒它因已出現在對話而不適合正式使用；學生只需親自填入，不得回傳。Agent 不得將臨時值寫入程式碼、測試、紀錄檔(Log)、Git 或課程進度，並要列出密碼管理器、本機安全產生器與 `openssl rand -hex 32` 等日後自行產生正式值的方法。
- 一般 Google 資源 URL／ID 等非敏感設定，若資源由 Agent 建立，Agent 先重新核對目標，再直接提供可點擊網址、說明 ID 位於 URL 的哪一段、提供可複製的完整 ID，最後逐欄說明如何填入「指令碼屬性」；不得要求學生自己找網址或把網址貼回來。只有使用者原有的資源，才由使用者主動貼 URL 給 Agent 擷取。
- 以 Google Sheets 為例，明確說明 Spreadsheet ID 是網址中 `/spreadsheets/d/` 與 `/edit` 中間的文字，接著直接列出屬性名稱 `SPREADSHEET_ID` 與本次已核對的 ID。
- 程式執行前先檢查必要屬性；缺少時用繁體中文指出屬性名稱並停止後續寫入。
- 紀錄檔(Log)只能顯示「已設定／未設定」，不得顯示任何實際值。
- Google 帳號密碼與 OAuth Token 永遠不得存放。

### 6. 測試與驗證

每節至少有一個肉眼可見結果與一個可診斷結果：

- 肉眼結果：工作表、儲存格、選單、文件、郵件草稿或 Web App 回應。
- 可診斷結果：執行紀錄、函式回傳值、明確錯誤訊息或測試輸出。

每節都要測試正常資料與錯誤資料；涉及寫入時，還要測試重複執行。批次課程測試零筆、一筆及多筆資料。這些工程測試由 Agent 執行，只使用練習檔、假資料、測試資料夾及使用者自己的測試信箱，並在學生開始 UI 驗收前整理通過證據。

學生只執行能代表真實使用方式的流程：必要設定與授權、案例的自訂選單／按鈕／表單／觸發器／部署，以及可見成果判讀。只有學生親自看到實際結果並完成判讀，才能說該節完成；但不要求學生為了證明工程品質而重跑正常、錯誤與重複測試函式。

真實寄信、觸發器、公開部署或其他必須由學生帳號授權的整合結果，先由 Agent 完成安全的模擬與回歸測試，再由學生只走一次真正的使用流程。這次操作同時提供遠端整合證據，不代表把工程測試責任交回學生。

狀態數量、觸發器清單、執行項目與紀錄檔(Log)不是正常成功流程的學習成果。Agent 可以保留管理入口與診斷能力，但不得為了蒐集工程證據，要求學生在同一個功能已成功後反覆開啟技術頁面或貼回狀態。

### 7. 中文紀錄檔(Log)與查看方式

每個主要函式至少輸出：

- `[開始]`：函式將處理什麼。
- `[成功]`：實際完成了什麼。
- `[失敗]`：哪個步驟失敗、原因及下一個檢查動作。

需要時加入 `[設定]`、`[進度]`、`[略過]` 與 `[警告]`。紀錄檔(Log)必須使用繁體中文，不只輸出原始物件或英文例外，也不得包含 API Key、Token、密碼、OAuth 憑證或不必要的個資。

只有需要診斷或本課明確在教除錯時，才引導使用者查看紀錄檔(Log)。直接從 Apps Script 編輯器按「執行」時，查看編輯器下方的「執行記錄」；從 Sheets 自訂選單、觸發器、表單或 Web App 啟動時，改到 Apps Script 左側「執行項目」查看相符時間的執行。正常結果已在 Sheets、Forms、Docs、Drive、Gmail 或 Web App 可見時，不要求學生再進技術頁面證明一次。

正常時只要求學生回覆簡短結果。若執行失敗，請學生直接複製「執行記錄」底下從 `開始執行` 到錯誤結束的文字訊息；不要要求截圖，也不要求學生先自行解釋。只有按鈕、選單、彈出視窗或其他無法用執行記錄呈現的介面問題，才改請學生提供截圖。

### 8. 錯誤分流

發生錯誤時完整使用 `google-apps-script-debugging`。以下是初學者對話時的最小資訊，不取代獨立除錯技能。

先取得：

- 使用者執行的函式名稱。
- 從「執行記錄」直接複製的錯誤訊息與行號。
- 預期結果與實際結果。

再依類型處理：

- 找不到函式：確認儲存、函式名稱與目前選取的執行入口。
- 權限錯誤：確認使用的服務、OAuth scopes 與執行帳號。
- 找不到試算表或工作表：確認專案是否綁定正確檔案，以及名稱是否一致。
- 觸發器沒執行：確認觸發器類型、建立者帳號、失敗紀錄與時區。
- 執行過慢或超過配額：減少逐格服務呼叫，改成批次讀寫，再核對官方配額。

### 9. 檢查點

每個教學範例完成實際成果驗收後，都用一題與本次核心概念有關的小問題收尾。這題是幫助學生整理剛完成的操作，不是考試：

- 優先提供兩至三個簡短選項，讓學生只回覆選項數字；需要判讀畫面時，也只要求一句短答。
- 題目只問本範例已經實際操作過的一個重點，不加入尚未教過的名詞。
- 學生回答後，Agent 明確公布正確答案，再用白話說明原因及它和本次操作的關係。
- 不論學生答對或答錯，都在說明後繼續下一個教學範例；不得要求重答，也不得把錯誤答案當成阻擋課程的條件。

使用者回答並看過說明後，即完成這個檢查點。

## 建議對話節奏

- 每次回覆只推進一個小節或處理一個錯誤。
- 每個操作以一至三個短句說明；除非使用者追問，不展開程式語法或長篇技術背景。
- 不主動操作使用者的 UI；只有使用者明確要求時才協助。
- 開頭先寫這一步會得到什麼結果。
- 操作步驟後立刻提供成功判斷方式。
- 下一節只預告名稱，不先給所有程式。
- 使用者卡住時留在同一節修正，不用重開整套流程。
- 不要求使用者修改或貼上程式；Agent 根據紀錄檔(Log)與測試結果在本機修正。
- 通過驗證後先建立只包含本課變更的 Git commit，再準備遠端同步。
- 每次準備「推送到Apps Script(clasp push)」前，先說「教學範例程式已經寫好了」；若是第一次出現，先用上述白話完整解釋其意涵，再說明要同步到哪一份練習檔案的 Apps Script 及這一步不會做什麼，最後取得確認。commit、絕對路徑、完整檔案清單與 OAuth scope 等工程證據留在 Agent 的推送前檢查；學生追問時才展開。
- 每次推送成功後，第一次學生操作指示要先在同一則訊息提供精簡課程回顧，再完整交付本次操作與成功判斷；即使對話稍後被折疊或學生只看到這一則，也能理解自己為什麼要做。

## 共用開發環境關卡

若使用者沒有指定專案，先使用 `google-apps-script-project-development` 檢查開發環境並建立安全專案基線。

共用環境關卡完成標準：

- Agent 已確認作業系統、架構、Shell、Node.js、npm／npx 與 Git 狀態。
- 目標目錄已確認，專案內的 `clasp` 已固定並驗證版本。
- Agent 已明確回報是沿用既有環境、補齊缺少項目，或修復衝突。
- Apps Script API 已實際確認開啟。
- 使用者已用預期 Google 帳號完成 `clasp` OAuth。
- 敏感檔案忽略規則已存在。
- 尚未執行 `clasp pull`、`clasp push` 或部署。

## 第一個實作教材

共用環境關卡驗收後，依學員開始前選擇的階段開始或恢復，不強迫先完成另一階段。第一階段五個案例彼此獨立，Agent 顯示各案例完成狀態並讓學員自由選擇，直接取用 `templates/beginner/` 的已驗收程式；完成一個後再次選擇，不自動指定下一個。第二階段八課是同一個累積專案，從最早未完成課次開始並查 `templates/catalog.json`；每課完成後直接開始下一課，不詢問是否繼續或切換階段。`pending` 課次只能在 Toolbox Google 技能包維護流程中實作與驗收，成為 `validated` 後一般學員才可直接取用。

第一節完成標準：

- 使用者能從 Google Sheets 開啟綁定型 Apps Script 專案。
- 能從 Sheets「活動報名工具」親自執行初始化或主要功能，不把 Apps Script 函式選單當成日常入口。
- 能完成第一次必要授權，並到 Apps Script 左側「執行項目」找到選單操作的相符紀錄。
- 能說明程式由 Agent 維護，而自己如何透過 UI 驗證程式結果。
- 「活動報名資料」工作表出現兩筆預期的假報名資料。
- 重複執行不會不斷新增重複工作表或資料列。

## 停止條件

發生下列情況時，不繼續增加功能：

- 使用者目前登入的 Google 帳號不明或不是預期帳號。
- 使用者不理解即將授予的資料權限。
- 錯誤訊息顯示組織管理員政策、帳號限制或 Apps Script 服務不可用。
- 下一步需要真實收件人、敏感資料、付費服務、公開部署或刪除資料。
- 下一步需要進階 Google 服務、Workspace 管理員或付費方案。
- 尚未驗證目前小節，繼續操作可能掩蓋錯誤。

停止時說明目前已完成到哪裡、卡在哪個檢查點，以及使用者下一個最小動作。
