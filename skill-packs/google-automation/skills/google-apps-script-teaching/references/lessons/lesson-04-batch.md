# 第 4 課：Google Sheets 批次處理

## 本課成果

一次讀取所有待處理報名資料，在記憶體中驗證與轉換，再一次寫回狀態；零筆、一筆與多筆都能正確處理，重跑只略過已完成資料。

## 課前簡介（Agent 必須先說）

這一課把前面收進試算表的報名資料，整理成後續建立文件能使用的狀態。程式會一次讀取整批資料、在記憶體中驗證，再一次寫回「待產生文件」、「資料有誤」或既有完成狀態；這比逐格來回更快，也比較不容易留下半套結果。Agent 負責安全升級欄位，並測試零筆、一筆、多筆、錯誤與重複執行；學生負責從「活動報名工具」執行批次處理並判讀狀態。本課沿用`SPREADSHEET_ID`，不新增資源或 Script Properties，也不建立文件、不寄信、不建立觸發器。驗收看有效、無效、略過狀態與繁體中文計數紀錄檔(Log)，並確認表單回覆分頁及既有資料沒有被覆蓋。

## 核心概念

1. 一次把整批資料讀出來。
2. 整理完成後，再一次把結果寫回去。
3. 不要每處理一格就往返一次 Google Sheets。

本課主要檔案是 `04_Batch.gs`。可以把批次處理想成「一次拿出整籃資料，整理好，再一次放回去」。使用者不需要理解二維陣列語法。

## Agent 實作

- 建立安全的欄位升級函式，將前課資料擴充為共用資料欄位；不得清空既有報名。
- 建立 `processPendingRegistrations()`。
- 將資料讀取、純資料轉換與 Sheets 寫回分開。
- 有效資料標記為待產生文件；無效資料保留中文原因；已處理資料略過。
- 寫回前檢查列數與欄數，避免範圍大小不一致。
- 建立以下公開入口；只有設定檢查與主要功能需要學生操作：
  - `checkLesson04Settings()`
  - `runLesson04Tests()`
  - `processPendingRegistrations()`
- `runLesson04Tests()` 依序驗證零筆、一筆、多筆、錯誤與重複執行，每項都輸出清楚的中文結果。
- 個別測試函式留在 `04_Batch.gs` 並以底線結尾，標示為內部使用；只把測試總入口列給使用者。
- `runLesson04Tests()` 只使用記憶體中的假資料，不讀寫真實 Sheets。為了讓學生在真實 UI 同時看見無效與略過狀態，主要功能只在「活動報名資料」安全補入兩筆具名教學資料：一筆無效且狀態為「資料有誤」，另一筆已處理且狀態為「已完成」。重跑不得重複新增，也不得讀寫或覆蓋學生剛填寫的表單回覆分頁。
- 累積專案新增 `04_Batch.gs` 後，前課測試只能檢查必要檔案仍存在，不得把整個 `.gs` 檔案清單寫死而阻擋後續課程增加檔案。

## Script Properties

本課沿用 `SPREADSHEET_ID` 與 `FORM_ID`，沒有新增屬性。設定檢查只驗證本課實際需要的 `SPREADSHEET_ID`；Forms 僅在需要回查表單時才驗證 `FORM_ID`。

不得把工作表名稱、試算表 ID 或批次測試資料改成私人硬編碼值。

## 權限說明

本課只使用現有 Sheets 權限，不新增 Gmail、Docs、Drive、觸發器或部署權限。

## 推送到Apps Script(clasp push)前摘要

摘要列出欄位升級、批次處理、測試入口、本課 Git commit，以及「不會建立文件、不會寄送郵件、不會建立觸發器」。

取得使用者確認後才推送。

## 使用者 UI 驗收順序

工程測試由 Agent 使用 `runLesson04Tests` 完成。學生只操作真正的批次功能：

1. 開啟試算表並重新整理，確認上方出現「活動報名工具」選單。
2. 選擇「活動報名工具」→「檢查系統設定」，確認本課可安全使用工作表。
3. 選擇「活動報名工具」→「批次處理待處理報名」。
4. 在試算表查看有效、無效及已略過資料的狀態。
5. 需要診斷時到 Apps Script 左側「執行項目」查看相符時間的繁體中文紀錄檔(Log)；`runLesson04Tests` 與內部函式不出現在 Sheets 選單。

## 預期紀錄檔(Log)

```text
[開始] 準備批次處理報名資料
[設定] SPREADSHEET_ID=已設定
[進度] 已讀取待檢查資料｜筆數=3
[成功] 批次處理完成｜有效=2｜無效=1｜略過=0
[失敗] 資料欄位數與寫入範圍不一致｜未寫入任何結果
[略過] 沒有待處理資料
```

紀錄檔(Log)只記錄數量、測試列號或報名編號的非敏感縮寫，不輸出完整 Email。

## 驗收

- 零筆：沒有資料時正常結束，不建立空白業務結果。
- 一筆：一筆有效資料得到正確狀態。
- 多筆：有效與無效資料同批處理。
- 錯誤：範圍或欄位不一致時，在寫回前停止。
- 重複：已處理資料被略過，結果數量不增加。
- 效率：主要處理流程沒有在逐列迴圈中呼叫 `getValue()` 或 `setValue()`。
- UI：使用者只需在 `04_Batch.gs` 操作設定檢查與主要功能，不需要操作 `runLesson04Tests` 或內部測試。

## 使用者檢查點

請使用者用自己的話說明：「為什麼整批讀取與寫回，比逐格來回處理更適合 Apps Script？」並從紀錄檔(Log)找出有效、無效與略過筆數。

通過後才進入第 5 課。
