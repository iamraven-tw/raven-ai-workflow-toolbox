# 第 7 課：表單觸發器與時間觸發器

## 本課成果

學生提交一筆使用自己 Email 的測試報名後，表單提交觸發器(trigger)會在
背景自動驗證並加入待處理資料；短暫的時間觸發器再處理最多一筆，建立
確認文件並把通知寄到該筆報名資料的 Email，接著自動停止時間處理。
兩種觸發器各成功執行一次後，學生從 Sheets 選單停止剩餘的表單自動化。

## 課前簡介（Agent 必須先說）

這一課把前六課已能從 Sheets 選單手動完成的流程接成背景自動化：
Google Forms 收到新回覆後，表單提交觸發器先驗證並建立待辦資料；
時間觸發器再定期找一筆待辦，沿用第五課建立文件、沿用第六課寄出報名
通知。收件人仍直接來自該筆報名資料的 Email，不使用 `TEST_EMAIL`；
因此這次保留到寄送測試的表單資料要填學生能親自收信的 Email。

`SPREADSHEET_ID`、`FORM_ID`、`DOC_TEMPLATE_ID`與`OUTPUT_FOLDER_ID`
都沿用前課，本課不新增學員必填的指令碼屬性(Script Properties)。
每次最多處理一筆是程式內建的教學安全限制，不讓學員重複填寫一個不可
變更的固定值。Agent 負責事件、錯誤、批次上限、重複觸發器、停止入口
與自動到期測試；學生負責分別確認建立兩種安裝型觸發器、提交一次表單、
查看背景執行結果及確認清理完成。

觸發器會以建立者帳號在背景執行，時間觸發器可能在畫面未開啟時建立
文件並寄信。因此「推送程式、啟用表單觸發器、啟用時間觸發器、停止並
刪除觸發器」是不同確認點，不能互相代替。

## 核心概念

1. 觸發器可以想成「符合條件時，自動執行一個有名字的動作」。
2. 安裝型觸發器會以建立者帳號在背景執行，所以即使沒有開著試算表，
   新報名仍能自動進入系統；只有結果異常時才需要到 Apps Script 左側
   「執行項目」除錯。
3. 表單提交只收件與驗證；時間觸發器才建立文件與寄信。
4. 教學用短間隔必須能看見狀態、能停止，並有自動到期保護。

本課主要檔案是 `07_Triggers.gs`；共用紀錄檔(Log)沿用 `00_Log.gs`，
日常管理入口放進 Sheets 的「活動報名工具」。學生不需要理解事件物件
或觸發器建立程式的語法。

## 兩種觸發器的工作範圍

### 試算表表單提交觸發器

- 事件來源使用綁定的練習試算表，不另外建立 Forms 專用觸發器。
- 回呼函式是 `onRegistrationFormSubmit(e)`。
- 只讀取本次新回覆、驗證資料並加入「活動報名資料」待辦。
- 不建立文件，也不寄信。

### 時間觸發器

- 回呼函式是 `processPendingRegistrationsByTimer(e)`。
- 整次啟用最多嘗試一筆；上限由程式內建，不是學員設定。
- 在建立文件或寄信前先留下單次嘗試記號，完成、結果不確定或錯誤後
  立即停止時間觸發器，不接著處理其他舊待辦。
- 沿用第五、六課的文件與寄信業務函式。
- 收件人固定來自被處理報名資料的 Email。
- 教學期間每 5 分鐘檢查一次，超過安全期限後即使尚未人工清理也停止
  業務處理，不能無期限寄信或消耗配額。

## Agent 實作

- 將觸發器設定、狀態檢查、停止入口、事件解析與測試輔助函式集中在
  `07_Triggers.gs`。
- Sheets 選單提供：
  - 「檢查觸發器狀態」
  - 「啟用表單提交自動處理」
  - 「啟用短暫時間處理」
  - 「停止第 7 課自動化」
- 每個啟用或停止入口都有使用者介面(UI)確認對話框；對話框不能取代
  對話中的遠端操作確認。
- 建立觸發器前先檢查同一回呼函式與事件類型；已存在時安全略過，不建立
  重複觸發器。
- `onRegistrationFormSubmit(e)`依事件的`range`、`values`或
  `namedValues`取得新回覆。缺少真實事件時安全停止。
- `processPendingRegistrationsByTimer(e)`只接受真實時間觸發事件，並在
  執行前檢查安全期限；手動從函式選單執行時不得建立文件或寄信。
- `processPendingRegistrationsByTimer(e)`在外部業務動作前寫入內部單次
  嘗試記號；後續背景執行看到記號時只停止時間觸發器，不得再次建立文件
  或寄信。這個內部狀態不要求學生設定。
- `checkLesson07Triggers()`只讀取目前專案的觸發器，顯示兩種教學觸發器
  各有幾個與安全期限狀態，不顯示觸發器識別碼(ID)。這是管理與除錯
  入口，不是正常教學流程的必做回報。
- `stopLesson07Automation()`只刪除本課兩個已知回呼函式的觸發器，不得
  刪除同專案其他自動化。
- `runLesson07ManualTests()`使用假事件與測試替身，驗證有效事件、缺少
  事件、程式內建批次上限、自動到期、重複建立與精準清理；不得修改真實
  Sheets、建立文件、寄信或建立真正觸發器。
- 安裝型觸發器回呼函式與底線結尾的內部函式不得放進 Sheets 選單。

## Script Properties

| 名稱 | 用途 | 敏感性 |
|---|---|---|
| `SPREADSHEET_ID` | 核對表單回覆與待處理資料 | 非密碼，沿用第 2 課 |
| `FORM_ID` | 核對第 3 課活動報名表單 | 非密碼，沿用第 3 課 |
| `DOC_TEMPLATE_ID` | 建立確認文件 | 非密碼，沿用第 5 課 |
| `OUTPUT_FOLDER_ID` | 存放確認文件 | 非密碼，沿用第 5 課 |

本課不建立 `TEST_EMAIL`，也不新增其他學員必填的指令碼屬性。整次啟用
最多嘗試一筆由程式內的批次上限與單次嘗試記號共同保護。安全到期時間
由啟用函式建立並顯示在 Sheets 管理結果，不要求學生手動計算或貼進
對話。

## 權限說明

本課沿用 Sheets、Forms、Docs、Drive 與第六課只能寄信的 `MailApp`
權限，並新增管理目前專案安裝型觸發器所需的權限。Agent 必須在啟用前
說明：

- 觸發器以建立者的 Google 帳號權限執行。
- 表單觸發器只驗證與建立待辦，不寄信。
- 時間觸發器可能在學生沒有開啟畫面時建立一份文件並寄一封郵件。
- 收件人是該筆報名資料的 Email；本次測試資料必須使用學生能親自收信
  的地址。
- 觸發器會消耗 Apps Script 配額；教學短間隔有安全期限，驗收後仍要
  立即停止。

## 確認點

下列操作分開確認：

1. 推送到Apps Script(clasp push)：只更新程式與資訊清單(manifest)，
   不建立觸發器，也不寄信。
2. 啟用表單提交觸發器：先說明它讓新報名在試算表沒有開啟時也能自動
   進入待處理資料，再說明使用目前帳號在背景執行及本步不寄信。
3. 啟用時間觸發器：先說明它會自動接手待辦、整次啟用最多建立一份文件
   並寄一封通知，處理後會自動停止；再說明 5 分鐘頻率與安全期限。
4. 停止教學自動化：先確認只刪除本課兩種觸發器，再由學生從 Sheets
   選單執行。

每次確認只適用於當次操作，不延伸到下一項。

## 使用者 UI 驗收順序

Agent 先完成無遠端副作用的工程測試與本機提交，再取得推送確認。學生
只走一次真正會在日常使用的自動報名流程；觸發器數量、技術頁面與
紀錄檔(Log)由 Agent 驗證，正常成功時不得要求學生反覆貼回。

1. 學生開啟 Agent 提供的試算表並重新整理；本課不需要先進入 Apps
   Script「專案設定」新增設定。
2. Agent 用白話說明表單觸發器的用途與影響，取得明確建立確認。
3. 學生選擇「活動報名工具」→「啟用表單提交自動處理」，接著直接開啟
   Agent 提供的表單預覽連結；不得停在「已啟用」要求回報技術狀態。
4. 學生填入假姓名、假場次與自己能親自收信的 Email，送出一筆測試報名。
5. 回試算表確認新資料已自動成為「待產生文件」；此時沒有建立文件，
   也沒有寄信。這個可見結果就是表單觸發器的學生驗收。
6. Agent 用白話說明時間觸發器會接手哪一筆待辦及外部影響，取得明確
   建立確認。
7. 學生選擇「活動報名工具」→「啟用短暫時間處理」，接著直接等待一次
   背景執行；不得停在「已啟用」要求回報技術狀態。
8. 到試算表、Drive、收件匣與 Gmail「寄件備份」確認一筆完成狀態、
   一份文件及一封寄到該報名 Email 的郵件。只有結果沒有出現或不正確
   時，才到「檢查觸發器狀態」或 Apps Script「執行項目」除錯。成功後
   時間觸發器已自動停止，不會再處理其他待辦。
9. Agent 說明停止後不再自動接收或處理新報名，並取得明確清理確認。
10. 學生選擇「活動報名工具」→「停止第 7 課自動化」。正常時以停止
    成功對話框作為可見結果；只有結果不確定時才使用狀態入口複核。

所有網頁操作都要在同一則教學指示提供已核對的可點擊連結。若任何步驟
出錯，不得重複建立觸發器；先複製相符時間的紀錄檔(Log)並進入除錯流程。

[設定] 教學觸發器｜表單提交=0｜時間驅動=0

[失敗] 缺少真實觸發事件｜未執行後續處理

紀錄檔(Log)不輸出觸發器識別碼(ID)、完整事件、真實 Email、完整表單
回覆或指令碼屬性(Script Properties)實際值。

## 驗收

- 設定：本課不新增學員必填的指令碼屬性，不使用`TEST_EMAIL`；批次上限
  由程式內建固定為`1`。
- Agent 工程測試：有效、錯誤、批次上限、自動到期、重複建立與精準清理
  都通過，而且沒有遠端副作用。
- 回歸：程式、教案與使用者介面(UI)不得再次要求
  `PROCESSING_BATCH_SIZE`。
- 表單觸發器：真實提交一次後只驗證並加入待辦，沒有建立文件或寄信。
- 時間觸發器：真實執行一次後只處理一筆，建立一份文件並寄一封郵件到
  該筆報名資料的 Email，接著自動停止，不再處理其他舊待辦。
- 單次保護：外部動作前已留下內部嘗試記號；刪除時間觸發器失敗時，
  後續背景執行仍不得再次建立文件或寄信。
- 重複：沒有重複觸發器、文件或郵件。
- 使用者介面(UI)：學生能從 Sheets 選單啟用與停止教學自動化，並用
  表單、試算表、文件及郵件的可見結果判斷成功。
- 管理與除錯：「檢查觸發器狀態」、「觸發條件」與「執行項目」只在
  結果異常或學生想管理自動化時使用，不列為正常流程的反覆回報。
- 清理：課程結束時兩個教學觸發器都是 0；安全期限亦能阻止過期業務處理。

完成清理後，Agent 必須重新核對 Google 官方最新配額，再說明個人帳號
的觸發器每日總執行時間是按使用者跨專案加總，並依真實使用頻率建議
正式環境的較長間隔；不得把 5 分鐘教學設定直接當成正式建議。

## 使用者檢查點

請問：「為什麼表單提交後先加入待辦，不立刻在同一步建立文件與寄信？
1. 讓表單先快速收件，再由受控批次安全處理 2. 因為 Forms 不能寄信」
正確答案是 1。分成兩段能讓收件保持簡單，並把較慢、會寄信的工作限制
為一次一筆。學生答錯只需解說，不得阻擋第 8 課。
