# 第 6 課：Gmail 報名通知

## 本課成果

根據第五課產生的確認文件，從「活動報名資料」選出一筆待寄送資料，
把 PDF 確認文件真實寄到該列的 Email，並在工作表記錄通知編號與寄送
狀態。相同報名資料重跑不會寄出第二封。

## 課前簡介（Agent 必須先說）

這一課把前五課的資料收集、批次整理與文件產生接成真正的通知流程：
程式會讀取報名資料中的 Email，使用目前執行 Apps Script 的 Google
帳號寄出一封報名確認郵件，並附上第五課文件的 PDF。第 1 課固定的
「小明／小美」教學資料已自動使用學員自己的 Google 帳號 Email；
第 3 課之後由表單新增的資料則使用填表時輸入的 Email。因此本課
不建立 `TEST_EMAIL`，也不要求學員重複填寫相同地址。

Agent 負責無效 Email、缺少文件、配額、寄送失敗、不確定狀態及防重複
測試；學生負責在試算表確認一次真實寄送，並到收件匣、Gmail
「寄件備份」、附件與工作表驗收。推送到Apps Script(clasp push)只同步
本機程式與資訊清單(manifest)，不會寄信；只有學生從 Sheets 選單確認
寄送後，才會對外寄出一封郵件。

## 核心概念

1. 正式收件人來自該筆報名資料的 Email，不是額外的測試屬性。
2. 寄件人是目前執行 Apps Script 的 Google 帳號。
3. 寄送前先記為「寄送中」，成功後才改為「郵件已寄出」。
4. 結果不確定時停止，不直接重寄；只有確認沒有寄出後才能使用安全重設。

本課主要檔案是 `06_Gmail.gs`；共用紀錄檔(Log)沿用 `00_Log.gs`，
日常入口由 `00_Menu.gs` 放進 Sheets 的「活動報名工具」。

## Agent 實作

- 使用 `MailApp.sendEmail()` 作為唯一寄信邊界。`MailApp`只能寄信，
  不能讀取 Gmail 收件匣；不得改用需要讀信權限的 `GmailApp`，也不啟用
  Gmail 進階服務。
- 公開的日常入口：
  - `checkLesson06Settings()`：只讀檢查報名資料與第五課文件，不寄信。
  - `confirmLesson06RegistrationEmailSend()`：顯示確認對話框，確認後最多
    寄一封。
  - `confirmLesson06UnsentRecovery()`：只有使用者確認沒有寄出時，重設
    一筆「寄送中」資料；本身不寄信。
- 工程測試入口：
  - `runLesson06ErrorTests()`
  - `testLesson06Repeat()`
- 從第一筆狀態為「待寄送郵件」的報名資料取得姓名、Email、場次、
  報名編號及文件識別碼(ID)。
- 先驗證 Email、文件、剩餘收件人配額與目前處理狀態，再建立不含個資的
  `NOTICE-...` 通知編號。
- 把通知編號寫入工作表，也放進郵件主旨，讓學生不必依賴 Gmail 郵件
  識別碼即可交叉核對。
- 舊版表頭「郵件 ID」安全遷移為「通知編號」；不得覆寫其他不相容欄位。
- 寄送前使用指令碼鎖(script lock)避免同一時間重複處理。
- 寄送前先寫回「寄送中」；`MailApp.sendEmail()` 回傳後再寫回
  「郵件已寄出」與時間。
- 若寄信呼叫或寄信後寫回失敗，保留「結果待確認」狀態，要求人工檢查，
  不得自動重跑。
- 診斷訊息保留錯誤分類與經過清理的原因，但隱藏 Email、私人識別碼(ID)
  與郵件內容。

## Script Properties

本課不新增指令碼屬性(Script Properties)，也不使用 `TEST_EMAIL`。

| 名稱 | 用途 | 本課處理 |
|---|---|---|
| `SPREADSHEET_ID` | 核對共用練習試算表 | 沿用第 2 課，只顯示已設定／未設定 |
| `DOC_TEMPLATE_ID` | 第五課文件範本 | 沿用第 5 課，本課不直接重讀範本 |
| `OUTPUT_FOLDER_ID` | 第五課輸出資料夾 | 沿用第 5 課，本課不新增 PDF 檔案 |

實際收件地址是報名資料，不是課程設定；地址只存在學員自己的工作表與
真實郵件，不得寫進程式、模板、紀錄檔(Log)、課程進度或 Git。

## 權限說明

本課新增兩個最小權限：

- `script.send_mail`：允許目前執行者寄出郵件，但不能讀取既有信箱。
- `userinfo.email`：讓第 1 課初始化固定教學資料時，自動使用目前執行者
  的 Google 帳號 Email。

並沿用 Sheets、Forms、Docs 與 Drive 權限。Agent 必須在授權前說明：

- 程式會以目前執行者帳號寄出一封真實郵件。
- 收件地址來自選定的報名資料。
- 程式會讀取第五課文件並即時轉成 PDF 附件，不另外建立 PDF 檔案。
- 程式不讀取 Gmail 收件匣，也不把地址、郵件全文或私人識別碼寫入
  紀錄檔(Log)。

## 推送到Apps Script(clasp push)前摘要

摘要要列出 `06_Gmail.gs`、Sheets 選單、PDF 附件、`MailApp` 寄信、
通知編號、安全重設、測試結果、新增的兩個最小授權範圍及本課本機版本
提交(commit)，並醒目說明：

> 推送到Apps Script(clasp push)不會寄信、重設資料、建立觸發器或部署；
> 學生之後從 Sheets 選單確認寄送，才會真實寄出一封郵件。

取得推送確認後才可同步。推送確認不等於寄信確認；真正寄送前仍需另外
取得一次明確同意。

## 使用者 UI 驗收順序

Agent 已完成設定、正常、錯誤與重複工程測試後，學生只走一次真實流程：

1. 開啟 Agent 提供且已核對的試算表連結並重新整理。
2. 選擇「活動報名工具」→「檢查系統設定」；預期顯示可安全使用報名
   資料與第五課文件，而且尚未寄信。
3. 若工作表已有「寄送中」但使用者已確認沒有收到、寄件備份也沒有相符
   郵件，選擇「活動報名工具」→「確認未寄出並重設」。對話框必須明確
   說明這個動作不寄信。沒有不確定資料時略過此步。
4. Agent 說明會把一封報名確認郵件寄到該筆報名資料的 Email，並取得
   一次真實寄送確認。
5. 選擇「活動報名工具」→「寄送報名確認郵件」，閱讀「最多一封、收件
   來源、寄件帳號」確認對話框後按「是」。
6. 到 Apps Script 左側「執行項目」查看相符時間的繁體中文紀錄檔(Log)。
7. 回到工作表確認狀態是「郵件已寄出」，「通知編號」有值。
8. 到收件匣與 Gmail「寄件備份」確認同一封郵件，並開啟 PDF 附件檢查
   第五課文件內容。

若發生錯誤或停在「寄送中」，不得直接重跑。先保留資料，再依除錯技能
核對收件結果與寄送證據。

## 預期紀錄檔(Log)

```text
[開始] 準備檢查第 6 課設定
[設定] 收件來源=活動報名資料｜寄件帳號=目前執行者｜實際地址不顯示
[成功] 第 6 課可安全使用報名資料與第五課確認文件｜尚未寄送郵件
[開始] 準備寄送報名確認郵件｜預計寄送=1
[成功] 報名確認郵件已寄出｜寄送數量=1
[略過] 這筆報名已寄送完成｜沒有重複寄信
[警告] 上次寄送結果尚未確認｜未再次寄信｜請先向收件人確認，再使用重設功能
[開始] 準備重設未完成的寄送資料｜不會寄信
[成功] 未完成寄送已重設｜重設筆數=1｜未寄送郵件
```

紀錄檔(Log)不顯示實際收件地址、完整主旨、本文、附件內容、文件
識別碼(ID)或通知編號。

## 驗收

- 設定：不需要 `TEST_EMAIL`，既有必要屬性只顯示狀態。
- 正常：報名資料指定的收件匣收到一封內容與 PDF 附件正確的郵件。
- 寄件證據：目前執行者帳號的 Gmail「寄件備份」有相符郵件。
- 寫回：工作表顯示「郵件已寄出」、通知編號與寄送時間。
- 錯誤：Agent 測試證明無效 Email、缺少文件、配額不足與寄信錯誤都
  不會被宣告成功。
- 重複：已寄出或仍為「寄送中」的資料不會直接再寄。
- 復原：只有使用者確認沒有寄出後才能重設；復原本身不寄信。
- 安全：程式使用 `MailApp`，不讀取 Gmail；私人地址與識別資訊沒有進入
  模板、紀錄檔(Log)、課程進度或 Git。

## 使用者檢查點

請問：「第 6 課正式寄送時，收件人的電子郵件地址應從哪裡取得？」

1. 固定寫在 `TEST_EMAIL`
2. 從該筆報名資料的 Email 欄位取得
3. 由 Agent 隨機選擇

正確答案是 2。學生答錯時只需說明，不得阻擋進入第 7 課。
