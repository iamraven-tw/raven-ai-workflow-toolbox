# 第 3 課：Google Forms 收集資料與資料驗證

## 本課成果

建立活動報名表單並連結同一份練習試算表。Forms 先阻擋明顯格式錯誤；Agent 測試 Apps Script 的第二層驗證，使用者則親自預覽並提交一筆假資料。本課尚未啟用自動處理。

## 課前簡介（Agent 必須先說）

這一課把第 1、2 課的試算表變成可由 Google Forms 收集報名的系統。
完成後，學生可以開啟「活動報名表單」、測試錯誤 Email 會被阻擋，
再提交一筆資料到同一份練習試算表；本課還不會自動處理或寄信。
會保留到第 6、7 課測試通知的資料，必須填寫學生能親自收信的 Email，
因為後續正式流程會直接寄到報名資料中的地址，不使用 `TEST_EMAIL`。
`SPREADSHEET_ID`沿用第 2 課，`FORM_ID`則來自 Agent 取得單獨確認後
建立並核對的「活動報名表單」。`FORM_ID`像表單的「門牌號碼」，讓
程式每次設定同一份表單而不是重建；Agent 要說明它位於編輯網址
`/forms/d/`與`/edit`之間，並解釋放進指令碼屬性(Script Properties)
的理由後才提供值與填寫步驟。Agent 負責表單設定與兩層驗證測試；
學生負責設定、預覽、提交與檢查回覆。驗收看錯誤 Email 被阻擋、有效
資料進入新回覆分頁，而原有兩筆資料仍保留。

## 核心概念

1. Google Form 負責收資料，Apps Script 負責再檢查一次。
2. 表單收到回覆，不代表資料已經自動處理完成。
3. 報名編號可以避免同一筆資料被重複處理。

本課主要檔案是 `03_Forms.gs`。表單設定、資料驗證與本課測試集中在同一檔案。

## Agent 實作

- 依 `FORM_ID` 開啟並設定「活動報名表單」，不得每次執行都建立新表單。
- 表單包含姓名、Email 與活動場次。
- Email 欄位加入 Forms 可提供的格式驗證；場次使用固定選項。
- 將表單回覆目的地設為 `SPREADSHEET_ID` 指定的試算表。
- Google Forms 第一次建立時可能尚無回覆目的地；此時呼叫 `Form.getDestinationId()` 會拋出 `The form currently has no response destination.`，不會回傳空值。程式只把這個已知狀態視為尚未連結，再設定本課試算表；其他錯誤仍原樣拋出，不得用廣泛 `catch` 掩蓋。
- Forms 欄位有兩種實際回傳型別：`Form.getItems()` 回傳通用 `Item`，操作型別專屬方法前才使用 `asTextItem()` 或 `asMultipleChoiceItem()`；`Form.addTextItem()` 與 `Form.addMultipleChoiceItem()` 已直接回傳具體欄位，不得再次呼叫 `asTextItem()` 或 `asMultipleChoiceItem()`。
- 建立 `validateRegistration_()` 純函式，再對回覆做姓名、Email、場次與空白驗證。
- 建立安全的報名編號與處理狀態，不把真實個資寫入測試。
- 建立以下測試入口：
  - `setupLesson03Form()`
  - `checkLesson03Settings()`
  - `testLesson03Normal()`
  - `testLesson03InvalidEmail()`
  - `testLesson03Repeat()`
- 本課由 Agent 測試處理函式，不建立觸發器。表單送出後的自動 Apps Script 處理留到第 7 課。

Agent 的本機回歸測試必須讓表單替身在尚無回覆目的地時真的拋出 `The form currently has no response destination.`，確認第一次執行會完成連結；另測已連結時不重複設定，以及讀取目的地發生其他錯誤時仍會停止並原樣拋出。不得只用「回傳空字串」的假實作測試，否則無法重現 Google Forms 的第一次執行行為。

欄位測試替身也必須區分通用 `Item` 與新增後的具體欄位：新增方法回傳的物件不提供 `asTextItem()`／`asMultipleChoiceItem()`，藉此重現真實 Forms 型別。若舊版本第一次執行失敗後留下「唯一一個、未命名、非必填、無說明、尚無回覆的文字欄位」，修正版可把它安全接續設定為姓名欄位；只要欄位不只一個、內容不完全相符或已有回覆，就必須停止，不得廣泛接管或刪除既有欄位。

## Script Properties

| 名稱 | 用途 | 設定方式 |
|---|---|---|
| `SPREADSHEET_ID` | 沿用第 2 課練習試算表 | 必須已設定 |
| `FORM_ID` | 沿用同一份活動報名表單 | Agent 建立並核對後提供完整 ID；使用者自行輸入；紀錄檔(Log)只記錄已設定 |

Agent 先摘要預計使用的 Google 帳號、遠端資源名稱、影響與驗收方式，取得本課單獨的遠端建立確認後，以最終教材名稱「活動報名表單」建立一份 Google Form。Agent 必須重新核對表單名稱與編輯網址，說明 ID 位於 `/forms/d/「表單 ID」/edit`；不能使用提供給填表者的 `/forms/d/e/.../viewform` 網址。接著在目前的私人教學對話中提供已核對的可點擊編輯網址與可複製的完整 ID，不得要求學生建立空白表單、自己找網址、拆出 ID 或把網址貼回來。

Agent 建立表單與之後的推送到Apps Script(clasp push)是兩個獨立授權點；
建立表單的確認不代表允許推送程式。使用者親自到 Apps Script
「專案設定」的「指令碼屬性」，使用「編輯指令碼屬性」及
「新增指令碼屬性」填入 `FORM_ID`，最後點擊「儲存指令碼屬性」。
表單 URL／ID 不得寫入程式、測試、紀錄檔(Log)、課程進度或 Git。
Agent 預設不操作學生的 Forms UI；只有使用者明確要求時才可協助。
使用者親自完成表單預覽、提交與可見成果判讀。

程式必須先開啟既有 `FORM_ID`；屬性缺少或表單無法存取時，停止並提示檢查，不可直接建立另一份掩蓋問題。

## 權限說明

新增 Google Forms 的開啟與修改權限，並繼續使用 Sheets。Agent 必須說明本課不使用 Gmail、Docs、Drive 檔案遍歷、觸發器或 Web App。

## 推送到Apps Script(clasp push)前摘要

摘要列出 Forms 程式、資料驗證程式、測試入口、manifest 權限差異與本課 Git commit；明確寫「推送本身不會建立新表單，使用者之後執行 `setupLesson03Form()` 只會設定 Agent 已建立且由 `FORM_ID` 指定的表單」。

取得使用者確認後才推送。

## 使用者 UI 驗收順序

工程測試由 Agent 完成。學生只操作必要設定與實際填表流程：

1. Agent 提供已核對的 Apps Script 編輯器、表單與試算表連結，以及完整 `FORM_ID`；使用者親自到 Apps Script「專案設定」的「指令碼屬性」，使用「編輯指令碼屬性」及「新增指令碼屬性」輸入 `FORM_ID`，再點擊「儲存指令碼屬性」。
2. 回到試算表重新整理，選擇「活動報名工具」→「檢查系統設定」。
3. 設定通過後，選擇「活動報名工具」→「設定活動報名表單」，確認只設定並沿用指定的一份表單。
4. 需要診斷時到 Apps Script 左側「執行項目」確認成功紀錄檔(Log)；日常操作不從 `03_Forms.gs` 的函式選單執行。
5. 開啟 Agent 提供的表單預覽連結，先嘗試明顯錯誤格式；這筆錯誤測試
   不得送出。接著填寫一筆假姓名與假場次，但 Email 使用學生能親自
   收信的地址，因為這筆資料之後可能進入真實寄送流程。
6. 工作表結果檢查：開啟 Agent 提供的試算表連結，確認原始表單回覆；原有「活動報名資料」工作表與兩筆資料不得被破壞。
7. Agent 明確提醒：目前只有 Forms 收集資料；表單送出時自動執行 Apps Script 要等第 7 課。

## 預期紀錄檔(Log)

```text
[開始] 準備活動報名表單
[設定] SPREADSHEET_ID=已設定｜FORM_ID=已設定
[成功] 活動報名表單已可使用｜欄位數=3
[失敗] 報名資料驗證失敗｜欄位=Email｜原因=格式不正確｜未進入後續處理
[略過] 報名編號已存在｜沒有重複新增
```

紀錄檔(Log)不輸出完整 Form ID、回覆者真實 Email 或整筆原始表單內容。

## 驗收

- 正常：學生提交的一筆有效測試資料出現在回覆試算表，且該 Email 可由
  學生本人收信；Agent 測試也通過。
- 錯誤：Agent 測試空白、Email 格式錯誤或非法場次，且沒有後續寫入。
- 重複：Agent 測試證明相同報名編號重跑只保留一筆業務結果。
- 設定：`SPREADSHEET_ID` 與 `FORM_ID` 都只顯示狀態。
- 可見：表單存在並連結練習試算表。
- 自動化邊界：使用者知道本課只完成收集與手動驗證，自動處理要等第 7 課。

## 使用者檢查點

請使用者說明：「為什麼 Forms 已限制 Email 格式，Apps Script 還要再驗證一次？」並在紀錄檔(Log)中指出被拒絕的欄位與下一個檢查動作。

通過後才進入第 4 課。
