# 第 5 課：Google Docs／Drive 產生文件

## 本課成果

根據一筆有效報名資料，從測試範本建立一份確認文件並放入專用 Drive 測試資料夾；文件 ID 寫回工作表，重跑不會建立第二份。

## 課前簡介（Agent 必須先說）

這一課把第 4 課已整理成「待產生文件」的報名資料，轉成一份真正的 Google Docs 報名確認文件，放到專用 Drive 資料夾，並把文件 ID 寫回試算表避免重複建立。`DOC_TEMPLATE_ID`來自 Agent 取得確認後建立並核對的「活動報名確認範本（教學）」，`OUTPUT_FOLDER_ID`來自同時建立的私人「活動報名確認文件（教學輸出）」資料夾；兩者分別告訴程式「複製哪一份範本」與「把新文件放到哪裡」。這些 ID 都像資源的「門牌號碼」：Docs ID 位於`/document/d/`與`/edit`之間，Folder ID 位於`/folders/`之後。放進 Script Properties 可讓資源設定與程式分開，換範本或資料夾時不用改程式，也避免私人 ID 進入原始碼、紀錄檔(Log)或 Git。Agent 負責建立資源、程式與正常／錯誤／重複測試；學生負責輸入設定、從 Sheets 選單建立一次文件，並在 Drive、Docs、工作表與繁體中文紀錄檔(Log)驗收。本課會新增一份測試文件，但不寄信、不建立觸發器、不部署，也不搜尋、分享或刪除其他 Drive 檔案。

## 核心概念

1. 範本 ID 與輸出資料夾 ID 是環境設定，不是程式碼。
2. 範本裡的 `{{姓名}}` 等文字是等待程式替換的記號。
3. 把新文件 ID 記錄回試算表，程式才知道這筆資料已經處理，不會重複產生。

本課主要檔案是 `05_Documents.gs`；共用紀錄檔(Log)沿用 `00_Log.gs`。使用者不需要理解文件處理程式的語法。

## Agent 實作

- 將本課功能與測試輔助函式集中在 `05_Documents.gs`，不為每個小功能增加檔案。
- 建立 `createRegistrationDocument_()`。
- 從 `DOC_TEMPLATE_ID` 複製範本到 `OUTPUT_FOLDER_ID`。
- 只替換教學用記號，例如 `{{姓名}}`、`{{活動場次}}`、`{{報名編號}}`。
- 使用可辨識但不含完整 Email 的檔名。
- 建立文件成功後才把文件 ID 與狀態批次寫回。
- 若寫回失敗，紀錄檔(Log)必須指出已建立的測試文件需要人工檢查，不可假裝整體成功。
- 建立學生真正使用的主要入口 `createPendingRegistrationDocuments()`。
- 建立以下測試入口：
  - `checkLesson05Settings()`
  - `testLesson05Normal()`
  - `testLesson05MissingFolder()`
  - `testLesson05Repeat()`
- 錯誤測試使用注入的不存在設定或測試替身，不修改真實屬性。

## 遠端資源準備

建立本課程式前，Agent 先顯示 Google 帳號、資源名稱、建立位置、內容、
分享狀態與影響，取得本課單獨的遠端建立確認。確認後由 Agent 使用同一個
教學帳號直接建立：

1. 一份名為「活動報名確認範本（教學）」的 Google Docs，只包含以下
   假資料記號：

   ```text
   活動報名確認
   姓名：{{姓名}}
   活動場次：{{活動場次}}
   報名編號：{{報名編號}}
   ```

2. 一個名為「活動報名確認文件（教學輸出）」的私人 Drive 資料夾。

Agent 建立後重新核對名稱、擁有者、內容、資料夾為空及未公開分享，再
直接提供已核對的可點擊 Docs 與 Drive 連結。不得要求學生建立空白文件、
貼上範本文字、建立資料夾、尋找網址或把網址貼回來。

若 Agent 首選的 Google Drive 操作管道只有唯讀權限或缺少建立權限，
先唯讀確認沒有留下同名或部分完成的資源，再改用已登入同一教學帳號的
瀏覽器完成建立與核對；不得因工具權限不足就把資源建立工作丟回學生。
瀏覽器若要求登入、OAuth 授權或其他使用者確認，必須停下交還使用者，
完成後才接續。

Agent 從已核對的 URL 擷取 ID，並用短句說明 ID 在 URL 的位置：

   - Docs：`/document/d/「文件 ID」/edit`
   - Drive 資料夾：`/folders/「資料夾 ID」`

Agent 在目前的私人教學對話提供可複製的完整 ID；使用者只需親自開啟
Apps Script「專案設定」，找到「指令碼屬性」，依序點擊
「編輯指令碼屬性」及「新增指令碼屬性」填入資料，最後點擊
「儲存指令碼屬性」。

一般 Google 資源 URL／ID 不是密碼，可由使用者主動提供給 Agent 協助擷取，但不得寫入程式、紀錄檔(Log)或 Git。若網址含 Token、簽章或其他驗證資料，則視為敏感值，不可貼進對話。

建立 Docs／Drive 資源與之後的推送到Apps Script(clasp push)是兩個
獨立確認點；前一次
確認不得延伸到推送。工程測試由 Agent 負責，使用者親自輸入指令碼屬性
並判讀產出文件。

## Script Properties

| 名稱 | 用途 | 敏感性 |
|---|---|---|
| `SPREADSHEET_ID` | 讀取報名與寫回文件 ID | 非密碼，沿用第 2 課設定 |
| `DOC_TEMPLATE_ID` | 指定測試文件範本 | 非密碼，仍不寫入程式、紀錄檔(Log)或 Git |
| `OUTPUT_FOLDER_ID` | 指定測試輸出資料夾 | 非密碼，仍不寫入程式、紀錄檔(Log)或 Git |

設定檢查必須先全部通過，才可建立任何 Drive 檔案。

## 權限說明

本課新增 Docs 文件存取權限與完整 Drive 檔案存取權限。Google 官方目前
要求 `DocumentApp.openById()` 使用 `documents` scope，而
`DriveApp` 以指定 ID 取得範本、資料夾並複製文件需要 `drive` scope。
Agent 必須在授權前說明：權限畫面範圍較廣，但本課程式邏輯只使用
`DOC_TEMPLATE_ID` 與 `OUTPUT_FOLDER_ID` 指定的資源，不搜尋、整理、分享
或刪除其他 Drive 檔案。

## 推送到Apps Script(clasp push)前摘要

摘要列出 Docs／Drive 程式、主要功能、測試入口、新增權限、本課 Git commit，以及「推送不會立即建立文件；執行主要功能時才會建立一份測試文件」。

取得使用者確認後才推送。

## 使用者 UI 驗收順序

工程測試由 Agent 完成。學生只操作設定、主要功能與實際文件驗收：

1. 使用者完成三個必要屬性。
2. 回到試算表重新整理，選擇「活動報名工具」→「檢查系統設定」；需要診斷時到 Apps Script「執行項目」確認三項設定均已完成。
3. 選擇「活動報名工具」→「建立報名確認文件」，處理待建立文件的報名；預期指定資料夾新增一份確認文件。
4. 在 Drive 打開新文件，確認三個範本記號都已換成假報名資料。
5. 到「執行項目」確認這次主要功能的繁體中文紀錄檔(Log)；工程測試與內部函式不出現在 Sheets 選單。

## 預期紀錄檔(Log)

```text
[開始] 準備建立報名確認文件
[設定] DOC_TEMPLATE_ID=已設定｜OUTPUT_FOLDER_ID=已設定
[成功] 已建立報名確認文件｜建立數量=1
[失敗] 找不到指定輸出資料夾｜未建立文件｜請檢查 OUTPUT_FOLDER_ID
[略過] 這筆報名已有文件｜沒有重複建立
```

紀錄檔(Log)不輸出實際 ID、完整文件內容或完整 Email。

## 驗收

- 設定：Agent 建立並核對一般 Google 資源、提供 ID 位置與完整值；使用者親自在指令碼屬性完成輸入。
- 正常：指定資料夾出現一份內容正確的測試文件。
- 錯誤：Agent 測試證明無效資料夾設定在建立前被拒絕。
- 重複：Agent 測試證明相同報名資料重跑不新增文件。
- 寫回：工作表有文件 ID 與正確狀態。
- 安全：一般資源 ID 只在私人對話與指令碼屬性間傳遞；紀錄檔(Log)、程式與 Git 沒有屬性值或完整文件內容。

## 使用者檢查點

請使用者說明：「哪一個欄位讓程式知道文件已建立，所以重跑時應該略過？」Agent 再用錯誤測試證據說明 `OUTPUT_FOLDER_ID` 缺漏時如何安全停止。

通過後才進入第 6 課。
