# 第 1 課：Google Sheets 基礎讀寫

## 本課成果

建立「活動報名與通知系統」的綁定型試算表專案；共用 `onOpen(e)` 在
Sheets 建立「活動報名工具」選單。使用者從選單執行一次真正的初始化
動作，並在試算表確認「活動報名資料」工作表與兩筆使用自己 Google
帳號 Email 的教學資料。Agent 的工程測試證明重跑不會增加重複資料。

## 課前簡介（Agent 必須先說）

這一課先建立整套系統的資料底座：一份可從 Sheets 選單初始化的
「活動報名資料」工作表。完成後會看到欄位、兩筆「小明／小美」教學
資料與「活動報名工具」選單。兩筆資料的 Email 會由程式取得目前執行者
的 Google 帳號並自動帶入，讓第 6 課真的寄信時仍只寄給學員自己；
不要求學員手動複製地址，也不把地址寫進原始碼、紀錄檔(Log)或 Git。
之後七課都沿用這份試算表，不會每課重建。Agent 負責建立綁定型程式、
選單及正常／錯誤／重複測試；學生負責從 Sheets 選單親自初始化並核對
結果。本課不需要指令碼屬性(Script Properties)，也不會建立表單、
文件、觸發器、部署或寄信。驗收看工作表資料、選單操作的繁體中文
紀錄檔(Log)，以及重跑後仍只有兩筆教學資料。

## 開始條件

- 共用開發環境關卡已完成。
- 本機專案目錄、Git、專案內 `clasp`、Apps Script API 與 OAuth 已驗證。
- 尚未建立教學用遠端專案時，Agent 必須先顯示建立摘要並取得確認，才可使用目前版本 `clasp create --help` 支援的語法建立 `sheets` 專案。
- 已有教學專案時，先核對綁定類型與本機 `.clasp.json`，不得重建。

建立遠端專案與推送到Apps Script(clasp push)是兩個不同確認點；可以在
同一份摘要中一次說明，但未獲明確同意前都不得執行。

## 學習重點

1. 重新整理 Google Sheets，找到「活動報名工具」選單。
2. 用白話理解函式(function)是 AI 代理(Agent)寫好的一個「有名字的動作」。
3. 理解程式由 Agent 撰寫與推送；使用者不需要手寫程式，也不需要進 Apps Script 尋找日常函式。
4. 親自完成一次真正的「從 Sheets 選擇初始化項目 → 必要時完成授權 → 回到 Sheets 檢查成果」。
5. 知道 `SpreadsheetApp`、`Sheet` 與 `Range` 分別代表試算表服務、工作表分頁與儲存格範圍；不要求背誦語法或二維陣列格式。

本課不介紹專案總覽、檔案管理、觸發條件或部署介面。只有選單操作失敗而需要診斷時，才開啟 Apps Script 左側「執行項目」查看相符時間。

## 本課檔案

- `00_Log.gs`：放共用的繁體中文紀錄檔(Log)功能。
- `00_Menu.gs`：放共用 `onOpen(e)` 與「活動報名工具」累積選單。
- `01_Sheets.gs`：放 Sheets 功能及第一課測試。

第一課使用這三個程式檔，不把所有內容放進單一 `Code.gs`，也不為每個測試建立新檔案。使用者不需要開啟這些程式檔；真正的初始化入口在 Google Sheets。

## 給使用者的第一段說明

Agent 在第一次請使用者操作選單前，只說：

> 函式(function)可以先想成一個「有名字的動作」。程式已經由 AI 代理(Agent)寫好，你只要在試算表的「活動報名工具」選擇要做的事，不需要進入程式編輯器。

接著直接指出 Sheets 上方的「活動報名工具」，不展開說明程式語法。

學生只需要選擇「初始化活動報名資料」，選單會呼叫 `setupLessonSheet`。其餘函式是 Agent 的工程測試入口：

| 檔案 | 函式 | 用途 | 預期結果 |
|---|---|---|---|
| `01_Sheets.gs` | `setupLessonSheet` | Sheets 選單呼叫：建立本課工作表。 | 工作表出現兩筆練習資料。 |
| `01_Sheets.gs` | `checkLesson01Settings` | Agent 測試：檢查本課設定。 | 紀錄檔(Log)顯示本課不需要 Script Properties。 |
| `01_Sheets.gs` | `testLesson01Normal` | Agent 測試：驗證正常情況。 | 工作表內容符合預期。 |
| `01_Sheets.gs` | `testLesson01Error` | Agent 測試：驗證錯誤情況。 | 安全停止，資料沒有改變。 |
| `01_Sheets.gs` | `testLesson01Repeat` | Agent 測試：驗證重複執行。 | 工作表仍只有兩筆練習資料。 |

## Agent 實作

- 建立最小 `src/appsscript.json`，使用 V8 runtime 與使用者時區。
- 在 `00_Log.gs` 建立共用中文紀錄檔(Log)輔助函式。
- 在 `00_Menu.gs` 建立只負責 UI 的 `onOpen(e)`，加入「初始化活動報名資料」；不得在開啟試算表時直接寫入業務資料。
- 在 `01_Sheets.gs` 建立 `setupLessonSheet()`，安全建立或沿用「活動報名資料」。
- 使用 `Session.getEffectiveUser().getEmail()` 取得目前授權執行者的
  Google 帳號 Email，建立兩筆可供後續真實寄信驗收的教學資料。
- 實際 Email 只寫入學員自己的練習試算表，不得進入程式、紀錄檔(Log)、
  課程進度或 Git。
- 重跑時只辨識固定的「小明／小美」教材資料；保留已推進的處理狀態，
  也不得改寫碰巧同名、同場次的其他真實報名者。
- 在 `01_Sheets.gs` 建立以下測試入口：
  - `testLesson01Normal()`
  - `testLesson01Error()`
  - `testLesson01Repeat()`
  - `checkLesson01Settings()`
- 錯誤測試使用空白工作表名稱或注入的無效輸入，不刪除真實試算表。
- 重複測試執行兩次後，確認工作表只有一份、標題一列、資料兩列。

## Script Properties

本課沒有必要的 Script Properties。`checkLesson01Settings()` 必須輸出：

```text
[設定] 本課不需要 Script Properties｜未在程式中硬寫私人 ID 或秘密
```

這個檢查點是為了建立習慣，不為了形式製造無用途屬性。第 2 課才正式設定 `SPREADSHEET_ID`。

## 權限說明

本課需要讀寫練習試算表，並讀取目前執行者的 Google 帳號 Email，
只用來填入兩筆學員自己的教學資料。第一次執行時，Agent 先說明
`SpreadsheetApp`會修改哪一份練習檔案，`userinfo.email`則用來避免
把固定假信箱留到後續真實寄信課程。程式不會把地址輸出到紀錄檔(Log)；
本課也不需要 Gmail 寄信、Drive 全域檔案整理、觸發器或 Web App 權限。

## 使用者 UI 驗收順序

工程測試由 Agent 在學生操作前完成。以下只保留學生真正會用到的流程：

1. 開啟 Agent 提供的 Google Sheets 連結並重新整理，確認上方出現「活動報名工具」選單。
2. Agent 說明選單中的每個項目都是 Agent 寫好的「有名字的動作」；學生選擇「活動報名工具」→「初始化活動報名資料」。
3. 第一次需要時完成 OAuth 授權；授權後回到同一份試算表，再從同一個選單執行一次。
4. 在試算表查看「活動報名資料」與兩筆教學資料，確認 Email 欄已自動
   使用目前的 Google 帳號；不需要把地址貼回對話。
5. 需要診斷時才開啟 Apps Script 左側「執行項目」，查看相符時間的繁體中文紀錄檔(Log)；不得把 Apps Script 函式選單當成日常入口。

## 驗收

- 概念：使用者能用自己的話說明函式是什麼。
- UI：使用者能重新整理 Sheets，從「活動報名工具」選擇「初始化活動報名資料」，並在需要診斷時到 Apps Script 左側「執行項目」找到相符紀錄。
- 正常：工作表顯示兩筆預期教學資料，而且 Email 欄使用目前執行者帳號。
- 錯誤：Agent 測試證明空白名稱被拒絕，原資料不變。
- 重複：Agent 測試證明連續執行兩次仍只有兩筆假資料。
- 設定：明確確認本課不需要屬性，也沒有硬寫私人 ID。
- 可診斷：工程測試的執行記錄及選單操作的「執行項目」可找到 `[開始]`、`[設定]`、`[成功]`、`[失敗]` 與 `[略過]`。
