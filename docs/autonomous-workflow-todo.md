# AI Agent 主導工作流改造待辦清單

更新日期：2026-09-13。

## 目標

讓 AI Agent 成為工作流的主要執行者：自行規劃、操作、驗證、記錄與交付；人類只在帳號持有人才能完成的步驟、真正需要主觀判斷的成果，以及高影響或例外狀況介入。

執行依據見[共用人機分工契約](human-agent-contract.md)。API／App 的非敏感設定先使用可行的 API、CLI 或 OpenCLI；確認只剩 Computer Use 時，提供人工指引並告知代做可能較慢，讓使用者選擇。API key 與其他敏感機密的輸入、儲存，以及平台要求本人完成的步驟，一律由人類操作，沒有代做選項。

## 人類應介入的三類節點

1. **人類親自操作**：速度原因與安全原因分開。只有 Computer Use 可行時，預設提供人工指引，經選擇可由 Agent 代做並提醒速度；敏感機密輸入與儲存、OAuth 同意及平台本人驗證則必須由人類完成。Agent 負責準備入口、保存進度與檢查不含秘密的結果。
2. **成果與業務判斷**：品牌定位、無可靠來源的商業事實、正式對外文案、留言回覆、重要剪輯選擇及長期策略寫入。Agent 先完成可審核成果，再讓人類在單一介面批次判斷。
3. **高影響與例外處理**：首次公開發布、付款、購買網域、刪除、無法可靠回復的變更、權限擴大，以及 Agent 無法安全判定的衝突或不明結果。

除此之外，資料整理、草稿、程式撰寫、本機修改、測試、格式檢查、狀態記錄、可安全重試的修復與讀回驗證，都應由 Agent 自行完成。

## 自主執行原則

- 使用者提出明確任務，就視為授權 Agent 在該任務範圍內完成必要的本機讀寫與可回復處理；不代表自動授權未列明的外部寫入。
- 遠端發布、回覆、部署、排程與資料更新，由當次明確授權或使用者預先設定的持久執行政策決定，不在同一範圍內逐步重複詢問。
- Agent 自行從既有設定、檔案與已驗證狀態推導輸入；只有缺少的資訊會實質改變成果，且無可靠預設值時，才向人類提出一個集中且可行動的問題。
- 風險或來源不明時，自動隔離、略過或降級為草稿；只有確實需要人類判斷時才列入例外，不擴大任務範圍。
- 技術結果由 Agent 讀回驗證並自動寫入狀態；不要求使用者確認 Agent 已經能直接觀測的事實。
- 所有遠端寫入都必須具備唯一交易識別、執行前檢查、單次寫入、讀回驗證及中斷恢復，避免重複發布或重複回覆。
- 自主化不等於無限制。Agent 只能在已設定的帳號、目標、動作、費用、資料範圍與重試上限內行動。

## P0：共用人機分工契約（文件完成）

本階段依確認後的範圍交付規則與情境走查，沿用各包既有設定及狀態，不新增政策服務、統一狀態引擎或例外系統。下列完成標記只代表[共用契約](human-agent-contract.md)完成；各包程式、技能與測試接線仍依後續順序處理。

- [x] **AUTO-001 — 定義任務授權沿用。** 規定目標、帳號、動作、批次與限制的最小記錄內容，跨技能沿用同一確認；實質擴大範圍才重問。
- [x] **AUTO-002 — 定義人類操作的兩種原因。** Computer Use 唯一可行時才提出較慢的代做選項；機密輸入與儲存、平台本人操作不得代做。包含 macOS 與 Windows。
- [x] **AUTO-003 — 定義外部結果驗證。** 沿用現有單次交易及讀回機制；不明結果先查證，不重送、不切介面補送，也不自動回滾。
- [x] **AUTO-004 — 定義暫停與接續。** 準備具體成果或操作入口，保存既有進度；只讓沒有相依性且安全的其他工作繼續。
- [x] **AUTO-005 — 定義交付內容。** Agent 自行記錄技術結果，只回報任務相關的成果、證據與待處理事項。
- [x] **AUTO-006 — 完成八個文件情境走查。** 覆蓋工具選擇、Computer Use、機密儲存、OAuth、留言審核、已授權部署、本機修正與發布逾時；不是實機或模型行為驗收。

## P1：社群媒體工作流

本輪已完成技能入口／人機分工對齊，以及 Agent 草稿 → 六欄 Sheets 單次人工審核。以下未勾選的能力、私訊與全包情境項目是歷史延伸清單，不自動擴大本輪範圍，也不代表教學未完成。

本階段範圍：本人管理 Facebook 粉絲專頁、Instagram 專業帳號、Threads 與 YouTube；包含內容新增／修改／刪除、單篇與帳號成效、留言及私訊管理。只承諾已實作並取得證據的能力；不將 App 設定或取得權限當作功能完成。

- [x] **SOC-SCOPE-001 — 第一批初始化分流文件修正。** 保留留言與私訊；不追問未選 Meta 平台、不主動提出廣告／商店延伸權限、不強迫製圖偏好與 OpenCLI 安裝。教學加入既有連線沿用及回呼適用條件。此項只代表入口文件修正，不代表所有 reference、執行器或模型行為已對齊。
- [ ] **SOC-CAP-001 — 建立逐動作能力與實作盤點。** 四平台分別列出內容建立／修改／刪除、留言讀取／回覆／隱藏／刪除、私訊讀取／回覆、帳號與單篇成效；核對官方能力、帳號前提、套件執行器及實測證據，未實作與平台不支援分開。
- [ ] **SOC-CAP-002 — 補齊已確認可支援的內容修改與刪除。** 沿用現有交易、唯一目標、變更預覽、單次寫入及讀回機制；不得以刪除重發冒充修改，未知結果不重送。
- [ ] **SOC-CAP-003 — 加入單篇成效直接查詢。** 依指定貼文／影片與期間取數，不強迫週期報告、策略問答或長期寫回；不足資料不補零。
- [x] **SOC-SCOPE-002 — 路線與安全交接文件對齊。** 四平台沿用已選最短授權路線；後台秘密由本人在 Agent 開啟的安全終端機輸入，OAuth 交換／刷新 Token 由程式保存。教學完成與各帳號實機驗收分開，實際整合仍檢查當次權限及讀回結果。

- [x] **SOC-GUIDE-001 — 啟動時呈現 API 申請圖文網頁。** 四平台、六分支圖文與安全終端機交接示範已完成，啟動時直接呈現選定路線。依使用者確認，以能按圖文操作為教學完成標準；畫面來源與限制留在維護文件，不再把補拍舊進度當使用者待辦。
- [x] **SOC-AUTO-001 — 明確切分 API 啟用的人機責任。** 非敏感設定先以 API、CLI 或 OpenCLI 完成；確認只剩 Computer Use 時才提供人工指引與較慢的代做選項。人類親自完成 OAuth 同意、本人驗證與敏感機密輸入及儲存。
  - 驗收：macOS／Windows 的後台秘密由本人在安全終端機貼上並按 Enter，Agent 不代填或回顯。使用者已確認 OAuth 程式交換／刷新產生的 Token 可直接保存到系統憑證庫，保留授權、讀回比對與不明結果停止；不增加逐次人工保存。啟用狀態沿用現有欄位。
- [x] **SOC-AUTO-002 — Agent 完成留言摘要與初稿。** 固定規則先隔離可疑內容；Agent 透過 `draft-input` 取得單則已篩選資料，產生結構化摘要與草稿，不要求人類先代寫，也不新增模型服務。
  - 驗收：來源雜湊／狀態及草稿欄位檢查通過；可疑或不確定內容留在隔離區。`agent_draft` 只代表待審稿，不冒充人類或已實作的隔離式審查器，也不構成回覆授權。
- [x] **SOC-AUTO-003 — 將 Sheets 變成唯一的人類留言審核介面。** Agent 自動填好既定六欄，人類只需修改第六欄或留白；不再先操作本機人工頁面，又到 Sheets 重做一次。
  - 驗收：人類只看一次完整批次；說「可以回覆」後，Agent 重讀第六欄、逐則傳送並讀回，不使用較早草稿。
- [ ] **SOC-AUTO-004 — 建立可持久設定的發布與回覆政策。** 記錄帳號、平台、內容類型、期間、每日上限、語氣、禁止主題，以及哪些工作仍需要批次確認。
  - 驗收：相同範圍不重複詢問；需要人類確認的發布或回覆只出現一個完整批次，而不是逐平台、逐步確認。
- [ ] **SOC-AUTO-005 — 私訊採 Agent 初稿、人類批次審核。** Agent 在平台訊息窗、對方先發起、純文字與政策範圍內自動判斷並產稿；人類於單一介面確認後，由 Agent 傳送及驗證。
  - 驗收：附件、付款、退款、法律、個資、威脅或信心不足的訊息自動隔離；其餘對話不需人類整理上下文或手寫初稿。
- [x] **SOC-AUTO-006 — 預設建立權杖背景維護。** 整合預覽包含每日維護排程，除非使用者明確拒絕；工作開始時仍驗證並依授權刷新。
  - 驗收：入口沿用既有維護程式，排程需立即執行並讀回；不可用時保留已完成成果並揭露維護缺口。OAuth 交換／刷新 Token 可由程式保存，不增加人工逐次輸入。
- [ ] **SOC-AUTO-007 — Agent 準備成效洞察，人類確認長期策略。** Agent 自動蒐集、比較並提出三至五項觀察與一個關鍵問題；只有人類補充脈絡並確認的結論才寫入長期策略。
  - 驗收：人類不需整理數據；原始資料、AI 推論、人類判斷與正式策略可追溯且可回復。
- [ ] **SOC-AUTO-008 — 建立完整最少介入情境測試。** 覆蓋 API 啟用、規劃、寫作、製圖、發布、留言、私訊與成效更新。
  - 驗收：虛構完整週期只在預先定義的人類節點暫停，`unnecessary_human_prompt_count = 0`、沒有重複遠端寫入，所有成功項目都有獨立讀回證據。

## P1：官網建置工作流

本輪需求已實作並本機驗證：需求式頁面、Agent 先產稿、整體批次確認、七技能自動接續與技術紀錄。六主題的精簡網站已真實建置；外部登入、部署與 DNS 未在本輪執行，不宣稱實機驗收。

- [x] **WEB-AUTO-001 — 改為需求式頁面模型。** 首頁與 404 為最小核心；關於、服務、聯絡、部落格及其他頁面依商業目標與內容量啟用。
  - 驗收：不含部落格的單頁官網可通過設定、建置、檢查與部署流程。
- [x] **WEB-AUTO-002 — 讓 Agent 先完成可審核的初版內容。** 從工作區既有的產品、受眾、服務與品牌資料建立文案；缺乏證據的商業資訊集中成一次問題，不要求使用者逐欄從空白開始寫。
  - 驗收：Agent 先交付無佔位字串、無虛構數字的可建置初版；人類只需批次修正真正的商業事實與正式對外語氣。
- [x] **WEB-AUTO-003 — Agent 推薦設計，人類只做一次視覺定案。** Agent 依內容密度、品牌資料、素材與網站目的選出最合適的主題並產生完整預覽；人類可確認或改選一次，不必從空白開始設計。
  - 驗收：六個主題維持真正不同；未指定風格時，Agent 能說明推薦依據並交付可直接判斷的預覽，確認後自動完成建置。
- [x] **WEB-AUTO-004 — 合併跨技能人工交接。** 一個官網任務能連續完成設定、文案、設計、建置、部署、串接與維運設定；只在商業內容、視覺定稿、登入與公開部署等既定節點集中等待人類。
  - 驗收：任務不因技能邊界而停止或要求使用者接力下指令；同一類決策不重複確認。
- [x] **WEB-AUTO-005 — 自動記錄建置與頁面檢查結果。** Agent 觀測到的建置、連結、版面、無障礙與效能結果直接寫入狀態。
  - 驗收：不再為寫入 `passed` 狀態要求人工確認；失敗時自動修正並在上限內重測。
- [x] **WEB-AUTO-006 — 將部署技術工作交給 Agent。** 人類負責 Cloudflare 登入、首次公開授權、網域購買及付費決定；Agent 負責其餘設定、部署、DNS／HTTPS 檢查與讀回。
  - 驗收：人類完成必要授權後，Agent 不再要求使用者執行命令或判讀技術畫面；需要付款時明確停止。
- [ ] **WEB-AUTO-007 — 自動維運。** 依政策執行健康檢查、備份、依賴更新候選、回復與通知。
  - 驗收：例行成功保持安靜；失敗自動回復到最後已驗證版本，無法回復才建立例外。

## P2：AI 剪片工作流

- [ ] **VID-AUTO-001 — 以能力檢查取代完全相同版本限制。** 對 OpenCC、FFmpeg 與 libass 建立已驗證的相容版本範圍及功能測試；不相容時使用隔離的固定 runtime。
  - 驗收：系統工具版本不同但功能相容時可以繼續，且不修改使用者共用 Homebrew 環境。
- [ ] **VID-AUTO-002 — 自動管理模型與空間。** 依持久政策中的下載、磁碟與模型偏好選擇 runtime 及模型，不在每個階段重新詢問。
  - 驗收：政策與空間足夠時，自動下載、驗證、快取與重用；不足時產生例外，不留下半套環境。
- [ ] **VID-AUTO-003 — 區分自動技術檢查與人工內容驗收。** Agent 自動檢查第一段真實語音、字幕對齊與斷句、靜音、黑畫面、音量、解析度、編碼及輸出完整性；人類只審核剪輯意圖、觀看感受與重要內容取捨。
  - 驗收：技術問題不丟給人類判讀；初剪與最終版本各只有一次集中內容驗收。
- [ ] **VID-AUTO-004 — 端到端 Agent 執行。** 從素材盤點一路完成轉錄、剪輯、字幕、輸出與交付，不為內部技術階段逐次詢問。
  - 驗收：一個任務可產生初剪供人類判斷，收到集中意見後由 Agent 完成最終影片與驗證報告。

## P2：Google 工具自動化

- [ ] **GOOG-AUTO-001 — 自動選擇執行路線。** 依觸發方式、執行時間、權限、併發與維運成本，自行在 Apps Script、Workspace API、Cloud Run service 或 job 中選擇最小方案。
  - 驗收：常見需求不再要求使用者先決定技術架構；選擇理由記入交付結果。
- [ ] **GOOG-AUTO-002 — 自動沿用已驗證帳號與憑證。** 在持久政策允許的資源內，自動選取相符登入與最小權限，不重問 Script ID、Cloud Project 或 OAuth 路線。
  - 驗收：啟用完成的工作區可直接開發、同步、部署並讀回。
- [ ] **GOOG-AUTO-003 — 用相關狀態取代固定五段回報。** 保留內部狀態機，但只顯示本次實際經過的階段與仍需處理的例外。
  - 驗收：本機修正、既有專案接管與新部署分別產生簡潔且不同的結果報告。
- [ ] **GOOG-AUTO-004 — 建立自主重跑與回復。** 所有外部更新都先讀目前版本，使用固定識別與可驗證部署版本，失敗時回到最後可用版本。
  - 驗收：中斷、逾時或未知結果不會造成重複專案、重複部署或覆蓋未讀取的新修改。

## P2：AI 知識庫

- [ ] **KB-AUTO-001 — 區分原始記錄與正式知識。** 在已設定的知識目錄內，自動保存使用者原話、來源、分類、去重與索引；只有 AI 重寫、策略結論或會改變原意的內容才需要人類確認。
  - 驗收：原始心得一次輸入即可保存與讀回，AI 不會把自己的整理冒充使用者已確認的理解。
- [ ] **KB-AUTO-002 — 將不確定內容放進觀察區。** 無法判斷分類、來源或真偽時先保存為待釐清項目，累積後再集中與人類討論，不逐筆打斷目前工作。
  - 驗收：待釐清內容可搜尋、可追溯，但不會混入使用者已確認的事實。
- [ ] **KB-AUTO-003 — 自動維護索引與知識圖譜。** 依累積變更量與時間門檻批次更新，不在每次小修改後要求選擇。
  - 驗收：索引落後狀態可被偵測並自動補齊，重建結果可由來源檔重現。
- [ ] **KB-AUTO-004 — 自動產生可回復的策略候選。** AI 綜合判斷先進入候選區；達到來源數、時間跨度與信心門檻後，交由人類集中確認才提升，並保留前一版。
  - 驗收：AI 推論不冒充使用者原話；人類只判斷已整理完成的候選，不需重新蒐集或整理資料。
