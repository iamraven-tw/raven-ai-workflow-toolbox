# 第三方依賴政策

## 目的

Raven AI 一人公司工具包 會整合多個外部開源專案、套件、模型與服務。本政策確保使用者取得的是可重現、可追溯且授權清楚的版本，同時避免把所有第三方原始碼複製進 Toolbox。

## 來源優先順序

依序選擇下列方式：

1. **官方版本**：官方版本已滿足必要能力時，從官方套件庫、正式 Release 或官方 repository 取得。
2. **官方核心＋獨立擴充套件**：補強可以透過穩定介面完成時，保留官方核心，由本專案維護擴充套件。
3. **透明 fork**：必要能力必須修改核心時，使用公開 fork；清楚保留上游來源、授權與差異。
4. **vendoring**：只有離線發行、上游停止維護或其他已記錄理由，而且授權允許時，才把第三方程式實體收進發行包。

沒有明確授權、來源不可信或無法固定版本的依賴不得進入可發布套件。

## Manifest 必填資訊

每項必要依賴至少記錄：

- ID、用途與是否必要。
- 類型：官方、擴充套件、fork、vendored、模型或外部服務。
- 使用者實際下載網址與原始上游網址。
- 固定 tag、版本或完整 commit；不得只寫 `latest` 或未鎖定的 `main`。
- 可行時記錄 checksum 或其他完整性驗證方式。
- 授權、必要 NOTICE、修改與再散布要求。
- 安裝方式、支援環境、容量、硬體、登入、權限與費用。
- 驗證、更新、回復與移除方式。
- 已知限制與替代方案。

來源或 ref 尚未決定時，manifest 必須標示 `installable = false` 或該依賴為 `blocked`，不得放入可執行安裝路徑。

## Fork 規則

- fork 的 repository 說明必須連回上游，不得冒充官方版本。
- 保留適用的 LICENSE、NOTICE、著作權與修改聲明。
- 記錄建立 fork 時的上游基準，以及每次同步上游後的新基準。
- 上游更新不能自動進入正式版；先合併到維護分支，完成自動測試與實際工作流驗證後再建立新版本。
- Toolbox 只依賴已發布並鎖定的 fork ref，不直接依賴維護者的本機 branch。
- 若補強日後能成為獨立擴充套件，先完成相容性與移轉計畫，再切換使用者安裝來源。

## 模型、媒體與大型資產

- 模型程式、模型權重與資料集是不同資產，必須分別確認來源與授權。
- 模型權重、快取、虛擬環境、使用者素材與輸出成品不得提交到 Toolbox。
- 下載大型資產前，先顯示來源、預估容量、硬體需求、是否會連網與可能費用，再取得使用者同意。
- 測試媒體只能使用自製、虛構、公共領域或有明確授權的素材，並記錄來源。

## 安裝與更新

- 安裝前先唯讀檢查既有版本與衝突，不靜默覆寫。
- manifest 是安裝版本與順序的單一依據；文件中的範例不得凌駕 manifest。
- 不因上游出現新版就自動升級。維護者更新 ref 後，重新執行套件測試、乾淨環境安裝與相容性驗證。
- 更新失敗時保留既有可用版本，並提供明確回復方式。

## 私人流程、公開快照與第三方安裝的邊界

維護者的私人工作流程與公開 Toolbox 各自獨立，不自動同步。只有維護者明確選定的改進，才經過公開性檢查、一般化與候選版驗證後進入下一個版本快照；完整原則見 [`local-sync.md`](local-sync.md)。

第三方專案與 fork 則由公開安裝 manifest 取得固定版本，不把維護者本機工作目錄整包複製進 Toolbox，也不使用私人路徑作為下載來源。
